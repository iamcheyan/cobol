# ソート、マージ、バッチ処理のデータフロー

## 学習目標

SORT/MERGE の作業ファイル、INPUT PROCEDURE/OUTPUT PROCEDURE、SORT テーブル、ソートキー、ソートの安定性について学びます。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中で該当する宣言や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L18.COB`](./L18.COB) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから次を実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/18-sort-merge/L18.COB
cobc -x -Wall -o build/l18 extensions/legacy-workshop/lessons/18-sort-merge/L18.COB
./build/l18
```

期待される観察内容：このレッスンでは、まず SORT のデータフローとファイル宣言を説明し、その後、練習用リポジトリのバッチ処理プログラム全体で実際の読み書きを示します。

コンパイラが形式や列位置のエラーを報告した場合は、まず 7、8、12、72 列目を確認します。次に、ピリオド、変数の PIC、スコープを終了する文を確認してください。`-Wall` は追加の警告を表示します。警告の内容を理解してから、対処するかどうか判断しましょう。

## 各段落の理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言があれば、レベル番号と PIC に注目してください。
3. `PROCEDURE DIVISION` は実行の開始位置です。`0000-MAIN` は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースコードの順に実行されます。制御フロー文で処理経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更演習

sales_data.txt を顧客番号でソートし、キーが同じレコードが業務要件を満たす順序になるようにしてください。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つにし、変更前後の出力を記録しましょう。

## cobol.nvim を使った学習

プラグインのアウトラインで SORT の入力・出力手続きを追跡します。`:CobolLint` でファイル定義を確認してください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、次に `cobc --version` を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に使います。プログラムがコンパイルできるかどうかは、GNUCOBOL の実際のコンパイル結果で判断します。
