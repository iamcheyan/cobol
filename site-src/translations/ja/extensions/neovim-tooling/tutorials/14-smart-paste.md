# スマートペースト：smart-paste.nvim

ブラウザーやチャット画面、別のファイルからコードを Neovim に貼り付けると、最も起こりやすいのが**インデントの乱れ**です。貼り付ける内容が元のインデントを持ったまま挿入され、貼り付け先の位置と重なってギザギザになります。

`smart-paste.nvim` はこの問題を解決します。**ブロック内の相対インデントを保ちながら、ブロック全体を現在行に合わせて配置します。**

---

## 1. 解決する問題

| 貼り付け方法 | 問題 |
|---|---|
| `p`（既定） | 文字単位の貼り付けです。複数行の内容は元のインデントのまま挿入され、階層が累積します |
| `P` | 同上ですが、前に挿入します |
| `:set paste` | すべてのインデント処理を無効にしますが、補完や自動インデントも無効になります |
| `]p` | 現在のインデントに合わせますが、各行を再配置します |

smart-paste は、**ブロック内の相対インデントを保ち**、「先頭行」だけを現在行に合わせます。残りの行はその相対関係を保ちます。

## 2. 設定内容

`lua/plugins/smart-paste.lua` にあります。このプラグインの設定がほかより長いのは、3種類の貼り付け元を処理するためです。

1. **内部 yank**（Vim レジスタ）
2. **システムクリップボード**（`+` レジスタ）
3. **ターミナルからの貼り付け**（`<C-S-v>` または中クリック）

重要なロジックは設定のコメントに明確に書かれています。

```lua
-- External clipboard registers are often characterwise. Keep their
-- relative indentation intact while rebasing the block to this line.
```

```lua
-- Characterwise yanks omit whitespace before the first selected byte.
-- Remember that missing prefix instead of guessing from nested lines.
```

**2つ目のコメントが核心です**。文字単位の yank には、行頭の空白が含まれません。そのため貼り付け時には、内側の行のインデントから推測するのではなく、「元の空白が何文字分欠けていたか」を記録しておく必要があります。

## 3. 基本動作

### 内部 yank

```text
yy        复制一行
p         粘贴（自动对齐到当前缩进）
```

複数行のブロックをコピーした場合：

```cobol
       IF WS-STATUS = "A"
           DISPLAY "ACTIVE"
       END-IF
```

同じく7個の空白でインデントされた別の位置に貼り付けると、ブロック内の関係（`DISPLAY` は `IF` より4個深い）が保たれ、先頭行が貼り付け位置に揃います。

### システムクリップボード

ブラウザーから COBOL コードをコピーし、Neovim で `p` を押しても同じように自動調整されます。

### ターミナルからの貼り付け

ターミナルが bracketed paste に対応していれば、大量の内容を貼り付ける場合も同じ処理が適用されます。

## 4. COBOL での実用性

### ケース1：ドキュメントからサンプルコードをコピーする

教材の README には多くのコードブロックがあります。`.cob` ファイルに貼り付ける場合：

**smart-paste がない場合**：README のコードブロックはインデントが0ですが、COBOL では Area B を12列目から始める必要があります。貼り付けた後、各行の先頭に空白を11個ずつ手作業で追加しなければなりません。

**smart-paste がある場合**：カーソルを12列目に置いて貼り付けると、ブロック全体が自動的に12列目から始まります。

### ケース2：`IF` ブロックをコピーして条件を変更する

```cobol
           IF WS-ACCOUNT-STATUS = "A"
               PERFORM 2000-POST-TRANSACTION
               ADD 1 TO WS-ACCEPTED-COUNT
           END-IF
```

この4行をコピーして下に貼り付けても、ブロック内の相対インデントが保たれます（`PERFORM` は引き続き `IF` より4個深くなります）。

### ケース3：別のレッスンからコードを移す

第20課のファイル照合ロジックを第32課に移すとき、インデント階層が同じなら、貼り付け後に並べ直す必要はありません。

## 5. 練習

### 練習1：標準の `p` と smart-paste を比べる

```sh
cd ~/development/cobol
nvim lessons/17_fixed-length-files/lesson.cob
```

1. インデントされた `IF` ブロックを見つけ、`V` で数行選択して `y` を押す
2. ファイル下部の空行に移動し、`p` を押す
3. `u` で元に戻す

**確認ポイント**：貼り付け後もブロック内のインデント関係（子の節は親の節より空白が多い）が保たれ、すべてが1列目に揃うことはありません。

### 練習2：README からコードをコピーする

1. `lessons/17_fixed-length-files/README.md` を開く
2. コードブロックの内容をコピーする（`V` で選択して `y`）
3. `.cob` ファイルに切り替える
4. カーソルを12列目（`12|`）に移動する
5. `p` を押す

**確認ポイント**：ブロック全体が1列目ではなく12列目から始まります。

### 練習3：システムクリップボード

1. ブラウザーまたはターミナルから複数行のテキストをコピーする
2. Neovim で `p` を押す

**確認ポイント**：貼り付け後に行ごとのインデントが累積して、ギザギザになりません。

### 練習4：関数全体を新しいファイルに貼り付ける

1. `0100-INIT.` 段落全体をコピーする
2. `:new` で新しい buffer を開く
3. `p` を押す

**確認ポイント**：段落のインデント階層がそのまま保たれます。

## 6. つまずきやすい点

### 貼り付けたらインデントが余計に増えた

ターミナルが貼り付け内容をキー入力として1文字ずつ送信し、自動インデントを発生させた可能性があります。ターミナルで bracketed paste が有効になっているか確認してください（多くの最新ターミナルでは既定で有効です）。

確認するには：

```vim
:set paste?
```

`nopaste` と表示される場合、`:set paste` の影響はありません。これは望ましい状態です。

### クリップボードから貼り付けると先頭行のインデントが失われる

これは文字単位の yank に固有の問題です（設定のコメントでも触れています）。smart-paste は「何文字分欠けていたか」を記録しますが、コピー元に最初からインデントがなければ、0として扱うしかありません。

**対策**：貼り付け前にカーソルを目的のインデント位置に置き、カーソル位置を基準に貼り付けてください。

### `p` と `P` で動作が違う

`p` はカーソルの後ろ／次の行に、`P` はカーソルの前／前の行に貼り付けます。複数行ブロックでは違いがはっきりします。**迷ったら先に `u` で元に戻して、もう一方を試してください。**

### 大きなブロックの貼り付けが遅い

smart-paste は各行のインデントを処理します。数千行を貼り付けると1、2秒止まることがありますが、正常です。

### `:set paste` と競合する

`:set paste` は smart-paste の調整を含む自動処理をすべて無効にします。**`:set paste` は使わず**、プラグインに処理を任せてください。

## 8. 適用範囲

- このプラグインの設定は `lua/plugins/smart-paste.lua` にあります。内部 yank、システムクリップボード、ターミナル貼り付けという3種類の入力元を個別に処理するため、ほかのプラグインより長くなっています。
- 「相対インデントを保ち、現在行に合わせて配置する」のが設計目標です。**特定のインデント規則（`shiftwidth` など）に完全に一致する保証はありません。**
- ブラウザーからコピーした内容には、ゼロ幅スペースや NBSP などの不可視文字が含まれることがあります。これらはこのプラグインでは修正できないため、`:set list` で確認してください。
- 貼り付け後も、COBOL は列位置に敏感なので、`cobc -fsyntax-only` で確認することをおすすめします。
