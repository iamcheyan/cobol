# 第 08 课：综合练习——迷你账户交易批次

第一阶段到这里要把零散语法拼成一条完整处理链：读入一笔交易、按交易码分类、用金额与余额规则决定接受或拒绝、更新余额并汇总计数。本课用五笔固定样例把前七课的字段、`MOVE`、`COMPUTE`、`IF`、`EVALUATE`、`PERFORM` 循环和命名段落串成一个小批次，并给出可逐笔手算核对的结果。

## 为什么现在学

你已经分别学过字段、算术、条件、多值分类、循环和段落，但它们各自练习时都只处理一小段逻辑。缺口是“把它们接起来”：真实批次的余额是顺序累积的，前一笔接受的交易会改变后一笔能否通过余额检查。本课把前七课的能力组装成一条可追踪的处理链，也让“计数不变量”第一次变得可验证——每笔交易要么记入接受数、要么记入拒绝数。

## 本课完成后的能力与边界

学完本课后，你可以：

- 用 `WORKING-STORAGE` 字段保存期初余额、当前余额、交易码、带符号金额和三种计数。
- 用 `PERFORM VARYING` 依序处理五笔固定样例，并说明循环的起止边界。
- 用 `EVALUATE` 按交易码选择存款、取款或未知代码路径，用嵌套 `IF` 校验正金额与可用余额。
- 逐笔追踪每笔交易对共享余额和计数的影响，并核对计数不变量 `処理件数 = 承認件数 + 拒否件数`。
- 把初始化、样例装载、交易处理和汇总组织成可调用的命名段落。

边界：样例数据直接写在 `2100-LOAD-SAMPLE` 里，程序不读终端、文件或数据库；没有持久化状态，重复运行结果相同。生产账务所需的文件状态、审计、并发和重启策略不在本课范围内，见第 15 课以后与第 26 课。

## 运行环境

- GnuCOBOL 3.2.0，默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不依赖数据库或附加工具。
- 无输入夹具、无输出数据文件；编译产物写在 `build/`，可直接删除重来。

## 批次规则

程序从 `1000.00` 开始，按样例编号处理五笔固定交易：

| 编号 | 代码 | 金额 | 处理规则 | 余额变化 |
|---|---|---:|---|---:|
| 001 | `D` | 125.50 | 正数存款，接受 | 1000.00 → 1125.50 |
| 002 | `W` | 40.10 | 正数取款且余额足够，接受 | 1125.50 → 1085.40 |
| 003 | `W` | 1500.00 | 金额大于当前余额，拒绝 | 不变 |
| 004 | `D` | -5.00 | 存款金额不是正数，拒绝 | 不变 |
| 005 | `X` | 25.00 | 未知代码，拒绝 | 不变 |

计数不变量：`処理件数 = 承認件数 + 拒否件数`，本课为 `5 = 2 + 3`。

这是用于学习控制流程的批次，样例数据是程序内固定数据（演示数据），不是从外部文件读到的真实交易。程序也不实现生产账务所需的持久化、审计、并发或重启规则。

## 数据和过程结构

完整源码见 [`lesson.cob`](./lesson.cob)。它用独立字段保存期初余额、当前余额、交易码、带独立符号的金额、样例序号以及三种计数。金额采用两个小数位，存储和计算遵循 GnuCOBOL 当前平台行为。

| 段落 | 职责 | 关键语句 |
|---|---|---|
| `0000-MAIN` | 按顺序调用初始化、批次处理和汇总 | `PERFORM`、`STOP RUN` |
| `1000-INITIALIZE` | 设置当前余额并清零计数 | `MOVE` |
| `2000-PROCESS-BATCH` | 从 1 循环到最后一个样例，装载并处理每笔交易 | `PERFORM VARYING`、段落 `PERFORM` |
| `2100-LOAD-SAMPLE` | 将序号映射为交易码和金额 | `EVALUATE`、`MOVE` |
| `2200-CLASSIFY-AND-POST` | 按代码验证交易并更新余额或拒绝计数 | `EVALUATE`、嵌套 `IF`、`COMPUTE` |
| `9000-REPORT` | 输出处理数、结果数和最终余额 | `DISPLAY` |

段落仍共享同一组 `WORKING-STORAGE` 字段。处理每一笔交易时，外层循环先调用装载段落，再调用分类处理段落，最后增加已处理计数。被 `PERFORM` 调用的段落结束后，控制返回调用位置，因此循环会继续下一笔。

## 逐笔处理逻辑

1. 主段落先执行 `1000-INITIALIZE`：当前余额设为期初余额，所有计数设为零。
2. `PERFORM VARYING` 将序号从 1 递增到 5。上界比较是 `WS-SAMPLE-INDEX > WS-LAST-SAMPLE`，所以序号 5 也会处理。
3. `2100-LOAD-SAMPLE` 用 `EVALUATE` 装入该序号的代码和金额，并打印记录；`WHEN OTHER` 提供序号范围以外的默认值。
4. `2200-CLASSIFY-AND-POST` 先按代码选择存款、取款或未知代码路径。
5. 存款只有金额大于零才加到余额并增加接受数；其他金额增加拒绝数。
6. 取款先检查金额大于零，再检查金额小于或等于当前余额。两个条件都满足才扣款；金额恰好等于余额时允许取款，余额变为零。
7. 未知代码增加拒绝数。每笔完成后，外层循环恰好增加一次处理计数。
8. 循环结束后，主段落调用汇总段落。五笔中两笔接受、三笔拒绝，最终余额为 `1085.40`。

交易处理次序是业务规则的一部分：每笔已接受的交易都会影响后续取款的可用余额。拒绝路径不修改余额。

## 运行与观察

程序不读终端、文件、命令行参数或数据库，也不生成数据文件，因此在本课目录或任意目录执行结果相同。下面按本课目录说明。

**输入：** 无外部输入。五笔样例是 `2100-LOAD-SAMPLE` 中的程序内固定数据。

**命令及作用：**

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob                  # 只做语法检查，不生成可执行文件
cobc -x -Wall -o build/lesson_08 lesson.cob    # 编译并生成可执行文件
./build/lesson_08                              # 运行程序，输出写到标准输出
echo $?                                        # 查看退出码
rm -rf build                                   # 清理生成的可执行文件
```

**预期结果：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出 | 16 行，见下方代码块 |
| 进程退出码 | `0` |

```text
バッチ=START
期首残高=0001000.00
レコード=001 符号=D 金額=+00125.50
結果=ACCEPTED 理由=DEPOSIT
レコード=002 符号=W 金額=+00040.10
結果=ACCEPTED 理由=WITHDRAWAL
レコード=003 符号=W 金額=+01500.00
結果=REJECTED 理由=INSUFFICIENT_FUNDS
レコード=004 符号=D 金額=-00005.00
結果=REJECTED 理由=AMOUNT_NOT_POSITIVE
レコード=005 符号=X 金額=+00025.00
結果=REJECTED 理由=UNKNOWN_TRANSACTION_CODE
処理件数=005
承認件数=002
拒否件数=003
最終残高=0001085.40
```

**输出字段对照（日文输出 → 含义）：** `バッチ=START` = 批次开始；`期首残高` = 期初余额；`レコード` = 样例序号；`符号` = 交易码；`金額` = 交易金额；`結果` = 接受/拒绝；`理由` = 判定理由代码；`処理件数` / `承認件数` / `拒否件数` = 处理/接受/拒绝件数；`最終残高` = 最终余额。

金额的前导零和正负号来自字段 `PIC` 与 `SIGN IS LEADING SEPARATE CHARACTER` 的显示格式；`V` 表示隐含的小数点位置，显示时省略。余额字段是 `PIC 9(7)V99`，所以 `1085.40` 显示为 `0001085.40`。

**实际观察到的环境细节：** 在本工作区运行可执行文件时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境的链接库版本警告，不是本程序的业务输出；其触发组件尚未定位。程序输出在标准输出，退出码为 0。

## 举一反三练习

扩展批次，让它能处理第六笔固定交易：为第六笔选择交易码和金额，说明它应接受还是拒绝，并给出逐笔处理后的余额与最终计数。至少包含一次“取款金额恰好等于当前余额”的边界，并确认 `処理件数` 只按实际处理的交易数增加。仍使用固定样例，不引入文件、表格或数据库。题目见 [`exercise.md`](./exercise.md)，本题不提供答案。

## 在企业中的位置

企业批处理常按序处理客户交易，先前已接受的交易会影响之后的可用余额，因此处理次序本身就是业务规则的一部分。生产系统还需要明确正数金额、账户状态、货币精度、限额、拒绝码、审计记录、重复输入处理、并发更新和失败重启策略。

本课只展示内存中的顺序规则，结果可逐笔手算核对，但它不能当作已验证的账务系统：没有外部输入、没有输出结果文件、没有持久化和重启保证。文件读取与写出从第 15、16 课开始，业务拒绝与系统故障的分流从第 26 课开始，数据库一致性到第 29–32 课才涉及。
