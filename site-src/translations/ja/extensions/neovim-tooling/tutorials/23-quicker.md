# quickfix の強化：quicker.nvim

`:copen` で開く quickfix リストは、デフォルトでは1行の概要しか表示しません。**前後の文脈が見えず、探している箇所かどうか判断できません。**

quicker.nvim は quickfix に「前後の文脈を展開する」機能を追加します。`>` で該当行の前後2行を表示し、`<` で折りたたみます。

---

## 1. 解決する問題

| 要件 | 標準 quickfix | quicker |
|---|---|---|
| 該当行の文脈を見る | 移動して確認し、また戻る | `>` でその場で展開 |
| 該当箇所が目的のものか判断する | 行き来する必要がある | 周辺の数行を一目で確認 |
| 結果を編集する | 該当箇所へ移動するだけ | その場で編集できる |

## 2. 設定内容

`lua/plugins/quicker.lua`：

```lua
{
  "stevearc/quicker.nvim",
  ft = "qf",
  opts = {
    keys = {
      {
        ">",
        function()
          require("quicker").expand({ before = 2, after = 2, add_to_existing = true })
        end,
        desc = "Expand quickfix context",
      },
      {
        "<",
        function() require("quicker").collapse() end,
        desc = "Collapse quickfix context",
      },
    },
  },
}
```

| パラメーター | 値 | 説明 |
|---|---|---|
| `before` | 2 | 展開時に該当行の**前**2行を表示 |
| `after` | 2 | **後ろ**2行を表示 |
| `add_to_existing` | `true` | もう一度 `>` を押したとき、表示範囲を追加してさらに展開 |

`ft = "qf"` は quickfix buffer でのみ読み込む設定です。

## 3. キー操作

| キー | 動作 |
|---|---|
| `>` | 前後の文脈を展開（前2行 + 後2行） |
| `<` | 折りたたむ |
| `<Tab>` | 展開して次の箇所へ移動 |
| `<S-Tab>` | 展開して前の箇所へ移動 |
| `q` | quickfix を閉じる |

`>` は続けて押せます。`add_to_existing = true` のため、押すたびにさらに行が追加されます。

## 4. 一連の操作

### 検索結果から quickfix を開く

```text
1. <leader>fg            内容を検索
2. 検索語を入力
3. <C-q                 結果をすべて quickfix に送る
4. :copen               リストを開く
5. >                    現在の項目の文脈を展開
6. j / k                結果間を移動
7. Enter                ソースの位置へ移動
```

### 診断結果から quickfix を開く

```text
1. <leader>xq           診断を quickfix に送る
2. :copen
3. >                    文脈を展開してエラーを見る
```

## 5. COBOL での利用例

### 例1：参照箇所が変更対象か確認する

`<leader>fw` で `WS-RECORD-COUNT` を検索すると、30か所が見つかりました。問題は、**どれが宣言で、どれが使用箇所か**です。

1. `<C-q>` で quickfix に送る
2. `:copen`
3. `>` で最初の項目を展開 → `01 WS-RECORD-COUNT PIC 9(2).` と前後の行を見る

**展開すれば WORKING-STORAGE の宣言部で、使用箇所ではないとすぐ分かります。** `Enter` で移動して戻るより素早く確認できます。

### 例2：一括置換の影響範囲をレビューする

grug-far で8個のファイルを変更した後、各変更箇所が適切か確認します。

1. `<leader>fg` で変更後のパターンを検索
2. `<C-q`
3. `:copen`
4. 順に `>` で展開してレビュー

### 例3：コンパイル診断の前後を見る

COBOL のエラーで、ある行にピリオドが足りないと報告された場合：

1. `<leader>xq`
2. `:copen`
3. `>` で展開 → 直前の文と後続の行を確認

**COBOL のピリオドに関するエラーは、原因の特定に前後の文脈が必要なことがよくあります。** 1行だけでは問題が分からないことがあります。

### 例4：複数の課にある同種の問題を見る

`PIC 9(2)` を検索して、2桁カウンターの箇所をすべて探します。展開すると、どの箇所で桁あふれが起こる可能性があるか確認できます（第17課では `WS-RECORD-COUNT` が `00`–`99` に限られることを扱いました）。

## 6. 練習

### 練習 1：基本の展開

```sh
cd ~/development/cobol
nvim
```

1. `<leader>fg` → `WS-RECORD-COUNT` を検索
2. `<C-q>` で quickfix に送る
3. `:copen`
4. `>` を押す

**確認**：現在の該当行の上と下に、行番号付きで前後2行の文脈が表示される。

### 練習 2：さらに展開する

1. 前の手順に続けて、もう一度 `>` を押す

**確認**：`add_to_existing = true` により、前後の文脈が4行に広がる。

### 練習 3：折りたたむ

1. `<` を押す

**確認**：1行表示に戻る。

### 練習 4：結果間を移動して展開する

1. `j` で次の項目へ移動
2. `>`
3. さらに `j`、続けて `>`

**確認**：各項目を個別に展開でき、展開済みの項目はそのまま表示される。

### 練習 5：該当箇所へ移動する

1. 項目上で `Enter` を押す

**確認**：ソースの対応箇所へ移動する。`:copen` で戻れる。

### 練習 6：診断を使う

1. COBOL ファイルを開き、ピリオドを1つ削除する
2. `:w` で保存して診断を実行する
3. `<leader>xq`
4. `:copen` + `>`

**確認**：エラー行の前後を見られる。変更を戻す（`u`）。

## 7. つまずきやすい点

### `>` を押しても反応しない

**quickfix buffer**（`ft = "qf"`）でのみ動作します。現在のウィンドウが quickfix か確認してください。

```vim
:echo &filetype
```

`qf` と表示されるはずです。

### 展開しても関数全体が見えない

`before = 2, after = 2` は固定行数です。文脈が足りない場合は `>` を何度か押してください（展開範囲が追加されます）。

### `>` / `<` が他のプラグインと競合する

通常の buffer では、この2つのキーは**インデント / インデント解除**に使われます。quicker の割り当ては quickfix buffer 内だけで有効なので、競合しません。

### quickfix リストが空

`:copen` で開いても内容がない場合、quickfix に結果が送られていません。先に `<C-q>`（snacks）または `<leader>xq`（診断）を使ってください。

### 編集後もリストが更新されない

quickfix の項目はスナップショットです。ファイルを変更した後も、`:copen` には古い行番号が残ります。再検索してください。

### 項目数が多いと展開が遅い

展開時には各項目に仮想行を挿入します。数百件あると動作が遅くなる場合があります。いったん `<` で折りたたみ、1件ずつ展開してください。

## 8. 他のプラグインとの関係

| 確認したいこと | 使う機能 |
|---|---|
| 内容を検索して結果を見る | `<leader>fg`（snacks） |
| 文脈付きで結果を見る | `<C-q>` + `quicker` |
| 結果間を移動する | `:cnext` / `:cprev` または `j` / `k` |
| 診断を見る | `<leader>xq` + `quicker` |
| 変更後の差分を見る | `<leader>gd`（diffview） |

**quicker は quickfix の表示を強化するもの**で、結果自体は生成しません。検索や診断から結果を受け取ります。

## 10. 対象範囲

- ここで紹介するキー操作は `lua/plugins/quicker.lua` の設定に基づきます：`>`、`<`、`before = 2`、`after = 2`、`add_to_existing = true`。
- `>` と `<` がこの意味になるのは `qf` filetype の buffer 内だけです。通常の buffer ではインデント操作です。
- quicker は quickfix の内容を生成しません。先に `<C-q>`（snacks）または `<leader>xq`（診断）を使う必要があります。
- quickfix の内容はスナップショットです。ファイル変更後は行番号が古くなるため、検索し直してください。
