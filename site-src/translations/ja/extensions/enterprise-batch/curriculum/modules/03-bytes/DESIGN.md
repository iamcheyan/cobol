# モジュール 03 設計：金額の物理表現と不正データの解析

本設計は CUSTOMER v1=27B、ACCOUNT v1=47B、TRANSACTION v1=55B の契約も、モジュール07や既存の P1 実験も変更しません。

## 環境と ABI の基準

- GnuCOBOL 3.2、Linux x86-64、**既定方言**。`COMP-3` / `FUNCTION TRIM` は GNU 拡張なので、`-std=cobol85` は禁止です。他のコンパイラー/アーキテクチャ/エンディアンでは再測定し、別の ABI 版を定める必要があります。
- 実測 ABI（本リポジトリの `instructor/modules/03-bytes/M03BYTES.COB` の実行時プローブ + P1）：
  - `PIC S9(n)` DISPLAY は数字1桁につき1バイト。`SIGN LEADING SEPARATE` は符号バイトを1つ追加します。
  - `SIGN SEPARATE` なしの DISPLAY は**符号上書き（overpunch）**です。正数は `0x30|digit`、負数は `0x70|digit`（例：`-12345.67` の最終バイトは `0x77`）。
  - `COMP-3` は1バイトに数字半バイト2個を格納し、最後の半バイトが符号（C 正 / D 負）です。バイト数 = `ceil((N+1)/2)`（N は数字桁数）。`S9(11)V99` は数字13桁+符号 = 7バイトです。
  - `COMP` はこの構成では**ビッグエンディアン**で、長さは値域により決まります（`S9(4)`=2B、`S9(9)`=4B、`S9(18)`=8B）。
  - `COMP-5` はネイティブの**リトルエンディアン**です。
- 生バイトを検証してからでなければ数値として解釈できません。`COMP`/`COMP-3` の上位バイトを ASCII として走査してはいけません。
- **ホストの Data Exception と GnuCOBOL の実挙動**：COBOL 規格では不正な数字を含む数値項目で算術を行うと data exception が発生します。IBM メインフレームでは ABEND `S0C7` となります。しかし本機の GnuCOBOL 3.2 は実測で**エラーになりません**。`PIC X` に `ABC`/`XYZ` を格納し、`REDEFINES` で `PIC 9` として `COMPUTE` に使うと、それぞれ124/901となり RC0 のままです。そのため本コースでは nibble を明示的に検証し、ランタイムに頼らないようにします。
- 実行時の表示 `Warning: program compiled against libxml 212 using older 209` は、このマシンの GnuCOBOL リンクライブラリー版のノイズで業務とは無関係です。`stderr.txt` に記録しますが、アサーションには含めません。

## 統一レコード単位（03.3）

- 生ファイル：連続した7バイトレコード、`PIC S9(11)V99 COMP-3`、数字13桁 + 符号。LF もアラインメントもありません。
- 外側の境界条件：ファイルのバイト数は7の整数倍でなければなりません。そうでない場合は RC8 で公開しません。GnuCOBOL の固定長順次ファイル読取は、レコード不足時に `PIC X` を空白で補い、`FILE STATUS 00` を返す場合があります。読取ループだけに依存できません。
- 半バイト単位の検証：数字半バイト13個はすべて0〜9、符号半バイトは C または D（本コースでは F を受け入れません）。検証が通るまで十進数の算術は**一切行いません**。行うのは整数としての半バイト比較だけです。
- デコード：数字列の先頭11桁が整数部、残り2桁が小数部です（暗黙小数点はバイトを占めません）。正負のゼロ（C/D）は数値としてどちらも0ですが、バイトは異なります。

## 出力契約

レポートは CSV 形式のテキストで、行の種類は次のとおりです：

- 03.1：`LESSON`、`ABI`（endianness）、`DECL,<name>,<usage>,<digits>,<bytes>,<formula>`。
- 03.2：`LESSON`、`AMOUNT`、`HEX,<name>,<lower-hex>`、`TOTAL,<bytes>`。
- 03.3：`LESSON`、`REC,<seq>,<hex>,OK,<value>,` または `REC,<seq>,<hex>,REJECT,[INVALID],<reason>`、続いて `SUMMARY` が3行。

行順は固定で、検査プログラムはバイト単位で比較します。余分または不足する行があれば失敗です。

## ランナーと失敗時の未公開

`run.sh`：引数検証 → ディレクトリロック `OUT.lock` → 非公開の `mktemp` stage → 入力をスナップショットして checksum 検証 → 参照ソース/学習者ソースをコンパイル → stage 内で実行（stdout→report.txt、stderr→stderr.txt）→ RC の正規化（0/4 は継続、それ以外は失敗）→ checksum と manifest を検証 → すべて通過した場合に `mv -T -n` でアトミックに公開。どこかで失敗すると stage を削除してロックの説明を残し、正式な出力は一切作りません。`reset.sh` はファイル一式が完全で manifest 検証にも成功した場合だけ出力ディレクトリを削除します（未知のファイル、シンボリックリンク、改ざんを拒否）。

## 銀行システムとの関係

03.1/03.2 は基礎実験用の金額 `12345.67` を使い、ACCOUNT v1 の「最小単位の整数」という考え方（`S9(9) COMP` で1234567セントを格納）も追加で示します。03.3 の7バイト Packed レコードはモジュール07 L4 の `S9(9)V99 COMP-3` 上限フィールドと同系統です（いずれも Packed で、比較の前に半バイトを検証）。モジュール07の Packed 処理とモジュール11の障害調査（不正数字/位置ずれ）の基礎になります。本モジュールで新しい銀行ファイル契約は追加しません。

## 制限

- Linux x86-64 / GnuCOBOL 3.2 でのみ実測済みです。EBCDIC、メインフレームの overpunch 文字コード表、その他の endian は未検証です。
- 1バイト ASCII のみを扱います。マルチバイト/Unicode の文字数とバイト数の違いは本モジュールの結論に含みません。
