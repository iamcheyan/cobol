# 第 30 课修改练习参考答案

本答案只回答 [`exercise.md`](./exercise.md) 的两项修改练习，不提供举一反三题答案。两项都以本课原始 [`lesson.cob`](./lesson.cob) 为基线。基线运行结果见 [`expected-output.txt`](./expected-output.txt)（8 行，退出码 `0`）。

两项都在本工作区实测过：把源码复制到临时目录、按题改动后，用同一套 GixSQL 工具链执行 `./build.sh run`（`BUILD_DIR`、`GIXSQL_ROOT` 指向临时位置），下述输出即实际观察值。

## 1. 反转结果顺序

**改动位置：** 游标声明中的排序子句。

```sql
ORDER BY ACCOUNT_NO DESC
```

**命令：** `./build.sh run`

**实际输出：**

```text
接続=成功
オープン=成功
行=A000000002 CUSTOMER=C0001002 BALANCE=00875.00
行=A000000001 CUSTOMER=C0001001 BALANCE=01250.75
取得=EOF SQLCODE=100
クローズ=成功
行数=002
切断=成功
```

**与基线的完整差异与原因：** 只有第 3、4 行互换——`A000000002` 先出，`A000000001` 后出。`ORDER BY` 只决定数据库返回行的**顺序**，不改变行数，所以 `行数=002` 不变；`FETCH` 循环在最后一行之后仍然收到 `SQLCODE 100`，故 `取得=EOF SQLCODE=100` 与 `クローズ=成功` 均不变。余额 `00875.00` / `01250.75` 与 `schema.sql` 里的 `875.00` / `1250.75` 对应（`PIC 9(5).99` 补足到 5 位整数）。

## 2. 限定到一个账户

**改动位置：** 游标 `SELECT` 的 `FROM` 之后，独立于第 1 题。

```sql
WHERE ACCOUNT_NO = 'A000000002'
```

**命令：** `./build.sh run`

**实际输出：**

```text
接続=成功
オープン=成功
行=A000000002 CUSTOMER=C0001002 BALANCE=00875.00
取得=EOF SQLCODE=100
クローズ=成功
行数=001
切断=成功
```

**与基线的完整差异与原因：** 只保留一行 `行=A000000002 CUSTOMER=C0001002 BALANCE=00875.00`，`行数` 由 `002` 变为 `001`。原因是 `WHERE` 把结果集缩小到一行：第一次 `FETCH` 返回 `SQLCODE 0`（计数 +1 并显示），**下一次** `FETCH` 没有更多行，返回 `SQLCODE 100`，于是打印 `取得=EOF SQLCODE=100` 并结束循环，随后正常 `CLOSE` 并断开，退出码为 `0`。

注意：`SQLCODE 100` 在这里表示“结果集结束”，不是错误，也不是“账户不存在”——本课没有“查不到”分支，账户不存在时结果集为空，其行为见 [`README.md`](./README.md) 的“空、单行、多行与 EOF”一节（本工具链下空表会先给一条空白记录）。
