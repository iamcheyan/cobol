## 举一反三迁移练习（无答案）

换一个相似场景：为一家保险公司的理赔日批次写 `claims.cob`。输入 `claims.txt` 每行 14 字节，布局是**理赔号 X(6) + `|` + 类型 X(1) + `|` + 金额 X(5)**（金额单位为分）；类型只允许 `M`（医疗）与 `A`（意外）。请自行完成：

1. 设计接受文件与拒绝文件的记录布局（宽度、字段顺序）并写进程序头注释，说明每个字段的来源。
2. 校验顺序自定，但必须区分：宽度不符、类型未知、金额非数字、金额为零——把它们都记为业务拒绝并继续读取；同时保留输入缺失、输出无法打开、非 EOF 读错误作为系统故障，返回码为 1。
3. 自己设计一份至少 5 行的夹具，覆盖正常记录、未知类型、零金额、金额非数字和一行宽度不符；给出计数不变量（`输入 = 受理 + 拒绝`）与两个结果文件的行数、字节数，并说明你是怎样独立算出这些数字的。
4. 让接受输出的**父目录不存在**：把 `SELECT ACCEPTED-OUTPUT` 的 `ASSIGN` 改成 `"nodir/accepted.txt"`（`nodir/` 不存在），运行后记录 `FILE STATUS`、摘要中的系统错误标志和进程返回码，比较它与第 2 步“业务拒绝”的差别。
5. 回答：如果拒绝文件本身写入失败，为什么不能继续把后续记录算作已成功处理？

本题不提供答案。不要用 `AT END` 代替 READ 之后的状态检查，也不要在输出失败后返回成功状态；不要引入本课尚未讲授的语法。交付源码、编译与运行命令、实际输出、两个结果文件内容和上述统计，并列出你**未能验证**的故障类型。
