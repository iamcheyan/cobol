# セッションの保存と復元：auto-session

Neovim を閉じて翌日開くと、**さっき開いていた12個のファイル、ウィンドウ配置、カーソル位置がすべて消えてしまう**。

auto-session は「プロジェクトのディレクトリ」ごとにセッションを保存します。ディレクトリごとにレイアウトを記録し、次にそのディレクトリを開いたとき自動で復元します。

---

## 1. 解決する問題

| 要件 | セッションなし | auto-session あり |
|---|---|---|
| 前回のファイルを復元する | 手動で開き直す | `cd` で入ると自動復元 |
| ウィンドウ配置を保つ | 分割し直す | 配置を保存 |
| 複数プロジェクトを切り替える | それぞれ開き直す | ディレクトリごとに独立したセッション |
| 先週の作業状態を取り戻す | 記憶に頼る | セッション一覧から選ぶ |

## 2. 設定内容

`lua/plugins/auto-session.lua` の `opts` にある主な項目：

| オプション | 値 | 説明 |
|---|---|---|
| `auto_save` | `true` | 終了時に自動保存 |
| `auto_restore` | `true` | ディレクトリに入ると自動復元 |
| `auto_restore_last_session` | `false` | 起動時に前回のセッションを無条件で復元しない |
| `args_allow_files_auto_save` | `true` | ファイル引数を指定して起動した場合も保存 |
| `git_auto_restore_on_branch_change` | `false` | ブランチ切り替え時にセッションを自動で切り替えない |

### サイドバーへの追加処理

この設定はデフォルトより複雑です。**Neo-tree / Aerial のサイドバーをセッション内で扱う問題**に対応しています。設定冒頭のコメントで理由を説明しています。

```lua
-- auto-session closes non-file windows in auto_save_session() *before*
-- pre_save_cmds. Snapshot first, keep neo-tree/aerial through that close
-- pass, then fold them ourselves so mksession cannot write ghost splits.
```

問題は、`mksession` が「幽霊分割」を書き出し、復元後に空白のウィンドウが現れることです。この設定では、**先にサイドバーの状態をスナップショットし、auto-session の通常の終了処理を通した後で、サイドバーを自前で再構築**します。

```lua
-- Restore is per-tab and per-file-window: a right-hand outline next to a
-- vsplit is not the same as "aerial is open".
```

復元は**タブごと、ウィンドウごと**に行われます。垂直分割の右側にあるアウトラインは、「Aerial が開いている」という状態と同じではありません。

## 3. キー操作

| キー | コマンド | 動作 |
|---|---|---|
| `<leader>wr` | `:AutoSession search` | セッションを検索 / 選択 |
| `<leader>ws` | `:AutoSession save` | 現在のセッションを手動保存 |
| `<leader>wa` | `:AutoSession toggle` | 自動保存の切り替え |
| `<leader>wd` | `:AutoSession delete` | 現在のセッションを削除 |

**これらのキーは `<leader>w`（windows）グループに属します**。セッションは本質的に「ウィンドウ配置の保存」だからです。

## 4. 動作の仕組み

### 自動保存と復元

1. `~/development/cobol` で作業し、複数のファイルを開く
2. `:q` で終了 → そのディレクトリのセッションを**自動保存**
3. 次回 `cd ~/development/cobol && nvim` を実行 → **自動復元**

ディレクトリごとにセッションが作られ、互いに干渉しません。`cobol` と `cobol.nvim` を切り替えると、それぞれの配置が復元されます。

### セッションの保存先

```sh
ls ~/.local/share/nvim/sessions/
```

ファイル名にはディレクトリパスがエンコードされています。**これらのファイルを手動で編集しないでください**。`mksession` が生成する形式のため、編集を誤ると復元に失敗します。

### 復元に失敗した場合

設定には `restore_missing_session_paths` があり、「セッションに記録されたファイルが移動または削除されている」場合に対処します。セッションに記録された cwd を基準にパスを再解決しようとします。

## 5. よくある場面

### 例1：翌日に作業を続ける

```
夜：作業途中で :q して終了
朝：cd ~/development/cobol && nvim
    → 昨日開いていたファイル、分割、カーソル位置がすべて戻る
```

### 例2：複数プロジェクトを並行して進める

```
~/development/cobol/        → セッション A（教材編集レイアウト）
~/development/cobol.nvim/   → セッション B（プラグイン開発レイアウト）
~/nvim/                     → セッション C（設定編集レイアウト）
```

ディレクトリを切り替えるだけで配置も切り替わり、手動で開き直す必要はありません。

### 例3：先週のレイアウトを探す

```text
<leader>wr     セッションを検索
```

名前やパスであいまい検索し、選択すると復元します。

### 例4：自動復元しない

何もない状態から始めたい場合：

```text
<leader>wa     自動保存をオフにする
:qa            終了
```

次に入ったとき、セッションは復元されません。

## 6. 練習

### 練習 1：自動保存を確認する

```sh
cd ~/development/cobol
nvim
```

1. 2つのファイルを開く（`:e lessons/17*/lesson.cob` と `:vsplit lessons/20*/lesson.cob`）
2. `:qa` で終了する
3. もう一度 `nvim` を起動する

**確認**：両方のファイルと分割レイアウトが復元される。

### 練習 2：手動で保存する

1. ファイルをいくつか開く
2. `<leader>ws`
3. `:qa`
4. もう一度起動する

**確認**：レイアウトが復元される。

### 練習 3：セッションを検索する

1. `<leader>wr`
2. `cobol` と入力して候補を確認する

**確認**：`cobol` ディレクトリのセッション項目が表示される。

### 練習 4：ディレクトリごとの独立性を確認する

1. `~/development/cobol` でファイル A を開く
2. `:qa`
3. `cd ~/development/cobol.nvim && nvim`
4. 別の（または空の）レイアウトが開くことを確認する

**確認**：2つのディレクトリのセッションが互いに影響しない。

### 練習 5：セッションを削除する

1. `<leader>wd`
2. 削除を確定する
3. 再度入ると、レイアウトが空になっている

**確認**：セッションが削除されている。**この操作は取り消せません**。練習時は対象のディレクトリをよく確認してください。

## 7. つまずきやすい点

### 復元後に空白の分割が現れる

設定は「幽霊分割」の問題に特別に対処していますが、セッションファイルを手動で変更した場合や別のプラグインを使った場合には発生することがあります。対処方法：

```text
<leader>wd     そのディレクトリのセッションを削除
レイアウトを作り直す
<leader>ws     保存し直す
```

### 復元後に Neo-tree / Aerial が表示されない

設定はサイドバーの復元を試みますが、**タブとウィンドウ単位で復元**します。保存時のレイアウトが特殊（たとえば2つの vsplit それぞれにアウトラインがある）だと、一部が失われる可能性があります。

`<leader>fe` / `<leader>cs` で再度開いてください。

### セッションに削除済みファイルが記録されている

設定の `restore_missing_session_paths` が対処しますが、ディレクトリ全体を移動した場合は復元に失敗することがあります。セッションを削除して作り直してください。

### 一時的に何もない状態で起動したい

```sh
nvim --clean      # 設定をまったく使わない
```

または

```text
<leader>wa       自動保存をオフにする
:qa!
```

### セッションと Git ブランチ

`git_auto_restore_on_branch_change = false` のため、ブランチを切り替えてもセッションは切り替わり**ません**。同じファイルであれば、ブランチが異なってもレイアウトは通常同じなので、この動作は意図的です。

## 8. 他のプラグインとの関係

| プラグイン | 管理するもの |
|---|---|
| auto-session | ファイル、ウィンドウ配置、カーソル位置 |
| dashboard | 起動画面（復元できるセッションがない場合に表示） |
| neo-tree / aerial | サイドバー。auto-session の拡張ロジックが保存 |

設定のコメントによると、起動時に Auto Session がプロジェクトのセッションを見つけた場合は先に復元し、復元できるセッションがない場合に Dashboard を表示します。

## 10. 対象範囲

- ここで紹介するキー操作は `lua/plugins/auto-session.lua` の設定に基づきます：`<leader>wr`、`<leader>ws`、`<leader>wa`、`<leader>wd`（すべて `<leader>w` グループ）。
- この設定はプラグインのデフォルトより**大幅に複雑**です。標準の `mksession` が幽霊分割を書き出すため、Neo-tree / Aerial サイドバーのスナップショットと復元を独自に実装しています。
- `<leader>wd`（セッション削除）は取り消せません。
- `rm -rf ~/.local/share/nvim/sessions/` ですべてのセッションを消去できますが、全レイアウトが失われます。
