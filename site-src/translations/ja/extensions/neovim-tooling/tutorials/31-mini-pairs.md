# 自動ペア入力：mini.pairs

`(` を入力すると `)` を自動補完し、`"` を入力すると `"` を補完する。これはエディターの基本的な気配りです。mini.pairs はこの機能に加えて、**煩わしさを避けるための判定**も行います。

---

## 1. 解決する問題

| 場面 | 自動ペアなし | mini.pairs あり |
|---|---|---|
| `(IF ...)` を書く | `(` の後に `)` も入力する | `(` だけ入力 |
| 文字列を書く | 引用符の片方を忘れやすい | 自動補完 |
| カーソルが `)` の前にある | さらに `)` を入力すると `))` になる | **既存の文字をスキップ**（`skip_unbalanced`） |


![`PIC X(10)` のように括弧と引用符が混じる文は、自動ペアの適用範囲です。](images/31-pairs-context.png)

`PIC X(10)` のように括弧と引用符が混じる文は、自動ペアの適用範囲です。

## 2. 設定

`lua/plugins/mini-pairs.lua`：

| オプション | 値 | 意味 |
|---|---|---|
| `modes.insert` | `true` | 挿入モードで有効 |
| `modes.command` | `true` | コマンドラインモードで有効 |
| `modes.terminal` | `false` | ターミナルモードでは無効 |
| `skip_next` | `%w%%%'%[\%"%.%`%$` | 次の文字がこれらの場合は**自動ペア入力しない** |
| `skip_ts` | `{ "string" }` | 文字列ノード内ではペア入力しない |
| `skip_unbalanced` | `true` | 右括弧が多い場合はスキップ |
| `markdown` | `true` | Markdown コードブロック向けに調整 |

### `skip_next` が重要

```lua
skip_next = [=[[%w%%%'%[%"%.%`%$]]=],
```

意味：カーソルの**直後**が次の文字なら、閉じ側を自動入力しません。

| 文字 | 例 | 補完しない理由 |
|---|---|---|
| `%w` | `a` `1` | `(a)` ではなく `a)` を書く場合がある |
| `%'` | `'` | 引用符がすでにある |
| `%[` | `[` | 角括弧がすでにある |
| `%"` | `"` | 二重引用符がすでにある |
| `%.` | `.` | `obj.method(` の可能性がある |
| `` %` `` | バッククォート | バッククォートがすでにある |
| `%$` | `$` | 変数記号 |

**すでに `)` があるのに、もう一つ補完されてしまう気まずさを防ぎます。**

### `skip_unbalanced = true`

右側の閉じ記号が開き記号より**多い**場合、開き記号を入力しても自動補完をスキップします。

例：`(a + b))` で2つ目の `)` の前にカーソルがあるとき `(` を入力しても、括弧の数が不均衡なので `)` は補完されません。

### 有効／無効の切り替え

設定では Snacks toggle を登録しています。状態の確認：

```vim
:lua =vim.g.minipairs_disable
```

`nil` または `false` なら有効です。

## 3. 使い方

### 基本

| 入力 | 結果 |
|---|---|
| `(` | `()` になり、カーソルは中間 |
| `[` | `[]` |
| `{` | `{}` |
| `"` | `""` |
| `'` | `''` |
| `` ` `` | ` `` ` |

### カーソルで閉じ側をスキップ

ペア入力後に閉じ側を入力する（または `→` を押す）と、新しい文字を挿入せず、既存の閉じ側を**スキップ**します。

```text
输入 (  →  ()
输入 )  →  ()|    光标跳到 ) 之后，不是 ())
```

### 削除

`()` の中間でバックスペースを押すと、設定によっては両側が一緒に削除されます。

## 4. COBOL での使い方

### 場面1：`PIC X(10)` を書く

1. `PIC X(` と入力
2. `PIC X()` に自動補完される
3. `10` と入力
4. `)` を入力するとカーソルが既存の文字をスキップ

**結果**：余分な括弧のない `PIC X(10)` になります。

### 場面2：文字列リテラルを書く

```cobol
DISPLAY "HELLO".
```

1. `DISPLAY "` と入力
2. `DISPLAY ""` に自動補完される
3. `HELLO` と入力
4. `"` を入力して既存の引用符をスキップ
5. `.` を入力

### 場面3：`VALUE` 節

```cobol
01 WS-FLAG PIC X(1) VALUE "A".
```

括弧と引用符の2種類のペアを続けて使いますが、閉じ側を手で補完する必要はありません。

### 場面4：入力の邪魔を避ける

COBOL のコメント行（第7列が `*`）に文章を書くとき、`skip_next` が余分なペア入力を防ぎます。

## 6. つまずいたとき

### `(` を入力しても `)` が補完されない

`skip_next` を確認してください。カーソルの直後に英字、引用符、`.` などがあるか確認します。これは意図した動作です。

### 文字列内でペア入力されない

`skip_ts = { "string" }` により、Treesitter が認識した文字列ノード内ではペア入力されません。**COBOL には parser がない**ため、このルールは COBOL では機能しません。ただし引用符のペアは `skip_next` で大半のケースを扱えます。

### Markdown では挙動が異なる

`markdown = true` はコードブロックを特別扱いします。Markdown 内の ``` `code` ``` ではペア入力が調整されます。

### 完全に無効にしたい

```vim
:lua vim.g.minipairs_disable = true
```

またはプラグイン設定を削除します。

### blink.cmp と競合する

補完メニューが開いているときに `(` を押すと、補完に処理されることがあります。**実際の動作を確認してください**。どちらも挿入モードのキー入力を監視します。

## 8. 適用範囲

- このページの設定は `lua/plugins/mini-pairs.lua` に基づきます。挿入モードとコマンドラインで有効、ターミナルでは無効で、`skip_next` に7種類の文字パターンがあります。
- **`skip_next` は意図した動作です**。カーソルの次が英字、引用符、`.`、`$` などなら閉じ側は補完されません。これは不具合ではありません。
- `skip_ts = { "string" }` は Treesitter に依存するため、**COBOL に parser がない場合は機能しません**。
- blink.cmp と併用したときにどちらがキーを処理するかは、実際に確認してください。
