# ファイルと内容の検索：snacks.nvim picker

32 レッスンのリポジトリで項目名を探す、コピーブックを開く、`PERFORM` 段落へ飛ぶ。**検索の速さがコード読解の速さを決めます。**

`snacks.nvim` の picker は現在の設定の主力入口です。ファイル検索、内容検索、バッファ切替、ヘルプ閲覧をすべて同じ画面で行います。まずこれを覚えれば、他のプラグインの話が頭に入ります。

本ページはあなたのローカル設定に基づきます。汎用チュートリアルではありません。

---

## 1. 何を解決するか

picker なしの非効率な 3 パターン：

| やり方 | 問題 |
|---|---|
| `:e path/to/file` | パスを覚える必要がある。深い階層では無理 |
| `:vimgrep /pattern/ **/*` | エディタがブロックされ、結果は quickfix に溜まる |
| Neo-tree を順にクリック | ディレクトリ構造しか見えず、中身が見えない |

picker の方法：**数文字入力 → 即時絞り込み → 右側にプレビュー**。ウィンドウを離れずに「これかどうか」が分かります。

## 2. 実際のキー割り当て

`lua/config/keymaps-defaults.lua` で定義されています。`<leader>` は**スペース**です。

### ファイルを探す

| キー | 動作 | 使いどころ |
|---|---|---|
| `<leader><space>` | ファイル検索（プロジェクトルート） | まずこれ一つ覚える |
| `<leader>ff` | ファイル検索（現在の cwd） | サブディレクトリ内だけ見たい |
| `<leader>fF` | ファイル検索（Git ルート） | 深い階層から全リポジトリを検索 |

**違いは検索の起点だけです。** `<leader>fF` は `.git` まで遡ってから検索するため、`lessons/17_xxx/` からでも `extensions/` 配下のファイルに届きます。

### 内容を検索する（grep）

| キー | 動作 |
|---|---|
| `<leader>fg` | リポジトリ全体を grep |
| `<leader>fG` | この設定では同じ実装 |
| `<leader>/` | 同じ、別の入口 |
| `<leader>fw` | **カーソル下の単語**を grep（cwd） |
| `<leader>fW` | カーソル下の単語を grep（ルート） |
| `<leader>fc` | カーソル下の単語を grep |

`<leader>fw` が最も楽です。`WS-RECORD-COUNT` の上で押すだけで、入力の手間が省けます。

### バッファとその他

| キー | 動作 |
|---|---|
| `<leader>fb` または `<leader>,` | 開いているバッファを切替 |
| `<leader>fr` | 最近開いたファイル |
| `<leader>fR` | **直前の picker を再開**（結果も保持） |
| `<leader>fh` または `<leader>?` | ヘルプを検索 |
| `<leader>fS` | 現在ファイルの Treesitter シンボル |

`<leader>fR` は見落としやすいですが便利です。検索の途中で編集に行き、戻って押すと、検索語も結果もそのまま残っています。

## 3. picker 内の操作

開くと 3 つの領域があります。

```text
┌──────────────────────────────────────────────┐
│  入力欄（入力で即絞り込み）                    │
├────────────────────────┬─────────────────────┤
│  結果リスト             │  プレビュー（追従）  │
│  ↑↓ で選択             │  シンタックスハイライト│
└────────────────────────┴─────────────────────┘
```

### 移動と開く

| キー | 動作 |
|---|---|
| 入力を続ける | 即時絞り込み、結果がすぐ変わる |
| `<C-n>` / `<C-p>` または `↑` `↓` | 選択を上下 |
| `<CR>` | 開く（現在のウィンドウを置換） |
| `<C-s>` | 水平分割で開く |
| `<C-v>` | 垂直分割で開く |
| `<C-t>` | 新しいタブで開く |
| `<Esc>` | 閉じる |

### 表示の調整

| キー | 動作 |
|---|---|
| `<a-p>` | プレビュー窓の開閉 |
| `<a-m>` | 最大化／復元 |
| `<a-w>` | 入力欄と結果リストのフォーカス切替 |
| `/` | フォーカス切替 |
| `<a-h>` | 隠しファイルの表示切替 |
| `<a-i>` | gitignore 対象の表示切替 |
| `<a-r>` | 正規表現モードの切替 |
| `<a-f>` | フォローモードの切替 |
| `<C-d>` / `<C-u>` | 結果リストのページ送り |
| `<C-f>` / `<C-b>` | プレビューのページ送り |
| `<a-d>` | 現在項目の内部データを表示（デバッグ用） |

### 結果を別へ送る

| キー | 動作 |
|---|---|
| `<C-q>` | 全結果を quickfix リストへ |
| `<Tab>` | 現在項目を選択して次へ（複数選択） |
| `<S-Tab>` | 選択して前へ |
| `<c-a>` | 全選択 |

`<C-q>` は特に練習する価値があります。grep 結果を quickfix に入れれば `:cnext` / `:cprev` で 1 件ずつ移動でき、`quicker.nvim` と組み合わせて文脈を展開できます。

## 4. 実測記録

以下はこのリポジトリでの実際のセッションでの観察です。推測ではありません。

### ファイル検索

`<leader>ff` を押して `account-master` と入力：

```text
lessons/17_fixed-length-files/account-master-200.dat
extensions/…/labs/03-one-to-many/starter/BATCHL2.COB
extensions/…/labs/04-many-to-many/starter/BATCHL3.COB
…
```

入力欄の右に `2624/2624`（一致数/総数）が表示されました。`<CR>` で開くと、**position-ruler の桁ルーラーが即座にウィンドウ上部へ**現れます。

```text
1...+...10....+...20....+...30....+...40....+...50....+...60....+...70....+...80
0001234567C0001042TANAKA ICHIRO                 BR-TOKYO2020011520261014ORDINARY
```

ここが 2 つのプラグインの協調点です。picker がファイルを見つけ、position-ruler が固定長レコードの項目位置を見せます。

### 内容検索

`<leader>fg` で `WS-RECORD-COUNT` と入力：

```text
WS-RECORD-COUNT                        30/30

lessons/17_fixed-length-files/lesson.cob:42:10
lessons/17_fixed-length-files/lesson.cob:85:24
lessons/17_fixed-length-files/lesson.cob:106:48
lessons/17_fixed-length-files/README.md:119:27  计数字段宽度
lessons/…/lesson.cob:21:10        01 WS-RECORD-COUNT P
lessons/…/INPUTCSV.COB:50:15            05  WS-RECO
```

**30 件が 3 ファイル以上にまたがり**、各行に `ファイル:行:桁` が付きます。右のプレビューが一致行の前後をそのまま表示するので、ファイルを開く必要はありません。

### バッファ切替

`<leader>fb` を押すと：

```text
2/2
10  #a  account-master-200.dat:1:33
1    h  lesson.cob:1:6
```

バッファ番号、変更マーク（`#` = 変更あり）、行:桁が表示されます。先頭の数字が `<C-^` で移動できるバッファ番号です。

## 5. COBOL 開発での頻出 5 パターン

### 用法 1：ある項目の全参照を探す

`WS-ACCOUNT-STATUS` の上で `<leader>fw`。

すべての参照が即座に出ます。項目を変更する**前に必ず行う**手順です。影響範囲を知ってから、マルチカーソルを使うか決めます（[マルチカーソルのページ](08-multicursor-batch-editing.md)参照）。

### 用法 2：課をまたいで実装を比較する

第 17 課と第 32 課の固定長処理を比べる：

```text
<leader>ff → fixed-length と入力 → 選択
```

内容検索なら `<leader>fg` → `RECORD CONTAINS 27` で関連する課が一度に出ます。

### 用法 3：コピーブックの定義を探す

`01  ACCOUNT-REC` や `PIC X(10)` を検索して `.CPY` 内の宣言へ移動します。

`<leader>fF`（Git ルート検索）なら、深い実験ディレクトリからでも `extensions/enterprise-batch/` 配下のコピーブックに届きます。

### 用法 4：あるキーが使われているか確認する

`<leader>fh` でヘルプ検索、または `<leader>?`。

特定キーの割り当てを知るには `:verbose nmap <leader>fw`。最終的なマッピングと定義元ファイルが表示されます。

### 用法 5：結果を quickfix へ送って順に処理する

`WS-RECORD-COUNT` を 30 件 grep したら `<C-q>`：

```vim
:cnext    " 次へ
:cprev    " 前へ
:copen    " quickfix ウィンドウを開く
```

picker 内で行き来するより集中できます。

## 6. 演習

### 演習 1：フィクスチャを探して開く

```sh
cd ~/development/cobol
nvim
```

1. `<leader>ff`
2. `account-master` と入力
3. `<CR>`

**合格条件**：`lessons/17_fixed-length-files/account-master-200.dat` が開き、ウィンドウ上部に `1...+...10` のような桁ルーラーが出ること。

### 演習 2：カーソル下の単語で検索

同じファイル（`.dat` を開いた場合は `lesson.cob` に切替）で、`WS-` で始まる単語の上にカーソルを置く：

1. `<leader>fw`
2. 結果件数を確認

**合格条件**：入力欄にその単語が自動で入り、全参照が一覧されること。

**比較実験**：`<leader>fg` で同じ単語を手入力しても結果は同じです。`<leader>fw` は入力の手間を省くだけです。

### 演習 3：quickfix への受け渡し

1. `<leader>fg` → `FILE STATUS`
2. `<C-q>` で quickfix へ
3. `:copen`
4. `:cnext` を 3 回

**合格条件**：quickfix ウィンドウが存在し、`:cnext` のたびに新しい `FILE STATUS` 位置へ移動すること。

### 演習 4：検索の再開

1. `<leader>fg` → 任意の単語を検索
2. `<Esc>` で閉じる
3. 少し編集する
4. `<leader>fR`

**合格条件**：picker が再び開き、検索語と結果が残っていること。

### 演習 5：複数選択して quickfix へ

1. `<leader>fg` → `PIC X(`
2. `<Tab>` で先頭 3 件を選択
3. `<C-q>` で選択分だけ送る

**合格条件**：quickfix に入るのは選んだ 3 件だけで、全部ではないこと。

## 7. つまずきやすい点

### `<leader>ff` で目的のファイルが出ない

3 つの可能性：

1. **gitignore 対象**：`<a-i>` を押す。
2. **隠しファイル**（`.` で始まる）：`<a-h>` を押す。
3. **cwd の外にある**：`<leader>fF`（Git ルート）に切り替える。

### grep で何も出ない

`<leader>fg` は ripgrep を使い、既定で `.gitignore` を尊重します。`build/site/` の生成物を検索する場合も `<a-i>` が必要です。

### `<Esc>` を押しても picker に残る

この設定では `<Esc>` は picker を閉じます。`<C-c>`（挿入モードでキャンセル）を押すと入力欄に戻るだけなので、もう一度 `<Esc>` を押してください。

### 大きなリポジトリで初回検索が遅い

ripgrep は初回スキャンでキャッシュを作るため、2 回目以降は速くなります。500 ファイル超で数百ミリ秒は正常範囲です。

## 8. 他のプラグインとの関係

| 目的 | 使うもの |
|---|---|
| **ファイル**を探す | `<leader>ff`（snacks） |
| **内容**を探す | `<leader>fg`（snacks） |
| **画面に見えている文字**へ飛ぶ | `s`（flash、[flash のページ](10-flash-jump.md)） |
| **ファイル横断の一括置換** | `<leader>sr`（grug-far、[grug-far のページ](11-grug-far.md)） |
| **ディレクトリ構造**を読む | `<leader>fe`（Neo-tree） |

**重要な区別**：snacks は「文字で位置を探す」、flash は「目で位置を探す」。探す対象が分かっているなら前者、見えているが行数を数えたくないなら後者です。

## 10. 範囲と限界

- 本ページのキーはローカル設定（`lua/config/keymaps-defaults.lua`）由来で、プラグインの既定値ではありません。設定変更後は `:map <leader>f` で再確認してください。
- `<leader>fg` と `<leader>fG` はこの設定では同じ実装を指し、実質的な差はありません。
- 実測記録は実際の Neovim セッションによるものです。ターミナル幅によりレイアウト比率（`width = 0.85`）が変わり、プレビュー窓の幅は前後します。
