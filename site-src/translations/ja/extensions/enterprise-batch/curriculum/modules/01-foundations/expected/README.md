# 独立した期待結果と手作業による照合（モジュール 01）

このディレクトリの期待結果は、ACCOUNT v1 契約とレコードごとの手作業による照合から導き出したものであり、プログラム出力のコピーではありません。
`check.py` は制御レポートをバイト単位で比較し、元のフィクスチャから `accepted.dat` と
`rejected.dat` を独立して導出します。ファイル全体の `trim` は行いません。

## 契約ルール

ACCOUNT v1 レコードは、47 バイト内で次の条件を満たす必要があります。口座番号 1–10 はすべて数字、通貨 19–21 は `JPY`、
符号 22 は `+`/`-`、金額 23–35 はすべて数字、状態 36 は `A`/`F`/`C`、日付 37–44 はジョブの
営業日と一致し、レイアウトバージョン 45–47 は `001` であること。ファイル内の口座番号は厳密な昇順でなければなりません。

- 構造上の契約違反（長さ、LF、CR、口座番号の文字、レイアウト、日付、並び順／重複キー）：RC8。バッチ全体が失敗し、
  出力ディレクトリは公開されません。
- フィールドの業務ルール（未知の状態）：RC4。そのレコードは `rejected.dat` に入り、残りは `accepted.dat` に入り、
  照合済みの結果は公開されます。
- 読み込み件数の保存則：`READ = ACCEPTED + REJECTED`。

## フィクスチャごとの照合

**normal**：3 レコード。口座番号 1/2/3 は厳密な昇順で、状態 A/F/C はすべて有効 → 受理 3、拒否 0。

```text
READ=000000000003  ACCEPTED=000000000003  REJECTED=000000000000
```

**empty**：0 バイトのファイル。空でもよい → 0 件を読み込み。

```text
READ=000000000000  ACCEPTED=000000000000  REJECTED=000000000000
```

**single**：1 レコード。口座番号 42、状態 A → 受理 1。

```text
READ=000000000001  ACCEPTED=000000000001  REJECTED=000000000000
```

**unknown-status**：1 レコード。口座番号 7、状態 `Z`（`A/F/C` に含まれない）→ 1 件を拒否、理由は `UNKNOWN-STATUS`。

```text
READ=000000000001  ACCEPTED=000000000000  REJECTED=000000000001
```

拒否レコードの形式は元の 47 バイト + `|` + 理由です。そのため、`rejected.dat` のこの行は LF を除いて 62 バイトです。

```text
000000000700000003JPY+0000000000000Z20261009001|UNKNOWN-STATUS
```

## 公開条件

制御行 `CONTROL|READ=..|ACCEPTED=..|REJECTED=..` が上記の照合結果と一致し、`accepted.dat`/`rejected.dat` がバイト単位で一致した場合に合格です。RC8 フィクスチャの合格条件は、出力ディレクトリが**作成されない**ことと、ソースフィクスチャの SHA256 が変わらないことです。
