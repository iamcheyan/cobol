# Boss L2：v1ファイルと業務契約

## バージョン管理インターフェース

ACCOUNT v1は47バイト、TRANSACTION v1は55バイトを維持し、`BANK-SYSTEM.md`の定義どおり解釈します。status=N、direction、amountに別の意味を与えません。ファイルはASCII、LF終端で、論理幅にLFを含めません。短/長行と最終LF欠落は拒否します。JOB業務日は引数で渡します。金額はJPY最小通貨単位の整数で、小数換算しません。

新設する`REVERSAL-LINK v1`関連ファイルは1レコード48バイトです：口座ID10、取消取引sequence6、取消取引ID16、原取引ID16。口座/sequence/取消取引ID順に厳密整列します。取消取引には必ず関連が1件あり、他の取引には関連がありません。このインターフェースは55バイト取引配置を保ったまま、取消対象を明示的に検証します。

## 業務方針

- 口座status Aのみ入金/計上可能です。F凍結、C閉鎖口座の取引は個別拒否し、残高を変えません。取引のない口座も期末Masterに出力します。
- 金額0は`ZERO-AMOUNT`で拒否します。13桁すべて9は1取引/口座残高の上限です。最大残高超過は`OVERFLOW`、利用可能残高を超える出金は`OVERDRAFT`です。取引金額に負数は使わず、directionが貸方/借方を示します。期首残高は符号と13桁金額で構成し、範囲は±9,999,999,999,999です。
- 通常取引のstatusはN必須です。口座のない取引は孤立レコードとして`NO-ACCOUNT`で拒否します。各入力取引は受理または拒否のどちらかに必ず1度だけ分類します。
- 取消は同一業務日、同一口座、より小さいsequenceで、先に受理された通常取引を参照します。取引IDは全体一意です。方向は反対、金額は完全一致が必要です。原取引は1回だけ取消可能です。対象なし/未受理/取消取引/取消済み/別口座、金額または方向不一致は拒否し、残高と台帳を変更しません。取消自体にも当座貸越/オーバーフロー検査を行います。同一口座の任意の過去取引を参照でき、間に他取引があっても構いません。
- 全体で重複する取引ID（口座が異なる場合や非隣接を含む）と取消関連ID重複はデータ契約違反RC8で、公開しません。同一口座の隣接行だけ調べても全体重複排除にはなりません。
- 1取引が複数業務問題に該当する場合、拒否理由優先順位は固定：口座F/C状態、金額0、取消参照の有効性、当座貸越/オーバーフロー。構造破損は常に全体RC8で、行単位拒否に格下げしません。
- 口座と口座/sequence/ID順の取引を順次読みます。作業メモリは現在レコードと単一口座残高のみです。一時BDB INDEXED台帳でIDから受理済み原取引を検索し、取消状態をREWRITEします。ディスク使用量は取引数に応じて増えますが、メモリはファイル/グループサイズに応じて増えません。外部SORTは全体ID重複検査だけに使います。

## 手計算例

口座A1の期首1000：T01貸方500を計上 → 1500；T02借方200 → 1300；T03はT01を取り消して借方500 → 800（間にT02があっても原取引を特定可能）；T04借方900は当座貸越で拒否され、800のままです。したがってA1は期末800、受理3件、拒否1件。凍結口座A2の貸方100は拒否され、残高50を維持します。A3は取引なしで0のままです。全体読込5件 = 受理3件 + 拒否2件；期末合計850 = 期首1050 + 受理貸方500 − 受理借方700。取消は逆方向の金額に含み、取引履歴を削除しません。

## 出力とRC

候補レポートは順に各POST/REJECT明細、口座期末行と口座control行、最後に全体control行を出力します。公開ディレクトリには`master.dat`（元47バイトMasterの残高以外を保持し、残高符号/金額だけ変更）、`accepted.dat`（受理した元55バイト取引）、`rejected.dat`（拒否した元55バイト取引、区切り、行ごとの理由）も含みます。ファイルは非公開stageへ書き、保存式とstatus検査後にまとめて公開します。候補stdoutは正式結果ではありません。runnerは入力/出力SHA256 manifestと参考ソースSHA256を保存します。control列は読込/受理/拒否件数と受理貸方/借方を含み、拒否金額は残高や合計に含めません。RC方針：

| RC | 意味 | 出力方針 |
|---:|---|---|
| 0 | 業務拒否なし、すべて保存式を満たす | 公開 |
| 4 | 行単位の業務拒否あり（凍結/閉鎖/当座貸越/overflow/金額0/孤立/取消参照問題）。ファイル契約は有効 | 拒否明細付き検証済み結果を公開。呼出側JOBはRC4続行を明示的に許可すること |
| 8 | ファイル配置、順序、全体ID一意性、関連完全性などの契約違反 | 全体失敗、公開なし |
| 12 | ファイルシステム、索引、build、lock、公開の失敗 | 全体失敗、公開なし |

口座単位：`closing = opening + accepted credits - accepted debits`、取引件数 = 受理 + 拒否。全体：入力取引 = 受理 + 拒否、口座数 = 取引あり口座 + 取引なし口座、受理金額と拒否件数を独立に照合します。口座/全体件数は12桁で、SIZE ERROR時は失敗します。口座別残高/取引金額は13桁、全体金額累計は正確な18桁10進数です。オーバーフロー時は公開しません。同一キー取引グループをbufferしないため、取引行は各口座の期末行より前に出力します。
