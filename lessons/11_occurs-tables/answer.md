# 第 11 课修改练习参考答案

本答案只回答 `exercise.md` 的三项修改练习，不提供举一反三练习答案。每题都从本课原始 `lesson.cob` 单独修改，命令与 README 一致：

```sh
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_11 lesson.cob
./build/lesson_11
```

以下输出均为本工作区实测，三次语法检查/编译/运行退出码全部为 `0`；运行时标准错误另有 libxml 版本警告，不是程序输出。

## 1. 改第四项金额

改动只有一行（`1000-LOAD-TABLE`）：

```cobol
           MOVE 35.00 TO WS-TXN-AMOUNT(4)
```

完整预期输出：

```text
明細=01 コード=C 金額=00125.50
処理=入金
明細=02 コード=D 金額=00040.10
処理=出金
明細=03 コード=X 金額=00025.00
処理=未知コードを無視
明細=04 コード=C 金額=00035.00
処理=入金
処理件数=004
最終残高=0001120.40
```

差异与原因：`C` 分支把该项金额加入余额，因此只有 `明細=04` 那一行的金额和 `最終残高` 变化：`1000.00 + 125.50 − 40.10 + 35.00 = 1120.40`。`処理件数` 仍是 `004`（按表项计数，与金额无关），前 6 行逐字节不变。

## 2. 扩为五项并装入第五项

三处必须同时改，否则容量、已装入项数和遍历上界不一致：

```cobol
          05 WS-TRANSACTION-ENTRY OCCURS 5 TIMES.
       01 WS-LAST-SAMPLE PIC 9 VALUE 5.
           MOVE "C" TO WS-TXN-CODE(5)
           MOVE 10.00 TO WS-TXN-AMOUNT(5).
```

第五项的两条 `MOVE` 接在第四项之后，`WS-TXN-AMOUNT(4)` 保持 `20.00`。完整预期输出：

```text
明細=01 コード=C 金額=00125.50
処理=入金
明細=02 コード=D 金額=00040.10
処理=出金
明細=03 コード=X 金額=00025.00
処理=未知コードを無視
明細=04 コード=C 金額=00020.00
処理=入金
明細=05 コード=C 金額=00010.00
処理=入金
処理件数=005
最終残高=0001115.40
```

差异与原因：新增项 `C`／`10.00` 被 `PERFORM VARYING` 处理到，余额由 `1105.40` 增加到 `1000.00 + 125.50 − 40.10 + 20.00 + 10.00 = 1115.40`，处理件数由 `004` 变为 `005`；原有四项输出不变，新项是最后一行明细。

## 3. 越界观察：只把遍历上界改为 5

改动只有一行：

```cobol
       01 WS-LAST-SAMPLE PIC 9 VALUE 5.
```

实测结果：

- `cobc -fsyntax-only lesson.cob` 与编译都返回 `0`，没有任何诊断：编译器不检查下标是否落在容量内。
- 运行退出码仍为 `0`，第 5 项照常被打印：`明細=05 コード=0 金額=5`，其后是四个不可打印的 NUL 字节和 `.00`。
- 这些字节既不是 `C` 也不是 `D`，`EVALUATE` 走 `WHEN OTHER`，输出 `処理=未知コードを無視`；最终 `処理件数=005`、`最終残高=0001105.40`（恰好等于四项的结果，因为读到的字节没有进入记账分支）。
- 因此程序既不报错、也不返回非零码，但第 5 项的数字完全不可信。

原因：表格四项共 32 字节，下标 5 的地址落在表外；GnuCOBOL 默认按下标直接计算地址，不做边界校验，于是读到紧邻表格之后的工作存储字节（`cobc -C` 生成的数据布局显示表后紧接着 `WS-SAMPLE-INDEX` 等字段）。读到的内容取决于编译器布局，换版本或调整字段顺序都会不同，所以既不能预测，也不能当作业务数据。

正确做法是让容量、已装入项数和遍历上界三处一致（如第 2 题），或在读取前显式校验下标范围；批处理里静默读错字节比直接失败更难发现。
