# 第 02 課 修正演習 参考解答

この解答は `exercise.md` の 3 件の初期値変更と境界セルチェックのみをカバーします。発展演習の解答は提供しません。

## 3 件の変更

この課の元の `lesson.cob` から出発し、3 つのデータ宣言の `VALUE` 句だけを変更してください。

```cobol
       01 WS-BRANCH-CODE PIC 9(4) VALUE 3107.
       01 WS-CURRENCY-CODE PIC X(3) VALUE "EUR".
       01 WS-CUSTOMER-NUMBER PIC X(10) VALUE "0000000042".
```

フィールド名、`PIC`、フィールドの順序、`PROCEDURE DIVISION` は変更しないでください。再コンパイルして実行します。

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_02 lesson.cob
./build/lesson_02
```

`cobc -fsyntax-only` と `cobc -x` はどちらも `0` を返し、診断メッセージは出ません。プログラム終了コードは `0`（stderr には libxml の環境警告のみ）。

## 完全な期待差分

元のプログラムの標準出力と比較し、ちょうど 3 行が異なります。

| 元の出力 | 修正後の出力 | 理由 |
|---|---|---|
| `支店コード=2048` | `支店コード=3107` | `PIC 9(4)` の初期値を `3107` に変更。4 桁の幅はそのまま |
| `通貨コード=USD` | `通貨コード=EUR` | `PIC X(3)` の 3 文字が `EUR` に置き換わる。幅は不変 |
| `顧客番号=0002046819` | `顧客番号=0000000042` | `PIC X(10)` は依然 10 文字を 1 文字ずつ保存し、先頭ゼロをそのまま残す |

他の 26 行は 1 バイトも変わりません。他のフィールドの `PIC` や初期値に変更を加えていないためです。出力行ラベルは日本語です。顧客番号の行は `顧客番号=` で、フィールド名 `WS-CUSTOMER-NUMBER` ではないことに注意してください。

## 顧客番号が PIC X(10) のままである理由

顧客番号は識別子であり、加減算に関わる数量ではありません。

- 先頭ゼロはキー値そのものの一部です。この課では、同じ 10 桁の文字列を `PIC 9(10)` と `PIC X(10)` で宣言しても `DISPLAY` の見た目は同じ（両方とも `0002046819` と出力）であることを実測済み。違いはこの 1 回限りの表示にはありません。意味論にあります。`9` はフィールドを数値と宣言し、以降のプログラムロジックは数値セマンティクス（算術に参加、数値として整列、数値として比較）で扱います。しかし顧客番号は算術に参加すべきではなく、数値処理の先頭ゼロ脱落や桁数変化にも巻き込まれるべきではありません。
- `X` を使えば、純粋な数字ではない値（区切り文字やチェック桁を含む番号体系など）も収容できますが、この課ではそうした値を導入しません。
- 結論：幅は `X(10)` のまま維持し、変更は `VALUE` だけに留めます。

## 境界セルチェック

`WS-BRANCH-CODE` の初期値を一時的に `12345` に変更した後の、このマシンでの実測：

- `cobc -fsyntax-only lesson.cob` と `cobc -x -Wall -o build/lesson_02 lesson.cob` の両方が、その宣言行を指して `warning: value size exceeds data size [-Wothers]` を出力します。両コマンドのリターンコードは依然 `0`。
- 実行すると、その行は `支店コード=2345` に変わります。初期値 `12345` が `PIC 9(4)` の容量を超えたため、最上位の `1` が落ち、残り 4 桁の `2345` が残る。
- プログラムは実行時エラーを出さず、終了コードも `0` のまま。

つまり `PIC 9(n)` の幅はハードな制約です。あふれはコンパイル時の警告に過ぎず、切り詰められた値がそのままプログラムに入ります。初期値を書き終えたら幅を確認してください。このマシン上の GnuCOBOL 3.2.0 では `-Wall` を付けなくてもこの警告は現れます。セルチェックが終わったら初期値を `3107` に戻してください。
