# inc-07 讲师根因（记录长度不符 / 字段错位 → 结构错误）

## 触发条件
`input/transaction.dat` 第 1 条记录只有 **54 字节**（比冻结的 TRANSACTION
v1 少 1 字节，末位 status 缺失，字段相对定长布局错位），其余 3 条为合法
55 字节。Manifest 声明的是**交付字节**的校验和，因此 JOB001 接收/校验和
通过；JOB002 的校验器在**长度前提**检查处判定为**结构错误**。

## 逐层提示阶梯（对应 student/hints.md）
1. 失败在 JOB002、RC8；JOB001 已 COMPLETE，说明接收校验和与内容契约
   检查是两个边界。
2. 读 `M11VAL.COB` `2000-PROCESS`：长度 ≠ 55 → `WS-STRUCT='Y'`，整批
   中止（不是逐笔业务拒绝 RC4）。
3. 用 `awk '{print NR": "length($0)}'` 定位第 1 条为 54 字节；与
   `TRANSACTION-V1.CPY` 的 55 字节布局对照，末位 status 缺失、字段错位。
4. 根因是**数据交付**（长度/落盘）问题，非程序缺陷；禁止放宽长度检查。

## 误导线索
- “接收校验和通过 = 内容合法”：校验和只证明字节未被改动，不证明符合
  内容契约长度。
- “重跑即可”：重跑同一坏数据仍 RC8。
- “把长度检查删掉/改成 >= 就能过”：会把错位记录当合法数据，属篡改断言。

## 证据
- `scene/logs/JOB002.log`：`BANKVAL: record length 0054 is not 55`；
  `BANKVAL: structural error, batch failed`；原始 RC=8（`scene/rc.txt`）。
- `scene/scheduler-status.txt`：JOB002 FAILED rc=8，JOB003+ NOT_RUN。
- 无 `publish/<run_id>`，锁释放。

## 最小修复
源数据：补齐/重传为 55 字节定长记录后重新交付。程序侧**不需要且不应**
修改；校验器行为与冻结契约一致。

## 恢复 / 重跑
以修正后的输入、**新 run_id 与新输出目录**重跑；不得覆盖失败目录。

## 防再发
接收后长度/记录数哨兵、上游定长校验、传输前字段级校验与告警。

## 评分点
- 正确判定为结构错误（RC8）而非业务拒绝（RC4）。
- 以原始字节长度与偏移证明，而非只贴日志。
- 明确“不改数据、不放宽长度校验”；恢复使用新 run_id。
