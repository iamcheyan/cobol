# 卒業課題：完全な GNUCOBOL バッチアプリケーションを構築する

## 学習目標

要件の分解、入力形式、Copybook、データ検証、順次ファイル、業務計算、制御ブレーク帳票、終了コード、Bash テスト、ドキュメント。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言や処理箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を確認しましょう。

## サンプルコード

[`L28.COB`](./L28.COB) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行しましょう。

## コンパイルと実行

リポジトリのルートから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/28-capstone-night-batch/L28.COB
cobc -x -Wall -o build/l28 extensions/legacy-workshop/lessons/28-capstone-night-batch/L28.COB
./build/l28
```

確認すること：卒業課題の仕様は README にあります。BATCHRPT.COB と INPUTCSV.COB を組み合わせて始められます。

コンパイラが形式や列位置のエラーを報告した場合は、まず 7、8、12、72 列目を確認します。次に、ピリオド、変数の PIC、スコープ終端文を確認してください。`-Wall` は追加の警告を表示します。警告も内容を理解してから対処するか判断しましょう。

## 各段落を理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言がある場合は、階層番号と PIC を確認しましょう。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文によって経路が変わるか、`STOP RUN` でプロセスが終了するまで、ソースコードの順に実行されます。

## 変更演習

まず入出力の例と受け入れ条件を書き出し、段落に分けてからテストスクリプトを追加します。繰り返し実行しても予測可能な結果になるようにしてください。

変更のたびに、構文チェック、コンパイル、実行をやり直します。一度に変更する概念は1つだけにし、変更前後の出力を記録しましょう。

## cobol.nvim を使った学習

Aerial で構成を確認します。記録計算、診断、Copybook へのジャンプ、折りたたみについて、それぞれ1回ずつコードレビューを行いましょう。

プラグインが応答しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に使用します。プログラムがコンパイル可能かどうかは、GNUCOBOL による実際のコンパイル結果で判断します。
