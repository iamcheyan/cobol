# エンタープライズ COBOL Batch シラバス


## モジュールと授業項目

### 01 COBOLとLegacyシステム（3時間）

- 01.1 営業日、オンライン処理と夜間Batch、プログラムとJOBの違い。初期システム図を作成。
- 01.2 GNUCOBOLのコンパイル、リンク、ランタイム、ビルドディレクトリ。同じ銀行プログラムをコンパイルし、ビルド失敗の原因を特定。
- 01.3 DIVISION/SECTION/Paragraph、ピリオドとスコープ、固定形式/自由形式の比較。
- 成果：環境の証跡、最小限の銀行バッチ入口、ソースと実行ファイルの関係図。
- 受け入れ確認：クリーンなディレクトリから再現できる。入力、出力、実際の入口を示し、列の切り詰めエラーを説明できる。

### 02 データ定義と顧客Record（4時間）

- 02.1 PIC X/A/9、01/05/77/78/88、VALUE、グループ項目と基本項目。
- 02.2 S/V、金額範囲、暗黙小数、MOVEのクラス変換、切り詰めと埋め合わせ。
- 02.3 顧客Record v1：ID、氏名、区分、状態。フィールド一覧を作成。
- 成果：顧客Copybook、フィールド契約、MOVEの実験表。
- 受け入れ確認：桁数/バイト数/数値範囲の違いを説明できる。負数とXへのMOVEについて、実験で得られた結果を説明できる。

### 03 データの内部表現（5時間）

- 03.1 DISPLAY、SIGN/SEPARATE、COMP/BINARY/COMP-5、COMP-3。論理定義とABI。
- 03.2 同じ金額を生バイトとして書き出し、Hex Dumpで符号、暗黙小数、バイト順、長さを比較。
- 03.3 不正Packed Decimal、位置ずれ/長さ誤りのある金額解析の実験。
- 成果：金額表現の実験パッケージ、バイト解釈表、パーサー、不正データ検出方針。
- 受け入れ確認：S9(11)V99 COMP-3の13桁と一般的な7バイト保存を説明できる。実際の結果は固定した環境に従う。ファイルの生バイトを文字列と誤認しない。

### 04 複雑なデータ構造（5時間）

- 04.1 REDEFINES、66 RENAMES、OCCURS、INDEXED BY、OCCURS DEPENDING ON。
- 04.2 Copybook/COPY REPLACING、REFERENCE MODIFICATION、レイアウトバージョンとオフセット。
- 04.3 拡張業務レコードを読む：顧客、口座、住所、リスク、限度額、連絡先、監査フィールド。
- 成果：名前付きフィールド150以上のレコード、レイアウト一覧、フィールド位置の演習。
- 受け入れ確認：フィールド一覧の長さとコンパイラの実測値が一致する。1つのフィールドを変更すると後続のどのフィールドが移動するかを特定できる。

### 05 プログラム制御とデータクレンジング（4時間）

- 05.1 IF/EVALUATE、段落/インライン/UNTIL/VARYINGのPERFORM、スコープ、後続段落への落下。
- 05.2 SEARCH/SEARCH ALLの整列前提。STRING/UNSTRING/INSPECT、INITIALIZE。
- 05.3 顧客状態の正規化、必須項目検証、金額範囲、拒否理由の分類。
- 成果：再利用可能な検証ロジック、拒否コード一覧、正常/異常のクレンジング結果。
- 受け入れ確認：業務拒否とシステム失敗を区別できる。拒否コードごとに最小fixtureがある。

### 06 ファイル処理（6時間）

- 06.1 SELECT/FD/SD、OPEN/READ/WRITE/CLOSE、FILE STATUS、EOF。
- 06.2 固定長バイトレコードとLINE SEQUENTIALの違い。改行を論理レコード長に含めず、長さ異常を検出。
- 06.3 欠落/空ファイル、短い行、長い行、不正な数字、ID重複、未知の状態、入力コントロール合計。
- 06.4 相対/索引ファイル、REWRITE/DELETE、ロックの実験と適用範囲。
- 成果：検証と変換のプログラム、有効/拒否出力、ファイル状態ログ。
- 受け入れ確認：読込件数=受付件数+拒否件数。空ファイルを許すかは契約で決める。失敗時に正式な成果物を公開しない。

### 07 エンタープライズBatchの中核アルゴリズム（12時間）

- 07.1 SORT作業ファイル、SD、INPUT/OUTPUT PROCEDURE。ソートの検証と一時領域の失敗。
- 07.2 整列済みストリームをMERGE。ソートキー、同一キーの順序、重複キーの契約。
- 07.3 Boss L1：Master/Transactionの1対1順編成突合。3種類の出力と両側EOFの組み合わせ。
- 07.4 Boss L2：1対多。口座単位のKey Break、取引順の累計、返金/取消、残高オーバーフロー。
- 07.5 Boss L3：Master、Transaction、DB Snapshot、Previous Dayの複数ストリーム。デカルト積を既定にせず、業務上の多対多を定義。
- 07.6 Boss L4：150以上のフィールドを1つずつ比較し、フィールド名、オフセット、旧/新値、比較ルールを出力。
- 成果：突合設計、状態遷移表、実装、分類ファイル、差分レポート、保存則の証跡。
- 受け入れ確認：DB/Python/全件配列で代替しない。データ量が増えてもメモリを上限内に保つ。重複キー/逆順/空ファイル/EOF/オーバーフローをすべて扱う。

### 08 COBOL + DB（6時間）

- 08.1 P1で検証済みのEmbedded SQLツールチェーン、Host/Indicator Variable、NULL、SQLCODE/SQLSTATE。
- 08.2 DECLARE/OPEN/FETCH/CLOSE Cursor。データなしとエラーを区別。
- 08.3 営業日単位で顧客Snapshotを抽出し、上流ファイルと突合して差分を出力。
- 08.4 更新、一意制約、COMMIT/ROLLBACK、接続中断、トランザクション再試行。
- 成果：DB初期化/seedデータ、Cursor抽出、更新Batch、トランザクションの証跡。
- 受け入れ確認：実DBを使った実験。同じ業務日で重複更新しない。コミット後のクラッシュに復旧手順がある。DB固有のエラーを明記。

### 09 モジュール化プログラム（4時間）

- 09.1 CALL/LINKAGE/USING、BY REFERENCE/CONTENT/VALUE、RETURNING、GOBACK。
- 09.2 WORKING-STORAGEのライフサイクル、共通Copybook、パラメーターの長さ/バージョン、インターフェース不一致。
- 09.3 金額計算、顧客検証、ログの各モジュールを切り出す。呼び出し側と被呼び出し側の双方について影響調査。
- 成果：インターフェース仕様、共通モジュール、呼び出し実験。
- 受け入れ確認：複数回呼び出しても結果が正しい。暗黙の共有状態がない。失敗状態を呼び出し元へ正しく返す。

### 10 Shell / JCL / Scheduler（9時間）

- 10.1 Bashパラメーター、環境変数、設定の優先順位、営業日、パス、一時ディレクトリ。POSIX shとの違い。
- 10.2 RC=0/4/8/12、pipefail、JOB依存関係、Warningを許可する方針。
- 10.3 ロック、入力Snapshot、チェックサム、ログ、アトミック公開、Manifest。
- 10.4 全体再実行、段階復旧、DBコミット後の公開失敗、取引重複と冪等性。
- 10.5 JCL/JP1などの例を読み、ローカルのJOB Flowに対応付ける。未検証のプラットフォームで動くと主張しない。
- 成果：夜間JOB一式、依存関係表、復旧チェックリスト、運用手順書。
- 受け入れ確認：前段が失敗したら後続は実行しない。並行起動を拒否する。同じ営業日の再実行で二重引き落としがない。4つのクラッシュ境界から復旧できる。

### 11 障害調査と保守（9時間）

- 11.1 Scheduler状態、JOB Log、RC、入力一覧からタイムラインを作り、元の証跡を保持する。
- 11.2 不正な数字、レコード位置ずれ、ランタイム異常。まず再現し、その後に根本原因を特定する。
- 11.3 DB一意制約、0バイトファイル、Master逆順、一時領域/権限の失敗。
- 11.4 RC=0でも残高やコントロール合計が誤っているケース。業務上の正しさを調査する。
- 11.5 顧客区分を1桁から2桁に拡張する。先に影響調査を提出してから変更と回帰確認を行う。
- 成果：影響調査書、修正対象一覧、修正方針、Test Case、Evidence、障害レビュー。
- 受け入れ確認：ソース/データ/ログの証拠で根本原因を説明する。元入力を書き換えて問題を隠さない。ロールバックと再実行の境界を説明する。

### 12 統合プロジェクトと卒業判定（9時間）

- 12.1 未知のバージョンの銀行システムと設計書を受け取り、構成と依存関係を復元する。
- 12.2 顧客区分の拡張を完了し、正常日、異常日、再実行日を扱う。
- 12.3 夜間フロー全体を実行する：受信→検証→ソート→突合→更新→レポート→公開。
- 12.4 根本原因を伏せた障害現場を調査し、証跡と復旧操作を提出する。
- 成果：システム一式、設計/運用文書、保守変更パッケージ、テスト/障害証跡。
- 受け入れ確認：制作基準の必須ゲートを満たし、上下流を損なわなかった理由を説明できる。

## 課程全体に通じるプラグイン演習

01/06では固定形式ルーラーと診断を使用します。02～04ではフィールドへのジャンプ、Copybookプレビュー、レコードレイアウトの見積もりを行います。07ではアウトラインと段落ジャンプで2つの読込ポインターを追跡します。09では呼び出しインターフェースを再確認します。11/12ではナビゲーションを使って影響調査を行います。各課題に端末での代替手順があり、プラグインがなくても課程を進められます。

## 学習チェックポイント

モジュール03：データ表現の確認。モジュール06：ファイル契約の確認。モジュール07：最初のBoss。モジュール10：JOB運用の確認。モジュール11：保守プロセスの確認。モジュール12：卒業。前提確認に合格していない場合は該当する演習を補い、業務上の証跡の代わりに構文の暗記で済ませてはいけません。
