# 第 01 课：Hello COBOL

> 状态：第 01 课教学草稿；目录与 5 行最小源码例外已获用户确认，课程验收尚未完成。示例按 GnuCOBOL 官方手册和仓库固定格式编写。

## 一、课程目标

学完本课后，你可以：

- 用 `cobc` 把一个 `.cob` 源文件编译成 Linux 可执行程序并运行它。
- 在最小程序中认出程序标识、执行入口、输出语句和正常结束语句。
- 解释程序没有输入数据时，为什么不需要 `DATA DIVISION`。
- 根据实际终端输出判断编译步骤和运行步骤是否成功。

## 二、知识讲解

### 一个 COBOL 程序解决什么问题

COBOL 程序常用于按明确记录和规则处理业务数据。第一课先只输出一条问候语，目的是建立从源文件到可执行文件的完整路径；后面的课再逐步引入字段、运算、条件、文件和数据库。真实批处理也需要这个最小闭环：编译器能找到程序入口，运行时能执行它，操作人员能观察输出。

### 本课用到的结构

- `IDENTIFICATION DIVISION` 标识源文件里的程序单元。
- `PROGRAM-ID` 为程序单元声明名称。本例叫 `HELLO01`。
- `PROCEDURE DIVISION` 开始可执行过程。
- `DISPLAY` 把字面量文本写到标准输出；这里没有读文件或数据库。
- `STOP RUN` 结束当前 COBOL run unit。本例到此正常退出。

本例没有 `DATA DIVISION`，因为没有定义或保存数据项。随着课程加入字段，我们会在需要时再添加数据声明。

### 与 Java / Python 的对应关系

可以把 `PROGRAM-ID` 粗略类比为 Java 类名或 Python 模块名，把 `DISPLAY` 的用途类比为 `System.out.println(...)` 或 `print(...)`。这只是用途上的类比：COBOL 的 Division 是源程序结构，不能直接等同于 Java 类或 Python 函数。

### 固定格式和常见误区

本课程的源文件使用固定格式。代码从第 8 列起；Division 名称位于 Area A，执行语句位于 Area B；有效程序文本不能越过第 72 列。不要把自由格式代码的左对齐习惯直接套进来。

常见误区：

- `cobc` 成功编译只说明生成步骤成功；程序输出要在运行可执行文件后才会出现。
- 源文件名和 `PROGRAM-ID` 是不同概念。`-o` 指定可执行文件名。
- 字符串里的逗号和感叹号是普通输出字符，不是 COBOL 语句分隔符。
- 没有输入数据的程序无需用 `ACCEPT`、字段声明或文件声明；这些会在后续课学习。

## 四、逐行解析

| 源码行 | 作用 | 运行时变化 |
|---|---|---|
| `IDENTIFICATION DIVISION.` | 开始程序身份声明区 | 编译阶段据此解析后续程序声明；不产生业务输出 |
| `PROGRAM-ID. HELLO01.` | 给程序单元命名 | 编译器将此程序标识纳入生成的可执行程序 |
| `PROCEDURE DIVISION.` | 声明执行部分开始 | 运行时从这里进入程序过程 |
| `DISPLAY "Hello, COBOL!".` | 将字面量写到标准输出 | 终端收到一行 `Hello, COBOL!`；本例未定义业务字段 |
| `STOP RUN.` | 正常结束 COBOL run unit | 程序返回操作系统；没有后续 COBOL 语句执行 |

这里“内存变化”非常有限：程序没有用户定义的数据项，也没有改变余额或记录；编译器/运行时仍会使用实现自身的运行时状态。

## 五、运行结果

本课不读取输入文件、命令行参数或数据库记录。

从本课目录执行：

```sh
mkdir -p build
cobc -fsyntax-only lesson_01.cob
cobc -x -Wall -o build/lesson_01 lesson_01.cob
./build/lesson_01
```

运行输出：

```text
Hello, COBOL!
```

`cobc -fsyntax-only` 只检查语法，不生成可执行文件；`-x` 要求 GnuCOBOL 生成可执行程序；`-o` 指定输出路径。若编译失败，先保留完整诊断，再检查固定格式列位置和标点。

本工作区实测时，程序退出码为 0 且标准输出与上面一致；该主机还向标准错误输出 `Warning: program compiled against libxml 212 using older 209`。这是本次运行观察到的环境信息，不是程序问候文本；其具体触发组件尚未定位。

## 八、企业实战补充

在银行、保险、证券和制造业的批处理系统里，最小程序入口通常会逐渐承担初始化、处理、汇总和结束职责。上线作业的 shell 或调度器负责启动可执行文件、收集标准输出/错误输出和解释进程返回码。本课只验证源代码能编译并输出；它尚未读取业务数据、核对金额，也不代表已具备生产批次的错误处理能力。
