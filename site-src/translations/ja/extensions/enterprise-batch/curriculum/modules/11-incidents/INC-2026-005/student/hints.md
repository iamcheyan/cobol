# INC-2026-005 ヒント階層（順に読み、先の層へ飛ばないでください）

## 第1層：どの種類の失敗か？

- 失敗は JOB003、RC12 です。コースの規約では、RC12 は権限、ディスク、一時領域、子プロセスの予期しない終了などのシステム／環境異常を示し、業務上の拒否ではありません。

## 第2層：ノードに必要なリソースは？

- `scene/source/job003-sort.sh` を読んでください。親ディレクトリの下に `mktemp -d` でソート用作業領域を作り、その中に候補ファイルを書き込みます。失敗メッセージはどのリソースを指していますか？

## 第3層：再現の証拠

- 再現スクリプトは、必ず失敗する `mktemp` を PATH に配置して現場を再現します。
- `scene/logs/nightly.log` のエラー行と照合し、失敗を引き起こした箇所を確認してください。

## 第4層：失敗後の現場の完全性

- 失敗後に一時ディレクトリは残っていますか？`publish/<run_id>` は作成されていますか？営業日ロックは解放されていますか？各項目でコマンドと結果を示し、「失敗時に公開しない、ロックを残さない」ことを説明してください。

## 第5層：復旧と再発防止

- 復旧：一時領域／権限を修復する（または TMPDIR を変更する）とともに、新しい run_id で再実行します。失敗したディレクトリを再利用できない理由も説明してください。
- 再発防止：JOB の入口でリソース（ディスク使用率、書き込み可能性）を事前確認し、一時ディレクトリを集約し、失敗時の後始末とアラートを行います。
