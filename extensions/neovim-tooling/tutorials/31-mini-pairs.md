# 自动配对：mini.pairs

输入 `(` 自动补 `)`，输入 `"` 自动补 `"`，这是编辑器的基本礼貌。mini.pairs 做的就是这件事，加上一些**避免烦人的判断**。

---

## 1. 它解决什么问题

| 场景 | 没有自动配对 | 有 mini.pairs |
|---|---|---|
| 写 `(IF ...)` | 输完 `(` 还要输 `)` | 只输 `(` |
| 写字符串 | 容易漏一边引号 | 自动补全 |
| 光标已在 `)` 前 | 再输 `)` 变成 `))` | **跳过**（`skip_unbalanced`） |

## 2. 你的配置

`lua/plugins/mini-pairs.lua`：

| 选项 | 值 | 含义 |
|---|---|---|
| `modes.insert` | `true` | 插入模式启用 |
| `modes.command` | `true` | 命令行模式启用 |
| `modes.terminal` | `false` | 终端模式关闭 |
| `skip_next` | `%w%%%'%[%"%.%`%$` | 下一个字符是这些时**不自动配对** |
| `skip_ts` | `{ "string" }` | 在字符串节点内不配对 |
| `skip_unbalanced` | `true` | 右括号更多时跳过 |
| `markdown` | `true` | 优化 Markdown 代码块 |

### `skip_next` 是核心

```lua
skip_next = [=[[%w%%%'%[%"%.%`%$]]=],
```

含义：如果光标**后面**紧跟着以下字符，就不自动补右半边：

| 字符 | 例子 | 为什么不补 |
|---|---|---|
| `%w` | `a` `1` | 你可能要写 `a)` 而不是 `(a)` |
| `%'` | `'` | 已有引号 |
| `%[` | `[` | 已有方括号 |
| `%"`` | `"` | 已有双引号 |
| `%.` | `.` | 可能是 `obj.method(` |
| `` %` `` | 反引号 | 已有反引号 |
| `%$` | `$` | 变量符号 |

**这避免了「你已经有一个 `)` 了，它还给你补一个」的尴尬。**

### `skip_unbalanced = true`

当右边的闭合符号**多于**开放符号时，输入开放符号会跳过自动补。

比如：`(a + b))` —— 光标在第二个 `)` 前输入 `(`，不会补 `)`，因为已经不平衡了。

### 开关

配置注册了 Snacks toggle。查看状态：

```vim
:lua =vim.g.minipairs_disable
```

`nil` 或 `false` = 启用。

## 3. 使用

### 基本

| 输入 | 得到 |
|---|---|
| `(` | `()` 光标在中间 |
| `[` | `[]` |
| `{` | `{}` |
| `"` | `""` |
| `'` | `''` |
| `` ` `` | ` `` ` |

### 光标跳过

配对后输入右半边（或按 `→`），光标会**跳过**已有的右半边，而不是插入新的。

```text
输入 (  →  ()
输入 )  →  ()|    光标跳到 ) 之后，不是 ())
```

### 删除

在 `()` 中间按退格，两边一起删（如果配置了）。

## 4. COBOL 场景

### 场景一：写 `PIC X(10)`

1. 输入 `PIC X(`
2. 自动补成 `PIC X()`
3. 输入 `10`
4. 输入 `)` → 光标跳过

**结果**：`PIC X(10)`，没有多余的括号。

### 场景二：写字符串字面量

```cobol
DISPLAY "HELLO".
```

1. 输入 `DISPLAY "`
2. 自动补成 `DISPLAY ""`
3. 输入 `HELLO`
4. 输入 `"` → 跳过
5. 输入 `.`

### 场景三：`VALUE` 子句

```cobol
01 WS-FLAG PIC X(1) VALUE "A".
```

连续用了括号和引号两种配对，全程不用手动补右半边。

### 场景四：避免干扰

COBOL 的注释行（第 7 列 `*`）里写内容时，`skip_next` 会避免多余的配对。

## 5. 练习

### 练习 1：基本配对

```sh
cd ~/development/cobol
nvim lessons/01_hello-cobol/lesson.cob
```

1. 进入插入模式
2. 输入 `(`
3. 观察

**验收**：变成 `()`，光标在中间。

### 练习 2：跳过已有右半边

1. 输入 `(`
2. 再输入 `)`
3. 观察

**验收**：光标跳到 `)` 之后，**不是** `())`。

### 练习 3：`skip_next` 生效

1. 在一行末尾已有 `)` 的地方输入 `(`
2. 观察

**验收**：不自动补 `)`（因为下一个字符是字母或已有符号）。

### 练习 4：写 `PIC` 子句

1. 找一行 `PIC X(10)`
2. 删掉重新输入

**验收**：只输 `(` 就得到 `()`，输完内容后输 `)` 能跳过。

### 练习 5：命令行模式

1. 按 `:` 进入命令行
2. 输入一个 `(`

**验收**：也自动配对（`modes.command = true`）。

### 练习 6：确认终端关闭

1. 打开终端（`:terminal`）
2. 输入 `(`

**验收**：**不配对**（`modes.terminal = false`）。

## 6. 踩坑

### 输入 `(` 没补 `)`

检查 `skip_next`：光标后面是不是跟着字母、引号、`.` 等。这是配置有意的。

### 在字符串里不配对

`skip_ts = { "string" }`：在 Treesitter 识别的字符串节点内不配对。**COBOL 没有 parser**，所以这个规则对 COBOL 不生效——但引号配对用 `skip_next` 也能覆盖大部分情况。

### Markdown 里行为不同

`markdown = true` 会特殊处理代码块。在 Markdown 里写 ``` `code` ``` 时配对行为有优化。

### 想完全关掉

```vim
:lua vim.g.minipairs_disable = true
```

或删掉插件配置。

### 和 blink.cmp 冲突

补全菜单弹出时按 `(`，可能被补全占用。**行为以实际测试为准**——两者都监听插入模式按键。

## 8. 边界

- 本篇配置来自 `lua/plugins/mini-pairs.lua`：插入+命令行启用，终端关闭，7 类 `skip_next` 字符。
- **`skip_next` 是刻意的行为**：光标后跟字母/引号/`.`/`$` 等时不自动补右半边。这不是 bug。
- `skip_ts = { "string" }` 依赖 Treesitter，**COBOL 无 parser 时该规则不生效**。
- 与 blink.cmp 共存时的按键归属以实际测试为准。
