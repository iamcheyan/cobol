# Markdown のレンダリング：markview.nvim

Markdown ファイルは通常、ソースのまま表示されます。`# 見出し` は `#` の付いた一行のテキストで、表は生の `|` パイプ文字です。

markview は最終的な表示に近い形にレンダリングします。見出しは大きくなり、表は整列し、コードブロックには背景が付き、チェックボックスをクリックできます。

---

## 1. 解決する問題

| 要件 | ソース表示 | markview |
|---|---|---|
| 見出しの階層を見る | `#` の数を数える | 文字サイズと色で区別 |
| 表を見る | `|` を目で追って整列する | 表としてレンダリング |
| コードブロックを見る | 等幅フォントのみ | 背景と言語ラベル付き |
| タスクリストを見る | `- [ ]` のテキスト | クリックできるチェックボックス |

## 2. 設定

`lua/plugins/markview.lua`：

| オプション | 値 | 意味 |
|---|---|---|
| `lazy` | `false` | すぐに読み込む（LazyFile を待たない） |
| `ft` | `markdown` など4種類 | Markdown 関連ファイルでのみ有効 |
| `preview.enable` | `true` | レンダリングを有効化 |
| `icon_provider` | `internal` | 内蔵アイコンを使う（追加のアイコンライブラリ不要） |

設定コメントには、`lazy = false` にしている理由が説明されています。

```lua
-- Markview manages its own preview attachment; keep it available after the
-- colorscheme has initialized so Markdown opens with rendered elements.
```

markview はプレビューのアタッチ時期を独自に管理します。配色の初期化後も利用できるようにしておくことで、Markdown を開いたときにレンダリング済みの要素を表示できます。

### 有効なファイルタイプ

```lua
ft = { "markdown", "markdown.mdx", "quarto", "rmd" },
```

### プレビューの切り替え

| キー | 動作 |
|---|---|
| `<leader>um` | Markdown のレンダリングを切り替える |

**Markdown バッファでのみ有効です**（設定の `ft` で制限されています）。

## 3. レンダリング対象

| 要素 | レンダリング結果 |
|---|---|
| 見出し `#` `##` | サイズと色を変えて表示 |
| 表 | 列が揃った表 |
| コードブロック ``` | 背景ブロックとプログラミング言語のラベル |
| 引用 `>` | 左側に縦線 |
| リスト `-` | 箇条書き |
| タスクリスト `- [ ]` | クリックできるチェックボックス |
| リンク | 色で区別 |
| 太字／斜体 | 太字／斜体で表示 |

## 4. COBOL コースでの実用性

このリポジトリには大量の Markdown があります。32 レッスンの README、`extensions/` のチュートリアル、そしてこのチュートリアル自体です。

### 場面1：コースのドキュメントを読む

```sh
cd ~/development/cobol
nvim lessons/17_fixed-length-files/README.md
```

レンダリングすると：
- 見出しの階層が分かりやすくなる
- 表（オフセット表など）の列が揃い、普通の表として表示される
- コードブロックに背景が付く

**ソースをそのまま読むよりずっと読みやすくなります**。特に表の多いレッスンでは効果的です（第17レッスンの200バイトオフセット表など）。

### 場面2：ドキュメントのレイアウトを確認する

README を書くときにレンダリングを有効にしておけば、表の整列や見出しの階層が正しいかすぐ分かります。

編集後に `<leader>um` でソース表示に戻し、構文エラーがないか確認します。

### 場面3：表を確認する

第17レッスンのオフセット表は14行あります。表としてレンダリングすれば、列が揃っていない行をすぐ見つけられます。

## 5. 練習

### 練習1：レンダリング表示を開く

```sh
cd ~/development/cobol
nvim lessons/17_fixed-length-files/README.md
```

**合格条件**：見出しに階層スタイルが付き、表が表としてレンダリングされ、コードブロックに背景が付く。

### 練習2：表示を切り替える

1. `<leader>um`

**合格条件**：ソース表示に戻り（`#` と `|` が見える）、もう一度押すとレンダリング表示に戻る。

### 練習3：表を見る

1. README のオフセット表を見つける
2. レンダリング後の列の整列を確認する

**合格条件**：表の列が揃い、ソース表示より読みやすい。

### 練習4：Markdown でのみ有効なことを確認する

1. `.cob` ファイルを開く
2. `<leader>um` を押す

**合格条件**：**何も起きない**（`ft` により Markdown でのみキーが割り当てられています）。

### 練習5：タスクリストを見る

1. `- [ ]` を含む Markdown を開く（リポジトリ内にあれば）
2. レンダリングを確認する

**合格条件**：チェックボックス風に表示される（設定によってはクリックできます）。

## 6. つまずいたとき

### Markdown を開いてもレンダリングされない

確認項目：
1. ファイルタイプが `markdown` か：`set ft?`
2. markview が読み込まれているか：`:Lazy` で状態を見る

設定は `lazy = false` なので、起動後は利用できるはずです。

### `<leader>um` が反応しない

キーは Markdown バッファにのみ割り当てられています（`ft` による制限）。`.cob` 内では使えません。

### レンダリング後にコードが読みにくい

コードブロックは等幅フォントで表示されますが、テーマのコントラストが低いと薄く見える場合があります。確認するには：

```vim
:hi MarkviewCode
```

### 編集中にカーソル位置がおかしく見える

レンダリング中もカーソルはソース文字上にあります。表示だけが装飾されます。**編集の動作は変わりません**。`x`、`dd`、挿入などは通常どおりです。

### 一時的にソースを見たい

`<leader>um` で切り替えます。または `:set ft=` でファイルタイプを解除できます（ハイライトも失われるため非推奨）。

### 大きなファイルで重い

このチュートリアルのように Markdown が長いと、レンダリングに少し時間がかかります。必要なら無効にしてください。

## 7. 他のプラグインとの関係

| 要件 | ツール |
|---|---|
| Markdown のレンダリング | markview（`<leader>um`） |
| Markdown の構造編集 | 通常の Vim 操作 |
| アウトライン移動 | aerial（`<leader>cs`、markdown backend 対応） |
| Markdown のフォーマット | LSP または外部の整形ツール |

**markview が変更するのは表示だけで、ファイルの内容は変更しません。** 無効にしてもファイルは元のままです。

## 9. 適用範囲

- このページの設定は `lua/plugins/markview.nvim` に基づきます：`lazy = false`、4種類の `ft`、`icon_provider = "internal"`。
- `<leader>um` は **Markdown バッファでのみ有効**です。
- markview は表示だけを変え、ファイル内容は変更しません。レンダリングを無効にすれば元の表示に戻ります。
- COBOL の開発自体には必要ありませんが、**コースのドキュメントを読むときに便利**です。このリポジトリには30以上の Markdown ファイルがあります。
