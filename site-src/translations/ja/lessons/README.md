# コースナビゲーション

各レッスンには、`lesson.cob`、`README.md`、`exercise.md`、`answer.md` に加え、必要なスクリプト、Copybook、データフィクスチャ、期待される結果が含まれます。解答付きの改変練習と、解答のない応用練習は `exercise.md` で分けています。解答ファイルが扱うのは、解答付きの練習だけです。

- [全32課のコース目録](DIRECTORY.md)：6段階それぞれの目標、前提知識、所要時間の目安、ソース成果物を確認できます。
- [第01課：Hello COBOL](01_hello-cobol/README.md)：固定形式プログラムをコンパイルし、最初の `DISPLAY` を実行します。

旧版のトピック、企業向けバッチ処理、Neovim ワークフローを続けて学ぶ場合は、課番号から[拡張コース一覧](../extensions/README.md)を参照してください。拡張教材によって本コースの前提順序が変わることはありません。

## 全レッスン共通の規約

- **言語**：README とソースコメントは中国語です。プログラムが出力する業務文言は、リポジトリで既に使われている日本語に従います（`POSTED`、`SQLSTATE` など一部のインターフェース表示は英語のままです）。各レッスンの README には出力ラベルの中国語対照表があります。実際の出力と README の説明を基準に、プログラムの動作を判断してください。
- **コンパイラと方言**：GnuCOBOL 3.2.x のデフォルト方言を使用します。`COMP-3` や `FUNCTION TRIM` など本コースで使う拡張は厳密な COBOL 85 ではサポートされないため、`-std=cobol85` は**付けないでください**。
- **ソース形式**：固定形式です。7桁目は標識領域（`*` はコメント）、Area A は8桁目から始まります（Division、`FD`/`SD`、レベル01、段落名）。このリポジトリではレベル05を11桁目、文を12桁目から置きます。有効なプログラム本文は72桁目を越えてはいけません。ツールチェーンはこの境界を**バイト数**で判定するため、中国語や日本語を含む行はより早く境界に達します。
- **ビルドとクリーンアップ**：`mkdir -p build` で `build/` を作成し、`cobc` で実行ファイルをそこに出力します（複数プログラムを扱う課では `copybooks/` も `-I` のパスに指定します）。`build/` は `.gitignore` 対象です。`rm -rf build` でまとめて削除できます。業務データを読み書きする課（16、22、26、27）は、リポジトリのフィクスチャを書き換えないよう、入力のコピーを `build/` に置いて実行します。
- **データベース課（29–32）**：GixSQL 1.0.20b と SQLite を使用します。第29課の `install-toolchain.sh` はツールチェーンを `build/toolchain/` に展開します（システムパッケージは変更せず、バイナリもリポジトリにコミットしません）。第30～32課は既定でこれを再利用します。ツールチェーンがない場合、各課の `build.sh check` はエラーになります。**模擬 SQL で代用しないでください**。
- **全体チェック**：リポジトリのルートで `make course-check` を実行すると、全32課の成果物を確認し、第01～28課の構文をチェックして、第01課の動作スモークテストを実行します。`make course-check-sql` は第29～32課のプリコンパイラーチェックと第32課のエンドツーエンドシナリオを対象にします。

具体的なコマンド、期待される出力、未検証の範囲は各レッスンの README を参照してください。実行ファイル、ログ、実行時出力をソースファイルとして扱わないでください。
