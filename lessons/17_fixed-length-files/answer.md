# 第 17 课修改练习参考答案

本答案只回答 [`exercise.md`](./exercise.md) 中的修改练习，不提供举一反三练习的答案。

## 输出 FD 改为账户号在前

改动位置：`lesson.cob` 中 `FD BALANCE-FILE` 下的 `01 FD-BALANCE-RECORD`。

改前：

```cobol
       01 FD-BALANCE-RECORD.
           05 FD-OUT-CUSTOMER-ID PIC X(8).
           05 FD-OUT-ACCOUNT-NUMBER PIC X(10).
           05 FD-OUT-BALANCE PIC 9(7)V99.
```

改后：

```cobol
       01 FD-BALANCE-RECORD.
           05 FD-OUT-ACCOUNT-NUMBER PIC X(10).
           05 FD-OUT-CUSTOMER-ID PIC X(8).
           05 FD-OUT-BALANCE PIC 9(7)V99.
```

命令行：

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_17 lesson.cob
cp accounts.dat build/
(cd build && ./lesson_17)
wc -c build/balances.dat
cmp accounts.dat build/balances.dat
rm -rf build
```

**标准输出：** 与基线完全相同，仍是 5 行。三条 `MOVE` 语句按字段名赋值，字段名没有改变，所以每条记录打印的账户号、客户号、余额数值都不变：

```text
ファイルを開きました
出力 口座番号=0001234567 顧客番号=C0001042 残高=0001000.00
出力 口座番号=0002468101 顧客番号=C0002042 残高=0000020.00
出力 口座番号=0007654321 顧客番号=C0003042 残高=0000250.75
クローズ完了 件数=03
```

**输出文件：** `wc -c build/balances.dat` 输出 `81`，即 `3 × 27`；`cmp accounts.dat build/balances.dat` 无输出且退出码为 0，说明输出与输入逐字节相同（文件内仍没有换行字节，下面分行只是查看效果）：

```text
0001234567C00010420001000000
0002468101C0002042000002000
0007654321C0003042000025075
```

对照字节位置，第 1 条的 `0001234567` 占输出字节 1–10、`C0001042` 占 11–18、`000100000` 占 19–27，与输入记录的偏移一致。

**与基线的完整差异：**

| 记录 | 基线 `balances.dat` | 改序后 `balances.dat` |
|---:|---|---|
| 1 | `C00010420001234567000100000` | `0001234567C00010420001000000` |
| 2 | `C00020420002468101000002000` | `0002468101C0002042000002000` |
| 3 | `C00030420007654321000025075` | `0007654321C0003042000025075` |
| 文件总字节数 | 81 | 81 |

**原因：** `MOVE` 按数据名赋值，与声明顺序无关；`WRITE` 按 `01` 记录内部各字段的声明顺序依次写出该记录的字节。因此改变 `05` 声明的顺序就改变了各字段在输出记录中的偏移，而每条记录的宽度仍由 `PIC` 决定为 `10 + 8 + 9 = 27` 字节，记录数和文件总字节数（`3 × 27 = 81`）都不变。

## 用列标尺核对偏移的参考答案

本答案回答 [`exercise.md`](./exercise.md) 中“用列标尺核对偏移”的三道题。

### 题目一

| 字段 | 起始列 | 结束列 | 宽度 | `:PositionRange` 输出 |
|---|---:|---:|---:|---|
| 户名 | 19 | 48 | 30 | `POSITION(19:48)` |
| 余额 | 89 | 108 | 20 | `POSITION(89:108)` |
| 预留区 | 177 | 200 | 24 | `POSITION(177:200)` |

宽度按“结束列 − 起始列 + 1”算：`48 − 19 + 1 = 30`、`108 − 89 + 1 = 20`、`200 − 177 + 1 = 24`。三个宽度与 README 偏移表的“长度”列一致，说明量的是同一批字节。

**这一步容易错的地方**：`:PositionRange` 报的是**两端都含**的闭区间，所以 `:PositionJump 48` 再减掉 `:PositionJump 19` 得到的是 29，少算了 1 列。用 `:PositionRange` 输出直接读宽度，不要自己相减。

### 题目二

1. 删除前，第 49–56 列是 `BR-TOKYO`（8 个字符）。
2. 删除第 19 列的 `T` 之后，第 49–56 列变成 `R-TOKYO2`。
3. 文件总字节数从 `600` 变成 `599`。
4. 程序**不会**因此报错。

**为什么第 2 问会变成 `R-TOKYO2`。** 删除第 19 列之后，第 19 列开始的所有字节整体左移一位。原本在 19–48 列的 30 字节户名少了一个字符，于是原本 49–56 列的 `BR-TOKYO` 向前移动到 48–55 列；第 49 列起读到的是 `R-TOKYO`（原 `BR-TOKYO` 去掉首字节 `B`），第 56 列读到的是下一条记录（第 2 条记录）的账户号首字节 `2`。

**为什么 `600 ÷ 200` 不再有意义。** 600 恰好是 200 的 3 倍，但 599 不是 200 的整数倍：`599 = 2 × 200 + 199`。也就是说文件现在只能完整读出 2 条记录，第 3 条只有 199 字节，缺 1 个字节。**这正是本课边界里说的“程序不校验总字节数”**——`READ` 读到第 3 条时能读满 199 字节，第 200 个字节位置留着上一条记录的残留数据，`AT END` 照样正常触发，程序什么都不会说。

**程序为什么不报错。** 三件事都没被检查：

- `OPEN` 只检查文件能否打开，599 字节的普通文件当然能打开；
- 每条 `READ` 都成功（前两条完整，第三条有残留填充），所以没有 `AT END` 以外的异常；
- `WRITE` 写的仍是被截断的一个字段，输出文件依然是 200 字节一条，状态 `00`。

所以退出码还是 `0`，屏幕上还是 3 行 `出力 …`，只是第 3 行的余额已经开始读错。**只有用列标尺逐列核对的人能发现。**

### 题目三

```sh
cd lessons/17_fixed-length-files
cp account-master-200.dat build/account-master-200.dat   # 若改过本课夹具，先恢复
wc -c account-master-200.dat                             # 应输出 600
cmp account-master-200.dat build/account-master-200.dat  # 与原始夹具比对
```

**需要提交：**

- 题目一的表格；
- 题目二的 4 个回答；
- `cmp` 无输出且退出码为 `0`，`wc -c` 输出 `600`。

如果 `wc -c` 输出的是 `599`，说明删掉的字符还没补回去；如果 `cmp` 报 `differ: byte 19`，说明补回去的位置不对——`cmp` 会直接告诉你第一个不同的字节偏移，这本身就是一次很好的定位练习。
