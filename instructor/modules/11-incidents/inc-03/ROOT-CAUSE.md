# inc-03 讲师根因（0 字节 / 传输截断）

## 触发条件
本营业日应交付的 `transaction.dat` 在传输/落盘中被截断为 **0 字节**；
接收清单 `MANIFEST` 仍带有**非空内容**的 SHA256。

## 根因
不是程序缺陷，而是**上游传输/落盘损坏**。JOB001 在冻结快照前先按
Manifest 校验每个声明文件的 SHA256，空文件的实际哈希与声明哈希不符，
于是以 RC12 中止——**在进入 JOB002 之前**就停止，保护下游。

## 区分“合法空文件”与“损坏文件”
- 契约允许**当日无交易**时交付**合法空文件 + 与之匹配的 Manifest**：
  此时 SHA256 匹配、JOB002 会以 RC0 通过（参见模块 10 的
  `boundary-empty-tx`）。
- 本现场是**声明的非空内容**却收到 0 字节 → 校验和不匹配 → 数据损坏，
  非合法空文件。

## 逐层提示阶梯（对应 student/hints.md）
1. 失败在 JOB001，RC12（系统）。
2. Manifest 声明了什么？实际哈希是否匹配？
3. 实际字节数 0，与声明的非空内容矛盾 → 传输/落盘损坏。
4. RC12 分类；为何在 JOB001 拦截即保护下游。
5. 恢复=重传 + 新 run_id；防再发=传输校验 + 长度/记录数哨兵。

## 误导线索
- “空文件应该走空批次逻辑”：那需要 Manifest 也声明空内容。
- “把校验和检查关掉就能跑”：掩盖了损坏事实，属篡改断言。

## 证据
- `scene/logs/JOB001.log`：`checksum mismatch for 'transaction.dat'`；
  RC=12（`scene/rc.txt`）。
- `wc -c input/transaction.dat` = 0；`sha256sum` 与 Manifest 不符。
- `scene/scheduler-status.txt`：JOB001 FAILED rc=12，JOB002+ NOT_RUN。

## 最小修复
重新从源系统接收文件并再次校验；程序侧无缺陷，无需修改。

## 恢复 / 重跑
重传成功、校验和匹配后用**新 run_id/新输出目录**重跑。

## 防再发
传输层校验、接收后文件长度与记录数哨兵、非空/非零字节告警。

## 评分点
- 判定为损坏（RC12）而非合法空文件（RC0）。
- 以字节数与校验和为证；说明 JOB001 先行的保护意义。
- 恢复使用重传 + 新 run_id。
