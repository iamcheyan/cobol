# STRING、UNSTRING、INSPECTと参照修飾

## 学習目標

区切り文字による分割、連結、DELIMITED BY SIZE、TALLYING、COUNTING、REPLACING、参照修飾、ポインタ項目。

このレッスンを終えたら、上記の用語を自分の言葉で説明し、小さなプログラムの中で該当する宣言や実行箇所を見つけられるようになりましょう。構文を暗記するだけでなく、入力、出力、状態の変化を観察してください。

## サンプルコード

[`L11.COB`](./L11.COB)を開きます。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文と実行文はArea Bに記述します。まずソースを1行ずつ読み、その後に実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/11-strings-unstring-inspect/L11.COB
cobc -x -Wall -o build/l11 extensions/legacy-workshop/lessons/11-strings-unstring-inspect/L11.COB
./build/l11
```

期待される観察内容：パイプ区切りの1行テキストを分割し、結果を連結します。

コンパイラが書式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認してください。次に、ピリオド、変数のPIC、スコープ終端文を確認します。`-Wall`は追加の警告を表示します。警告も内容を理解してから対処するか判断してください。

## 各節を理解する

1. `IDENTIFICATION DIVISION`はプログラム単位を宣言し、`PROGRAM-ID`はコンパイラが認識するプログラム名です。
2. `DATA DIVISION`はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号とPICに注目してください。
3. `PROCEDURE DIVISION`は実行の開始点です。`0000-MAIN`は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文によって処理経路が変わるか、`STOP RUN`でプロセスが終了するまで、ソースの順に実行されます。

## 変更演習

DELIMITED BY ALLに変更し、INSPECT TALLYINGを使ってWS-LINE内の区切り文字を数えます。

変更のたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つにして、変更前後の出力を記録します。

## cobol.nvimで学ぶ

UNSTRINGを使って書式診断を練習し、プラグインのアウトラインからフィールドや処理段落をすばやく確認します。

プラグインが応答しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に`cobc --version`を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかの判断基準となるのは、GNUCOBOLによる実際のコンパイル結果です。
