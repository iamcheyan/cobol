# 第 14 課演習：口座と取引の照合

この課では、第 09～14 課で学んだ内容だけを使います。階層レコード、`REDEFINES`、`OCCURS` テーブル、`INDEXED BY` インデックス、`SEARCH ALL`、`EVALUATE`、`IF`、`PERFORM`、`DISPLAY` を使用します。データはすべてメモリ内にあります。

## 変更演習（参考解答は `answer.md`）

1. 4件目の振込先口座を `0009999999` から、既存の口座 `0002468101` に変更します。プログラムを実行し、振込が成功すること、振込元と振込先の残高が変わること、拒否件数がゼロであることを確認してください。
2. 元のソースから始め、4件目の振込先を `0001234567`、金額を `100.00` にします。振込元の残高不足で拒否され、両口座の残高が変わらないことを確認してください。

各演習は元の `lesson.cob` から個別に始め、変更を重ねないでください。変更後は次を実行します。

```sh
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_14 lesson.cob
./build/lesson_14
```

「成功」の行だけを見るのではなく、取引結果、3口座すべての最終残高、集計件数を確認してください。参考解答は `answer.md` を参照してください。

## 学んだことを応用する（解答なし）

主テーブルに口座を1件追加し、取引テーブルにはその口座への入金と、存在しない口座を振込先にする振込を1件ずつ追加します。すべてのテーブル上限、ロード文、バッチ処理範囲を更新してください。

ソース全体、コンパイル／実行コマンド、実際の出力、終了コードを提出してください。`SEARCH ALL` の前提を守るために口座キーの順序をどう保つか、振込失敗時に両方の残高が変わらない理由、この課の方法がトランザクション保証ではなく文の順序による保護にすぎない理由を説明してください。解答はありません。メモリ内データだけを使い、ファイルやデータベースは追加しません。
