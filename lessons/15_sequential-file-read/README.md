# 第 15 课：顺序读取每日交易文本

银行每天把当日交易以文本文件送进批处理目录，程序要自己打开文件、按送达顺序逐行读完，并把“读完了”和“文件根本打不开”区分成两种结果。本课用四行 [`transactions.txt`](./transactions.txt) 建立这条输入流程：用 `SELECT` 和 `FD` 把程序连接到真实文件，用 `OPEN INPUT` 检查打开结果，用 `READ` 配合 `AT END` 读完全部记录，最后在标准输出报告实际读到的条数。

## 为什么现在学

前 09–14 课已经能把记录组成层级结构、用 `REDEFINES` 解释同一段字节、用 `OCCURS` 表格加 `SEARCH ALL` 按键查找；但那些“记录”全部写死在源码里。真实批处理的第一步是让数据从程序外面进来：调度器把文件放进工作目录，程序打开它、按行读完，并且在两种不同结局发生时报告准确的那一种。这里有三处新东西：文件怎样与 COBOL 数据项关联、一条“行”的物理边界在哪里结束、以及“读到文件尾”为什么不是错误。

## 本课完成后的能力与边界

学完本课后，你可以：

- 用 `FILE-CONTROL` 的 `SELECT ... ASSIGN TO "transactions.txt"` 把 COBOL 文件接到**运行时当前工作目录**下的真实文本文件，并用 `FILE STATUS IS` 保存每次 I/O 的状态码。
- 用 `ORGANIZATION IS LINE SEQUENTIAL` 加 `FD` 的 `01 FD-TRANSACTION-RECORD PIC X(100)` 描述行顺序文本，说明行长可变、FD 记录区固定 100 字符、短行右侧补空格、超过 100 字符的行被拆成多条记录。
- 用 `PERFORM UNTIL` 加 `READ ... AT END` 读完全部记录，并说明 EOF 是正常结束、EOF 分支不增加记录数。
- 从标准输出核对三个结果：四行夹具报告 `EOF=はい レコード数=04`；空文件报告 `00`；文件缺失报告 `オープン=FAILED STATUS=35` 并以退出码 `1` 结束。
- 用内容比对证明本程序只读输入，不创建、不覆盖任何数据文件。

边界：程序把整行当作一段文本，只计数和显示，不按竖线拆字段、不校验日期/类型码/账户号/金额，也不拒绝任何记录；这些判断要等[第 18 课](../18_csv-processing/README.md)和[第 26 课](../26_error-handling/README.md)。文件缺失时它在 `READ` 之前就结束，因此不会执行 `CLOSE`，也没有日志或资源回收。记录计数域只有两位，超过 99 条会回绕，本课不处理这个上限。

## 知识讲解

### 文件输入与内存数据有什么不同

内存里的 `OCCURS` 表格在你写源码时就确定了条数和内容；文件里的记录条数、长度和内容都由程序外部决定，程序只能在运行时一条条取。因此文件课多了两类必须处理的事实：**条数不确定**（可能 0 条，也可能很多条）和**结果不确定**（可能打不开）。本课用 `PERFORM UNTIL` 循环把“读到没有”变成循环条件，用 `FILE STATUS` 把“能不能打开”变成可判断的状态码。

### 行顺序组织与定长记录的差别

`ORGANIZATION IS LINE SEQUENTIAL` 表示文件按**行**组织：一行的结束符（Linux 上的换行符）就是记录边界，行长可以各不相同。它和“定长记录文件”（每条记录固定 N 字节、没有换行符）是两种不同的输入：

- 行顺序：记录边界由换行符决定，行长可变；本课处理这种。
- 定长：记录边界由固定字节数决定，没有换行符；记录宽度必须由接口约定，[第 17 课](../17_fixed-length-files/README.md)处理这种。

`FD` 下面的 `01 FD-TRANSACTION-RECORD PIC X(100)` 不是“每行 100 字符”，而是**读入缓冲区的大小**：每次成功的 `READ` 把一整行放进这 100 字节，不足的部分右侧用空格补齐；超过 100 字符的行放不下，会被拆成连续的 100 字符记录读出。所以 `FUNCTION TRIM(... TRAILING)` 只负责显示时去掉补齐的空格，它不改变记录区，也不代表文件里真的存了空格。

### 文件状态码和 EOF 不是一回事

`FILE STATUS IS WS-FILE-STATUS` 让每次文件操作之后的状态码落在 `WS-FILE-STATUS` 里。本课只检查 `OPEN` 和 `CLOSE` 之后的值：

| 操作 | 状态码 | 含义 |
|---|---|---|
| `OPEN INPUT` 成功 | `00` | 文件已打开，可以 `READ` |
| `OPEN INPUT` 文件缺失 | `35` | 本课工具链实测值，程序据此报告 `オープン=FAILED` 并退出码 `1` |
| `CLOSE` 成功 | `00` | 文件已关闭 |

EOF 不走状态码分支，而是由 `READ` 的 `AT END` 分支表达：读完最后一条后的那次 `READ` 找不到下一行，执行 `AT END`，把 `WS-END-OF-FILE` 置为 `"Y"`，循环随之结束。这说明为什么 EOF 不是错误——它是正常读完的标志；真正的错误是打不开文件。作为参考，本工具链在 EOF 时也会把文件状态置为 `10`（用临时探针程序观察，本课源码不读取该值）。

## 输入与规则

**输入夹具**：[`transactions.txt`](./transactions.txt)，竖线分隔的可见文本，本课不解析字段。

| 项 | 值 |
|---|---|
| 文件名与位置 | `transactions.txt`，运行时当前工作目录（硬编码在 `ASSIGN TO`） |
| 组织 | `LINE SEQUENTIAL`，一行一条记录，行结束符为换行符 |
| 行数 | 4 |
| 各行可见字符数 | 43、53、42、53（合计 191） |
| 文件总字节数 | 195（191 个可见字符 + 4 个换行符） |
| 分隔字段数 | 每行 5 或 6 段（转账行多一个收款账户），本课不检查段数 |
| FD 记录区 | `PIC X(100)`；短行右侧补空格至 100 字节 |
| 排序与唯一性前提 | 无：程序按物理顺序读出，既不要求有序也不查重 |

夹具第一行的原始内容（竖线只作可读分隔，本课不解析）：

```text
DAY-20261013|TXN-000001|D|0001234567|125.50
```

**由代码校验的条件**（源码里真的有对应分支）：

- `OPEN INPUT` 之后 `WS-FILE-STATUS` 是否为 `00`；不是则打印状态、置退出码 `1`、`STOP RUN`，不执行任何 `READ`。
- 每次 `READ` 是否到达文件尾（`AT END` / `NOT AT END`）。
- `CLOSE` 之后状态是否为 `00`，否则打印 `クローズ=FAILED` 并置退出码 `1`。

**仅由夹具或上游保证的条件**（本课不校验）：

- 文件存在、可读、是文本行，且每行不超过 100 字符——本课把这几项当作上游前提，不做校验。
- 每行字段个数、日期、类型码、账户号、金额的业务合法性：本课一概不检查（连段数都不数），夹具内容只作演示数据；字段解析与校验留给第 18、26 课。

**边界与故障政策**：

- **空输入**：空文件是合法输入，能成功打开，第一次 `READ` 立即 `AT END`，记录数报告 `00`，退出码 `0`。
- **空行**：文件中间的空行也是一条记录——会被 `READ` 成功读出、计数加一，`TRIM` 之后显示为空的记录行。
- **文件末尾没有换行符**：最后一行仍会被读出（行顺序读取不依赖文件以换行符结束）。
- **输入过长**：超过 100 字符的行会被拆成多条记录，总记录数因此大于物理行数；最大行长必须由上游约定。
- **打开失败**：报告真实状态码并用退出码 `1` 结束；本课不关闭文件、不写日志。

## 源码阅读路径

按“状态什么时候变”来读，完整源码见 [`lesson.cob`](./lesson.cob)。

| 位置 | 职责 | 关键语句 | 状态变化 |
|---|---|---|---|
| `FILE-CONTROL` 的 `SELECT TRANSACTION-FILE` | 绑定外部文件与状态域 | `ASSIGN TO`、`ORGANIZATION IS LINE SEQUENTIAL`、`FILE STATUS IS` | 之后每次 I/O 都会刷新 `WS-FILE-STATUS` |
| `FILE SECTION` 的 `FD` 与 `01` 记录项 | 定义 100 字符读入缓冲区 | `FD`、`PIC X(100)` | 每次成功的 `READ` 覆盖这 100 字节 |
| `0000-MAIN` 开头 | 打开并分流 | `OPEN INPUT`、`IF WS-FILE-STATUS NOT = "00"` | 成功 → `00` 继续；缺失 → `35` 并结束（退出码 1） |
| `0000-MAIN` 循环 | 驱动逐条读取 | `PERFORM UNTIL WS-END-OF-FILE = "Y"` | 退出条件由 `AT END` 置位，不由计数控制 |
| `1000-READ-ONE-RECORD` | 读一条并按结果分流 | `READ`、`AT END`、`NOT AT END`、`ADD 1`、`FUNCTION TRIM` | 成功 → 计数 +1、打印该行；EOF → 置标志、计数不变 |
| `0000-MAIN` 收尾 | 报告、关闭 | `DISPLAY "EOF=..."`、`CLOSE`、状态检查 | EOF 行在关闭之前打印；关闭失败同样置退出码 1 |

## 运行与观察

程序会以**运行时当前工作目录**去找 `transactions.txt`，所以下面把夹具复制到临时目录，再在临时目录里运行，仓库内不会留下任何产物。

```sh
cd lessons/15_sequential-file-read                # 进入本课目录（或任意包含 lesson.cob 的路径）
scratch_dir=$(mktemp -d)
trap 'rm -rf "$scratch_dir"' EXIT                 # clean：退出 shell 时删除临时目录

cobc -fsyntax-only lesson.cob                     # check：只做语法分析，不生成可执行文件
cobc -x -Wall -o "$scratch_dir/lesson_15" lesson.cob   # build：生成可执行文件到临时目录
cp transactions.txt "$scratch_dir/"               # 复制夹具副本，不碰仓库文件
( cd "$scratch_dir" && ./lesson_15 )              # run：从夹具所在目录执行
echo $?                                           # 查看退出码
```

`-fsyntax-only` 只验证源码能否被解析；`-x` 才生成可执行文件；`run` 必须让当前工作目录包含夹具；`clean` 在本课就是删掉上面这个临时目录。

**预期结果（正常路径）：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出 | 7 行，见下方代码块 |
| 进程退出码 | `0` |
| 生成文件 | 临时目录内只有可执行文件与夹具副本；程序不生成数据文件 |
| 夹具变化 | 无。夹具内容与运行前一致（运行前 `md5sum transactions.txt` 为 `a715090ba2436ed2a9feedf549558e77`） |

```text
オープン=OK
レコード=DAY-20261013|TXN-000001|D|0001234567|125.50
レコード=DAY-20261013|TXN-000002|T|0001234567|0007654321|40.00
レコード=DAY-20261013|TXN-000003|D|0002468101|75.00
レコード=DAY-20261013|TXN-000004|T|0007654321|0009999999|20.00
EOF=はい レコード数=04
クローズ=OK
```

**输出对照（日文输出 → 含义）：** `オープン=OK` = 打开成功；`オープン=FAILED STATUS=xx` = 打开失败并给出文件状态码；`レコード=` = 成功读出的一条原始行；`EOF=はい レコード数=nn` = 已到文件尾、成功读出的记录数；`クローズ=OK` / `クローズ=FAILED` = 关闭结果。`はい` 意为“是”。仓库约定程序输出用日文；判断行为以实际输出和本节的中文说明为准。

**空文件路径：**

```sh
: > "$scratch_dir/transactions.txt"      # 清空夹具副本
( cd "$scratch_dir" && ./lesson_15 )     # 退出码 0
```

```text
オープン=OK
EOF=はい レコード数=00
クローズ=OK
```

空文件仍然可以打开，所以没有失败信息；区别只体现在一条 `レコード=` 都没有、计数为 `00`。

**文件缺失路径：**

```sh
rm -f "$scratch_dir/transactions.txt"    # 让当前目录里没有夹具
( cd "$scratch_dir" && ./lesson_15 )     # 退出码 1
```

```text
オープン=FAILED STATUS=35
```

这一次输出停在打开失败：没有 `EOF=` 行，也没有 `クローズ=` 行，因为程序在 `READ` 之前就结束了。状态码 `35`、退出码 `1` 是判断“文件没到位”和“文件读完了”的事实依据。

**实际观察到的环境细节：** 在本工作区运行可执行文件时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境链接库版本警告，不是程序的业务输出（业务输出全部写在标准输出）；其触发组件尚未定位。

## 在企业中的位置

批处理入口先要回答三件事：文件到底有没有到位、每条记录是否按送达顺序读到、读完与失败能否区分。生产系统还会在此基础上增加最大行长、编码、字段校验、拒绝记录、日志和重复运行策略；本课只建立“打开 → 逐行读取 → 识别 EOF 或打开失败”这段最小输入流程。

本课的产物是后续文件课的共同起点：[第 16 课](../16_file-writing/README.md)把结果写成输出文件，[第 17 课](../17_fixed-length-files/README.md)换成定长记录，[第 19](../19_multiple-files/README.md)、[第 20 课](../20_file-matching/README.md)同时读取多个流并按顺序匹配，[第 22 课](../22_file-processing-practice/README.md)把它们串成端到端批次，[第 26 课](../26_error-handling/README.md)再补齐错误分类与资源清理。本课没有实现这些保证，不能当作生产批次。
