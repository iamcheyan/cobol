# データ部、階層番号、グループ項目

## 学習目標

01/05/10/77/88 のレベル番号、グループ項目と基本項目、WORKING-STORAGE・LOCAL-STORAGE・LINKAGE のライフサイクルの違い。

この課を終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言箇所や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L04.COB`](./L04.COB) を開きます。この課のソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートディレクトリで実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/04-data-hierarchy/L04.COB
cobc -x -Wall -o build/l04 extensions/legacy-workshop/lessons/04-data-hierarchy/L04.COB
./build/l04
```

期待される観察内容：顧客レコードと独立したカウンターを定義します。

コンパイラーが書式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認してください。次に、ピリオド、変数の PIC、スコープを終了する文を確認します。`-Wall` は追加の警告を表示します。警告も内容を理解してから、対処するかどうかを判断してください。

## 各部分を理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラーが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使用するデータを記述します。この課にフィールド宣言がある場合は、レベル番号と PIC に注目してください。
3. `PROCEDURE DIVISION` は実行の開始点です。`0000-MAIN` は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースの順序どおりに実行され、制御フロー文によって経路が変わるか、`STOP RUN` でプロセスが終了します。

## 変更演習

都市フィールドを追加し、階層のインデントを調整して、どの 01 レコードに属するかを考えてください。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つだけにし、変更前後の出力を記録してください。

## cobol.nvim を使った学習

フィールド名にカーソルを置いて gd を使うと、定義を検索できます。`:CobolCalcRecord` を使うと、レコードレイアウトの推定を確認できます。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に利用できます。プログラムがコンパイル可能かどうかは、GNUCOBOL による実際のコンパイル結果で判断します。
