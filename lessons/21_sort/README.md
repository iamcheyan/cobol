# 第 21 课：用 SORT 整理账户主档——把无序输入变成有序输出

第 20 课的顺序匹配要求两个输入都按账户号升序，但送来的主档往往不是有序的。本课用 `SORT` 把一份四条未排序的主档整理成升序：输入过程逐条 `READ` 并把记录 `RELEASE` 进排序工作文件，输出过程用 `RETURN` 取回已排序记录，最后用输入/输出计数确认一条也没丢。

## 为什么现在学

第 15–19 课你已经会读、写和并行推进文件，第 20 课学会了按顺序键归并匹配——但那套算法有前提：输入必须有序。缺口是“把无序变有序”：真实主档按录入顺序或抽取顺序到达，不能假设它已经排好。本课引入 `SORT` 与它的两个过程，把排序封装进数据流，并让结果直接喂给第 20 课的匹配扫描。

## 本课完成后的能力与边界

学完本课后，你可以：

- 声明排序工作文件（`SELECT ... ASSIGN TO DISK` + `SD`）并指定升序排序键。
- 在 `INPUT PROCEDURE` 中打开输入、逐条 `READ` 并用 `RELEASE` 送入排序。
- 在 `OUTPUT PROCEDURE` 中用 `RETURN` 逐条取回已排序记录，并用 `AT END` 结束。
- 用 `SORT-RETURN` 区分排序工作成功与失败，并核对 `入力レコード数 = 出力レコード数`。
- 说明为什么对排序工作文件不能执行 `OPEN`/`CLOSE`，以及排序输出如何成为第 20 课匹配的输入。

边界：本课只排序并显示，**不生成排序结果文件**、不累计金额、不做匹配；夹具账户号唯一，因此不涉及重复键的相对次序。排序键规则、重复键政策与排序失败的批次处置属于接口约定，正式的错误分流见第 26 课。

## 运行环境

- GnuCOBOL 3.2.0，默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不依赖数据库或附加工具。
- `SELECT` 使用相对文件名，因此**从本课目录执行**；语法检查与编译在 `build/` 下生成可执行文件。

## 记录布局与数据流

[`accounts-unsorted.txt`](./accounts-unsorted.txt) 有 4 条 27 字符记录，**未排序**：

| 字段 | `PIC` | 长度 |
|---|---|---:|
| 账户号 | `X(10)` | 10 |
| 客户号 | `X(8)` | 8 |
| 余额 | `9(7)V99` | 9 |

余额的 `V` 是隐含小数点、不占字符，所以一行的可见长度是 10 + 8 + 9 = 27。这与第 17、20 课的主档布局一致。

程序声明了 `SELECT SORT-WORK ASSIGN TO DISK` 和 `SD SORT-WORK`。排序工作文件由 GnuCOBOL 在内部管理，**程序不执行 `OPEN` 或 `CLOSE`**：输入过程负责把记录送进去，输出过程负责取回来。

## 三个排序阶段

1. `SORT SORT-WORK ON ASCENDING KEY SD-ACCOUNT-NUMBER` 声明排序键与两个过程的入口。
2. 输入过程 `1000-LOAD-INPUT` 打开行顺序输入，逐条 `READ`；成功时把 27 字符记录移入 `SD` 记录再 `RELEASE`，文件状态 `10` 表示正常 EOF。
3. GnuCOBOL 按 `SD-ACCOUNT-NUMBER` 组织已释放记录。
4. 输出过程 `2000-RETURN-SORTED` 重复 `RETURN`，每次成功返回一条记录就显示，`AT END` 结束。
5. 主段落检查 `SORT-RETURN`，最后显示输入/输出计数；任何检测到的输入或排序失败都会返回非零码。

计数不变量：`入力レコード数 = 出力レコード数`。本课为 `004 = 004`——把 4 条记录全部释放、又全部取回，说明排序过程既没有丢记录也没有凭空多出记录。

## 前提与边界

| 前提 | 由谁保证 | 本课是否校验 |
|---|---|---|
| 输入每行满足 27 字符布局 | 夹具/上游 | 否，宽度不符会读错字段 |
| 账户号作为排序键，含前导零且等长 | 夹具设计 | 否，但等长文本按字符顺序比较就等于按账户号升序 |
| 账户号唯一 | 夹具 | 否，本课不处理重复键 |
| 排序键相同记录的先后次序 | 未约定 | **未验证**：本课夹具没有重复键，所以没有观察到并列记录的次序；需要明确次序时应当补第二排序键（见举一反三练习） |

排序工作文件由 `SORT` 语句管理，程序既不 `OPEN`/`CLOSE` 它，也不直接读写它。输入文件在输入过程内打开并关闭；输出只写到终端，没有生成排序结果文件。

## 运行与观察

**输入：** 本课目录下的 `accounts-unsorted.txt`（4 条未排序记录）。程序按相对路径打开，所以要先 `cd` 到本课目录。

**命令及作用：**

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob                  # 只做语法检查，不生成可执行文件
cobc -x -Wall -o build/lesson_21 lesson.cob    # 编译并生成可执行文件
./build/lesson_21                              # 运行，读取当前目录下的夹具
echo $?                                        # 查看退出码
rm -rf build                                   # 清理生成的可执行文件
```

**预期结果：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出 | 5 行，见下方代码块；4 条记录按账户号升序 |
| 进程退出码 | `0` |
| 生成的业务文件 | 无（排序工作文件由运行时内部管理） |

```text
ソート済み 口座番号=A000000001 顧客番号=C0001001 残高=0001000.00
ソート済み 口座番号=A000000002 顧客番号=C0001002 残高=0000002.00
ソート済み 口座番号=A000000004 顧客番号=C0001004 残高=0000025.00
ソート済み 口座番号=A000000005 顧客番号=C0001005 残高=0000250.75
入力レコード数=004 出力レコード数=004
```

**可独立核算：** 输入夹具的账户号依次是 `A000000005`、`A000000001`、`A000000004`、`A000000002`（未排序），输出必须是 `A000000001`、`A000000002`、`A000000004`、`A000000005`——排序做的是重排，因此输出账户号集合必须与输入完全相同，只是顺序变了。计数行 `004 = 004` 印证没有丢记录。

**输出字段对照（日文输出 → 含义）：** `ソート済み` = 已排序；`口座番号` = 账户号；`顧客番号` = 客户号；`残高` = 余额；`入力レコード数` / `出力レコード数` = 输入 / 输出记录数。

**实际观察到的环境细节：** 在本工作区运行可执行文件时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境的链接库版本警告，不是本程序的业务输出；其触发组件尚未定位。

## 修改练习

两项都在**临时目录里的夹具副本**上做，不要改动仓库内的 `accounts-unsorted.txt`：

1. 交换副本的前两行，运行后确认输出仍按账户号升序，且输入/输出计数相同。
2. 从原始夹具出发，在副本末尾追加一条 27 字符记录：账户号 `A000000006`、客户号 `C0001006`、余额数字 `000000001`。确认它排在最后一行，计数变为 `005`。

完整题目与预期见 [`exercise.md`](./exercise.md)，参考答案见 [`answer.md`](./answer.md)。

## 举一反三练习

给排序键加第二个字段：先按账户号升序，再按余额降序。至少准备两条账户号相同、余额不同的记录，观察结果，并说明在只声明一个排序键时，程序**是否**依赖相同键记录的相对次序。记录修改后的 `SORT` 键声明与完整输出。不许用 `OCCURS` 先装入全部记录，也不许改用 `USING`/`GIVING` 绕开本课的两个过程。题目见 [`exercise.md`](./exercise.md)，本题不提供答案。

## 在企业中的位置

大批量对账常在匹配前整理输入顺序：`SORT` 把“读记录 → 释放排序 → 按键返回”封装在程序内，输出正好可以交给第 20 课的一次扫描匹配。上线前必须约定排序键、重复键政策、空文件行为、源文件状态和排序失败后的批次退出策略。

本课的产物只是“有序的记录流”，还没有写文件、没有累计金额、没有拒绝分类。排序结果写出成文件见第 22 课，模块化与错误分流见第 26 课，端到端对账见第 32 课。
