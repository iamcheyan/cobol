# 第24課の練習：金額検証サブプログラムの呼び出し

2つの変更練習は、元の `lesson.cob` と `amount_check_24.cob` から始めます。2つ目の練習を始める前に元へ戻し、変更を重ねないでください。検証ルールはサブプログラムにあるため、変更後は毎回2つのソースを一緒にコンパイルします。

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob amount_check_24.cob
cobc -x -Wall -o build/lesson_24 lesson.cob amount_check_24.cob
./build/lesson_24
echo $?
rm -rf build
```

## 変更練習（解答は [`answer.md`](./answer.md)）

### 1. 金額上限を上げ、境界値を確認する

- **基準：** 上限が `1000.00` の元の `amount_check_24.cob`。
- **変更と制約：** `0000-VALIDATE-AMOUNT` の `WHEN LK-AMOUNT > 1000.00` にある定数だけを `1500.00` に変更します。PIC宣言、フィールド順、呼び出し、メインプログラム内の金額は変えません。
- **正しさの条件：** `1000.01` は上限超過ではなくなり、`9999999.99` は引き続き上限超過。メインプログラムの終了コードは `0`。
- **期待する出力差分：** 結果と件数に関する3行だけが変わり、残り17行はバイト単位で同じです。

  ```text
  -CALL後の状態=LIMIT-EXCEEDED      （4件目、金額1000.01の後）
  +CALL後の状態=VALID
  -検査数=008 有効=005 拒否=003
  -ゼロ金額拒否=001 上限拒否=002
  +検査数=008 有効=006 拒否=002
  +ゼロ金額拒否=001 上限拒否=001
  ```

- **理由：** `1000.01 ≤ 1500.00` なので `WHEN OTHER` に進み `VALID` を返します。有効数は1増え、上限拒否数は1減ります。ゼロ金額のケースは変わらず、総検査数とゼロ金額拒否数も同じです。

### 2. ゼロ金額のケースをなくす

- **基準：** 元の `lesson.cob`。`1200-CHECK-ZERO-AMOUNT` に `MOVE ZERO TO WS-AMOUNT` があります。
- **変更と制約：** その段落の `MOVE ZERO` だけを `MOVE 0.01` に変更します。サブプログラム、上限、他の7件の金額、件数処理は変えません。
- **正しさの条件：** 2件目が拒否から有効に変わります。金額は5件目（`1500-CHECK-SMALL-POSITIVE`）と同じになり、出力には `金額=0000000.01` と `VALID` が2回現れます。
- **期待する出力差分：**

  ```text
  -CALL前 金額=0000000.00
  -CALL後 状態=ZERO-AMOUNT
  +CALL前 金額=0000000.01
  +CALL後 状態=VALID
  -検査数=008 有効=005 拒否=003
  -ゼロ金額拒否=001 上限拒否=002
  +検査数=008 有効=006 拒否=002
  +ゼロ金額拒否=000 上限拒否=002
  ```

- **理由：** `0.01` はゼロではなく、上限を超えないため `VALID` です。ゼロ金額の発生元はこの1件だけなので、その件数は0になり、有効数が1増えます。上限拒否数 `002` は変わりません。

### 両方の練習で制御フローを説明する

全出力を保存し、次のラベルがそれぞれどの制御段階を表すか説明します。

- `CALL前 金額=` は、呼び出し元が制御をサブプログラムへ渡す前に表示します。
- `CALL後 状態=` は `CALL` から戻った後に表示します。これが出ることは `GOBACK` で呼び出し元へ制御が戻った証拠です。
- `サブプログラムから戻り呼び出し元を継続` は8件すべての処理後に表示されます。`CHECK-AMOUNT` が `LESSON24` を終了させず、メインプログラムが最後に `STOP RUN` することを示します。

## 発展課題（解答なし）

顧客の利用状態を検証する第2のサブプログラムを作ります。金額検証の前にメインプログラムから状態項目を渡します。新しい `PROGRAM-ID`、`LINKAGE SECTION` の顧客状態フィールド（PICと幅は自分で選択）、`ACTIVE`、`FROZEN`、未知の状態に対する結果を定義してください。

顧客検証に失敗したら、メインプログラムは金額検証の `CALL` を**実行しない**ようにします。判断に使う戻り値を説明してください。変更したソース、コンパイルコマンド、実引数とLINKAGE引数の位置対応、各 `CALL` の戻り状態、2回目の `CALL` が実行されなかったことを示す出力を記録します。

解答はありません。呼び出し元が判定に使う戻り値を画面表示だけにしてはいけません。メインプログラムだけでなく、両方のプログラムソースをビルドしてください。ファイル入出力、データベース、本課で扱っていない引数渡し方式は使いません。
