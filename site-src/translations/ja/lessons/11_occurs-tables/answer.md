# 第 11 課変更演習：参考解答

この解答は `exercise.md` の3つの変更演習だけを扱います。「学んだことを応用する」の解答はありません。各問は本課の元の `lesson.cob` から独立して始めます。コマンドは README と同じです。

```sh
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_11 lesson.cob
./build/lesson_11
```

以下の出力はすべてこのワークスペースで確認したものです。3ケースすべてで構文検査、コンパイル、実行の終了コードは `0` でした。実行時の標準エラーには libxml バージョン警告もありましたが、プログラムの出力ではありません。

## 1. 4項目目の金額を変更

`1000-LOAD-TABLE` の1行だけを変更します。

```cobol
           MOVE 35.00 TO WS-TXN-AMOUNT(4)
```

出力全体：

```text
明細=01 コード=C 金額=00125.50
処理=入金
明細=02 コード=D 金額=00040.10
処理=出金
明細=03 コード=X 金額=00025.00
処理=未知コードを無視
明細=04 コード=C 金額=00035.00
処理=入金
処理件数=004
最終残高=0001120.40
```

差分と理由：`C` 分岐はこの金額を残高に加算するため、変わるのは `明細=04` の金額と `最終残高` だけです。計算は `1000.00 + 125.50 − 40.10 + 35.00 = 1120.40` です。テーブル項目数を数える `処理件数` は金額に関係しないため `004` のままで、先頭6行はバイト単位で変わりません。

## 2. 5項目に拡張し、5項目目をロード

容量、ロード済み項目数、走査上限が食い違わないよう、3か所を同時に変更します。

```cobol
          05 WS-TRANSACTION-ENTRY OCCURS 5 TIMES.
       01 WS-LAST-SAMPLE PIC 9 VALUE 5.
           MOVE "C" TO WS-TXN-CODE(5)
           MOVE 10.00 TO WS-TXN-AMOUNT(5).
```

5項目目の2つの `MOVE` は4項目目の後に置き、`WS-TXN-AMOUNT(4)` は `20.00` のままにします。出力全体：

```text
明細=01 コード=C 金額=00125.50
処理=入金
明細=02 コード=D 金額=00040.10
処理=出金
明細=03 コード=X 金額=00025.00
処理=未知コードを無視
明細=04 コード=C 金額=00020.00
処理=入金
明細=05 コード=C 金額=00010.00
処理=入金
処理件数=005
最終残高=0001115.40
```

差分と理由：`PERFORM VARYING` が新しい `C` / `10.00` の項目を処理します。残高は `1105.40` から `1000.00 + 125.50 − 40.10 + 20.00 + 10.00 = 1115.40` になり、処理件数は `004` から `005` に変わります。既存の4項目は変わらず、新しい明細行が最後に追加されます。

## 3. 範囲外の観察：走査上限だけを5にする

変更は次の1行だけです。

```cobol
       01 WS-LAST-SAMPLE PIC 9 VALUE 5.
```

確認結果：

- `cobc -fsyntax-only lesson.cob` とコンパイルはいずれも診断なしで `0` を返します。コンパイラーは添字がテーブル容量内か検査しません。
- プログラムの終了コードも `0` です。5項目目は `明細=05 コード=0 金額=5` と表示され、その後に表示不能な NUL バイト4個と `.00` が続きます。
- そのバイト列は `C` でも `D` でもないため、`EVALUATE` は `WHEN OTHER` に進み、`処理=未知コードを無視` と表示します。最終値は `処理件数=005`、`最終残高=0001105.40` です（読み取った値が記帳分岐に入らなかったため、偶然にも最初の4項目の計算結果と同じです）。
- したがって、エラーも非ゼロ終了も起きませんが、5項目目の値はまったく信用できません。

理由：4項目のテーブルは合計32バイトで、添字5はテーブルの外側のアドレスを指します。GnuCOBOL の既定動作では添字からアドレスを直接計算し、範囲検査を行わないため、テーブル直後のワーキングストレージを読み取ります（`cobc -C` の生成データ配置では、テーブルの直後に `WS-SAMPLE-INDEX` などの項目があります）。読み取るバイトはコンパイラーの配置に依存し、バージョン変更や項目順変更でも変わります。予測も業務データとしての利用もできません。

演習2のように容量、ロード済み項目数、走査上限を一致させるか、読み取り前に添字範囲を明示的に検査してください。バッチ処理では、誤ったバイトを黙って読むほうが、すぐ失敗するより発見しにくくなります。
