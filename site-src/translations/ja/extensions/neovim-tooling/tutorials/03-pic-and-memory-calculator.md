# PIC とレコードレイアウトのサイズ推定

COBOL の `PIC` 節はフィールドの形式を表します。固定長ファイルや Copybook のインターフェースでは、フィールド幅やオフセットの確認が必要になることがあります。`cobol.nvim` は一般的な宣言を読みやすいサイズ推定に変換できます。

## プラグインの機能

- データ宣言上にカーソルがあると、フィールドの PIC とバイト数の推定を表示します。
- レベル 01 のレコード行に、認識できたフィールドの合計推定値を表示します。
- `<leader>cr` / `:CobolCalcRecord` でレイアウト表を開き、フィールド階層、オフセット、PIC／使用形式、推定サイズを表示します。

![COBOL の PIC フィールドとレコードレイアウトの推定](images/record-layout.png)

レイアウト表では `WS-TRANSACTION-RECORD` 配下のフィールドのオフセットと推定サイズを確認できます。この画像は Neovim で `:CobolCalcRecord` を実行した画面です。

## 簡単な例

```cobol
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WS-TRANSACTION-RECORD.
          10 WS-CUSTOMER-ID PIC X(8).
          10 WS-AMOUNT PIC 9(5)V99.
          10 WS-STATUS PIC X.
```

`WS-TRANSACTION-RECORD` にカーソルを置いて `:CobolCalcRecord` を実行します。表には、認識されたフィールドがソース順に並び、推定バイトオフセットが表示されます。各フィールド行には個別のサイズヒントも表示されます。

概算の目安として、`PIC X(n)` と表示形式の `PIC 9(n)` は通常 1 文字あたり 1 バイトです。暗黙の小数点 `V` は記憶領域を使いません。`COMP-3` は一般に、数字のニブルと符号ニブルから推定します。2 進数の `COMP` のサイズは精度、コンパイラー、対象 ABI によって異なります。

## 推定値の限界

レイアウト表示は読み取りや初期確認には役立ちますが、対象環境のコンパイラーに代わるものではありません。アラインメント、符号表現、方言、コンパイルオプション、プラットフォームによって実際のレイアウトは変わります。現在の計算機能は、グループレベルの `OCCURS` の回数をすべての子フィールドに乗算しません。また、大きな `REDEFINES` の重ね合わせも合計サイズを増やしません。このような宣言では、対象コンパイラーとインターフェース仕様を基準にしてください。

## クイック操作

| 操作 | 動作 |
| --- | --- |
| `<leader>cr` / `:CobolCalcRecord` | 現在のフィールドまたはレベル 01 レコードのレイアウト推定を表示 |
| データ宣言にカーソルを置く | フィールドの PIC／バイト数の推定ヒントを表示 |
| `q` / `<Esc>` | レイアウトの浮動ウィンドウを閉じる |
