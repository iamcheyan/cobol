# 第 13 课：SEARCH 与 SEARCH ALL——把交易账户号关联到账户主档

对账前必须先按账户号从账户主档里取出余额。本课把四个账户装进 `OCCURS` 内存表，分别用逐项查找 `SEARCH` 和二分查找 `SEARCH ALL` 按账户号取出 `520.00` 这笔余额，并处理“账户不存在”的路径；两种写法各自的排序前提也在本课暴露出来。

## 为什么现在学

你已经能用 `OCCURS` 声明表格、用 `INDEXED BY` 索引遍历它，但还没有“按某个键找到表项”的写法。缺口是查找语义：怎样在表里找到匹配项、找不到时走哪条路，以及二分查找为什么要求键有序且唯一。账户号是定宽文本并带前导零，长度和顺序都必须显式约定，这正是后续文件匹配的基础。

## 本课完成后的能力与边界

学完本课后，你可以：

- 用 `SEARCH` 从指定索引开始逐项查找表格键，并用 `AT END` 处理未找到。
- 用 `SEARCH ALL` 对声明了 `ASCENDING KEY` 和 `INDEXED BY` 的表格做二分查找。
- 说明 `SEARCH ALL` 对索引、键顺序和键唯一性的要求，以及这三者由谁维持。
- 用同一个账户号分别跑两种查找，核对它们返回相同的余额；对不存在的账户核对两种写法都输出 `NOT_FOUND`。
- 指出“声明了 `ASCENDING KEY` 不等于数据有序”，并说明本课如何观察（以及无法观察）这一风险。

边界：本课只用四项程序内固定的内存表，不读文件或数据库，也不涉及索引顺序文件。`SEARCH` 不要求表格有序，但 `SEARCH ALL` 要求键值与声明同序且唯一；装载与排序流程的完整性留到第 17、21 课的文件与 `SORT` 内容。

## 运行环境

- GnuCOBOL 3.2.0，默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不依赖数据库或附加工具。
- 无输入夹具、无输出数据文件；编译产物写在 `build/`，可直接删除重来。

## 样例账户表

完整源码见 [`lesson.cob`](./lesson.cob)。程序把四个账户按 `X(10)` 账户号递增顺序装入 `OCCURS` 表格：账户号唯一，第三项余额为 `520.00`。

| 表项 | 账户号 | 余额 |
|---:|---|---:|
| 1 | `0000000042` | 0.00 |
| 2 | `0001234567` | 1000.00 |
| 3 | `0002468101` | 520.00 |
| 4 | `0007654321` | 250.75 |

表格声明 `ASCENDING KEY IS WS-ACCOUNT-NUMBER`，并用 `INDEXED BY WS-ACCOUNT-IDX` 提供搜索索引。固定宽度的文本账户号包含前导零，因此按长度相同的字符顺序升序排列就是按账户号升序排列。

程序对已存在的 `0002468101` 和不存在的 `0005550000` 分别执行两种查找。

## SEARCH 与 SEARCH ALL

`SEARCH WS-ACCOUNT-ENTRY` 是顺序查找。程序先用 `SET WS-ACCOUNT-IDX TO 1` 把索引设为 1；每个 `WHEN` 检查当前账户号，未匹配时 `SEARCH` 自动前进到下一项；全部项都不匹配时执行 `AT END`。

`SEARCH ALL WS-ACCOUNT-ENTRY` 是二分查找。它自动选择要检查的表项位置；`WHEN` 通过该表的 `INDEXED BY` 索引，把目标值与当前账户号比较。它要求表格声明索引和 `ASCENDING KEY`（或 `DESCENDING KEY`），且**实际键值顺序**必须符合声明。用于 `SEARCH ALL` 的键还必须唯一。

| 查找方式 | 比较顺序 | 前提 |
|---|---|---|
| `SEARCH` | 从当前索引逐项检查，直到找到或到达表尾 | 不要求按键排序；执行前应把索引设为合理起点 |
| `SEARCH ALL` | 二分缩小有序表的查找范围 | 要求 `INDEXED BY`、与声明一致的键顺序、唯一键 |

**声明不等于排序。** `ASCENDING KEY` 只说明“如果这张表要用于 `SEARCH ALL`，键应当按这个方向有序”，它不会替程序排列表项。键顺序由装载数据的那段代码负责，本课就是 `1000-LOAD-ACCOUNTS`。

## 程序执行步骤

1. `1000-LOAD-ACCOUNTS` 用常量下标装入四个账户，账户号严格升序且没有重复。
2. 主段落把 `0002468101` 设为目标，依次调用顺序查找和二分查找；两者都显示匹配账户及 `520.00` 余额。
3. 主段落再把 `0005550000` 设为目标。两个查找都没有匹配项，各自执行自己的 `AT END` 输出。
4. 顺序查找在运行前把索引重置为 1；二分查找则自动选择检查位置。
5. 搜索索引只用于表格引用（`WS-ACCOUNT-NUMBER(WS-ACCOUNT-IDX)`），不作为普通数值运算字段。

## 运行与观察

本课不读取输入文件、命令行参数或数据库，因此在本课目录或任意目录执行结果相同。下面按本课目录说明。

**输入：** 无外部输入。四个账户和两个搜索目标都是程序内固定数据。

**命令及作用：**

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob                  # 只做语法检查，不生成可执行文件
cobc -x -Wall -o build/lesson_13 lesson.cob    # 编译并生成可执行文件
./build/lesson_13                              # 运行程序，查找结果写到标准输出
echo $?                                        # 查看退出码
rm -rf build                                   # 清理生成的可执行文件
```

**预期结果：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出 | 8 行，见下方代码块 |
| 进程退出码 | `0` |

```text
検索=SEQUENTIAL キー=0002468101
逐次検索=検出 口座=0002468101  残高=0000520.00
検索=BINARY キー=0002468101
二分検索=検出 口座=0002468101  残高=0000520.00
検索=SEQUENTIAL キー=0005550000
逐次検索=NOT_FOUND
検索=BINARY キー=0005550000
二分検索=NOT_FOUND
```

**输出字段对照（日文输出 → 含义）：** `検索` = 正在执行的查找方式（`SEQUENTIAL` 顺序 / `BINARY` 二分）；`キー` = 本次搜索键；`逐次検索` / `二分検索` = 该方式的查找结果；`検出` = 找到；`口座` = 命中的账户号；`残高` = 该账户余额（`PIC 9(7)V99`，`520.00` 补零显示为 `0000520.00`）；`NOT_FOUND` = 未找到。

**实际观察到的环境细节：** 在本工作区运行可执行文件时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境的链接库版本警告，不是本程序的业务输出；其触发组件尚未定位。程序输出在标准输出，退出码为 0。

## 有序性前提在本机能不能观察

`SEARCH ALL` 依赖表项顺序符合 `ASCENDING KEY`。为了弄清这个前提能不能靠编译或测试发现，本工作区做了两个探针（探针不属于 [`lesson.cob`](./lesson.cob)）：

1. 把四项数据的装入顺序整体反过来（第四项先装），声明仍是 `ASCENDING KEY`；
2. 把表格扩为五项、按降序装入，同样保持声明不变。

**观察结果：** 两次探针都编译通过（`cobc -x -Wall` 返回码 `0`，无诊断），运行的输出与上表逐行相同——`SEARCH ALL` 仍然找到了 `0002468101`，不存在的键仍输出 `NOT_FOUND`。

**结论（限定在本机 GnuCOBOL 3.2.0 与这个表规模）：** 违反 `ASCENDING KEY` 在本课规模下既不被编译器拦下，也不会让运行时结果出错，所以“顺序对了没有”不能靠跑一遍程序来验证。有序性必须由装载或排序流程保证，并在评审时按数据来源单独核对；这也正是 `SEARCH ALL` 省比较次数却更难保证正确的原因。不要把这两次探针的结果推广成“顺序错了也没关系”。

## 修改练习

1. 从原始 [`lesson.cob`](./lesson.cob) 开始，把 `1000-LOAD-ACCOUNTS` 中账户 `0002468101` 的余额从 `520.00` 改为 `600.00`，运行两种查找并核对它们返回的余额。
2. 从原始 [`lesson.cob`](./lesson.cob) 开始，把账户表从四项扩为五项，在末尾追加账户 `0009999999`、余额 `75.00`，并把第二个搜索目标从 `0005550000` 改为 `0009999999`。保持键值唯一且递增，确认两种查找都找到新增账户。

## 举一反三练习

为五个产品代码和库存数量创建表格。先用 `SEARCH` 查找中间的产品和不存在产品；再为 `SEARCH ALL` 声明合适的键，确保所有产品代码唯一且实际按所声明方向排序，分别测试命中与未命中。最后说明：如果只改表格顺序而不同步键声明，会出现什么风险、为什么本课的探针无法自动发现它。使用固定内存表格，不添加文件或数据库。题目见 [`exercise.md`](./exercise.md)，本题不提供答案。

## 在企业中的位置

把交易账户号关联到账户主档时，查找结果决定后续读取哪个余额和状态。`SEARCH ALL` 只有在装载或排序流程确实维持唯一且有序的键时才可靠，这一点不能只靠数据描述里的 `ASCENDING KEY` 声明。生产流程必须定义重复键处理、缺失账户处理和数据顺序验证。

本课的结果只能说明“在这四个固定表项上两种查找返回一致”。把有序表换成真实输入要从第 17 课（定长文件）和第 21 课（`SORT`）开始；重复键与缺失键的正式处理在第 16、20 课展开；账户主档的排序与唯一性由上游保证，这一点在第 20 课的匹配前提里会再次出现。
