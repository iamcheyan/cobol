# 総合プロジェクト1：区切りテキストを整形して CSV に書き出す

## 学習目標

ファイル I/O、UNSTRING、データ検証、エラーカウント、STRING、Copybook、Bash による自動化を組み合わせ、エンドツーエンドの小さなプログラムを作ります。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言箇所や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L25.COB`](./L25.COB) を開いてください。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文と実行文は Area B に記述されています。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/25-project-csv-pipeline/L25.COB
cobc -x -Wall -o build/l25 extensions/legacy-workshop/lessons/25-project-csv-pipeline/L25.COB
./build/l25
```

期待される観察事項：対応する完全版のプログラムは、リポジトリのルートにある INPUTCSV.COB です。このレッスンではデータフローを分解して説明し、重要なエラー処理を隠したまま繰り返すことはしません。

コンパイラが形式や列位置のエラーを報告した場合は、まず第 7、8、12、72 列を確認してください。続いて、ピリオド、変数の PIC、スコープを終了する文を確認します。`-Wall` は追加の警告を表示します。警告の内容も理解してから、対処するかどうかを判断してください。

## 各部分の理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文で経路が変わるか、`STOP RUN` でプロセスが終了するまで、ソースコードの順に実行されます。

## 変更演習

`make run-csv` を実行し、input.txt のフィールド数、空フィールド、不正な金額を変更して、プログラムがどう処理すべきかを記録してください。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は一つにし、変更前後の出力を記録しましょう。

## cobol.nvim で学ぶ

`gf`/`K` で EMP-REC.CPY を開き、`<leader>cr` でフィールドのレコードを確認します。診断と Quickfix を使って、意図的に入れたエラーを修正してください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかは、GNUCOBOL の実際のコンパイル結果で判断してください。
