# 第 16 课修改练习参考答案

本答案只回答 [`exercise.md`](./exercise.md) 中的两项修改练习，不提供举一反三练习的答案。下列输出、字节数和返回码都在本工作区用 GnuCOBOL 3.2.0 实际运行观察过，运行目录是课内 `build/`。

## 一、把第四项改成接受结果

### 改动方式

从原始 `lesson.cob` 开始，只改 `1000-LOAD-RESULTS` 中的两行：

```cobol
           MOVE "A" TO WS-RESULT-DESTINATION(4)
           MOVE "TXN-000004|0009999999|T|000020.00|A"
               TO WS-RESULT-TEXT(4)
```

`PIC`、`FD` 记录宽度、`OCCURS 4 TIMES` 上界、循环上界、其它三条记录和所有 `DISPLAY` 文本都不变。

命令：

```sh
mkdir -p build
cp lesson.cob build/
cobc -fsyntax-only build/lesson.cob
cobc -x -Wall -o build/lesson_16 build/lesson.cob
(cd build && ./lesson_16)
echo $?
wc -lc build/accepted.txt build/rejected.txt
```

语法检查与编译返回码、退出码都是 `0`，编译无诊断。

### 改动后的完整输出

```text
オープン=受理 成功
オープン=拒否 成功
書込=受理 取引=000001
書込=受理 取引=000002
書込=拒否 取引=000003
書込=受理 取引=000004
クローズ=受理 成功
クローズ=拒否 成功
SUMMARY 受理=03 拒否=01
```

与原始初值的差异只有两行：

| 行 | 原始值 | 改动后的值 | 原因 |
|---|---|---|---|
| 6 | `書込=拒否 取引=000004` | `書込=受理 取引=000004` | 目的地标记改成 `A`，`EVALUATE` 选了接受文件那条 `WHEN` 分支 |
| 9 | `SUMMARY 受理=02 拒否=02` | `SUMMARY 受理=03 拒否=01` | 接受文件多写一条、拒绝文件少写一条 |

其余 7 行逐字节不变。

### 改动后的文件

`accepted.txt`（3 行、108 字节）

```text
TXN-000001|0001234567|D|000125.50|A
TXN-000002|0007654321|T|000040.00|A
TXN-000004|0009999999|T|000020.00|A
```

`rejected.txt`（1 行、36 字节）

```text
TXN-000003|0002468101|X|000000.00|R
```

独立核算：每行 35 个字符、最后一个字符不是空格，所以是 `35 + 1 = 36` 字节；`3 × 36 = 108`、`1 × 36 = 36`；两个文件合计 4 行与表里的 4 条一致，`03 + 01 = 04`。

### 逐题回答

**1. 第四项的记录文本为什么必须和目的地标记一起改？**

因为这是两个互不相干的字段：`WS-RESULT-DESTINATION(4)` 只被 `EVALUATE` 用来选文件，`WS-RESULT-TEXT(4)` 才是写进文件的 35 个字符。程序里没有任何语句比较这两个值。

只改目的地标记（记录文本仍以 `R` 结尾）的实测结果：`accepted.txt` 变成 3 行 108 字节，但第三行是

```text
TXN-000004|0009999999|T|000020.00|R
```

也就是说，**接受文件里出现了一条自称拒绝的记录**。程序不会报错：`cobc` 返回 `0`、退出码 `0`、`SUMMARY 受理=03 拒否=01` 与"两处都改"时完全一样。记录末尾标记与所在文件是否一致，只能由写样例数据的人保证，程序不校验——这正是本课"路由由标记决定、标记由人维护"的分工。

**2. 改动后 `accepted.txt` 里三行的先后顺序由什么决定？**

由 `PERFORM VARYING WS-RESULT-NUMBER FROM 1 BY 1 UNTIL WS-RESULT-NUMBER > 4` 的处理顺序决定，也就是结果表的装入顺序（第一条、第二条、第四条）；文件是顺序写出的，先写出的行在文件前面。文件系统不重排内容，`EVALUATE` 也只决定写去哪个文件，不改变顺序。

**3. 如果把第四项的目的地标记改成 `X`（既不是 `A` 也不是 `R`）会怎样？**

实测（把 `WS-RESULT-DESTINATION(4)` 改成 `"X"`，其余不动）：

```text
オープン=受理 成功
オープン=拒否 成功
書込=受理 取引=000001
書込=受理 取引=000002
書込=拒否 取引=000003
書込=FAILED REASON=UNKNOWN_DESTINATION
クローズ=受理 成功
クローズ=拒否 成功
SUMMARY 受理=02 拒否=01
```

| 观察项 | 实测值 |
|---|---|
| 走的分支 | `WHEN OTHER`，打印 `書込=FAILED REASON=UNKNOWN_DESTINATION` |
| `accepted.txt` | 2 行、72 字节（只有第一、二条） |
| `rejected.txt` | 1 行、36 字节（只有第三条） |
| `SUMMARY` | `受理=02 拒否=01` |
| 退出码 | `1` |

第四项哪份文件都没进去，因此**两个计数之和只有 3，小于表里的 4 条**——计数不变量在这里被打破，而这恰好是本课想要的信号：`WHEN OTHER` 只置错误标志、不写文件也不计数，最后由 `IF WS-WRITE-ERROR = "Y"` 把退出码设成 1，让作业失败而不是"成功但少了一条"。另外，因为第四项是最后一条，`UNTIL ... OR WS-WRITE-ERROR = "Y"` 的提前退出没有产生额外影响；如果错误发生在第一条，后面三条都不会被写出（只留下部分输出，本课不做回滚）。

## 二、核对覆盖与重跑

### 操作与观察

使用**未修改**的原始 `lesson.cob`，运行前在两个文件里各放一行 `OLD`：

```sh
mkdir -p build
cp lesson.cob build/
cobc -x -Wall -o build/lesson_16 build/lesson.cob
printf 'OLD\n' > build/accepted.txt
printf 'OLD\n' > build/rejected.txt
wc -c build/accepted.txt build/rejected.txt   # 各 4 字节
(cd build && ./lesson_16)
echo $?                                                         # 0
wc -lc build/accepted.txt build/rejected.txt  # 各 2 行 72 字节
cat build/accepted.txt build/rejected.txt
```

| 观察项 | 运行前 | 运行后 |
|---|---|---|
| `accepted.txt` | 4 字节、内容 `OLD` | 72 字节、内容为两条样例接受记录 |
| `rejected.txt` | 4 字节、内容 `OLD` | 72 字节、内容为两条样例拒绝记录 |
| 标准输出 | — | 正常路径的 9 行，逐字节相同 |
| 退出码 | — | `0` |

连续运行两次的对照：两次的标准输出逐字节相同，两个文件仍是 72 字节，没有变成 144 字节。

### 逐题回答

**1. `OLD` 为什么不见了？是程序的哪一条语句造成的？**

因为 `OPEN OUTPUT 受理-FILE` 和 `OPEN OUTPUT 拒否-FILE` 的语义是"创建或清空重建"：文件已存在时先把它截成长度 0，再从文件开头写，所以旧内容既不保留也不追加在后面。它不是"删除再新建"（文件仍指向同一个路径），也不需要先判断文件是否存在。

**2. 如果把两次运行的结果"累加"预期成 144 字节，实际会是多少？**

实际仍是 72 字节（每个文件）。`OPEN OUTPUT` 每次运行都把文件内容截断重建，两次运行不会叠加，第二次写出的 4 条覆盖第一次写出的同样 4 条。这种"重跑得到同一份结果"只在本程序每次都写出相同条数的前提下成立——它来自覆盖语义加上固定的表上界，不是程序做了幂等检查；如果哪天只写出了 3 条，第 4 条旧记录不会自动消失（本课不清理半截输出）。

**3. 如果运行前把 `accepted.txt` 建成目录，程序会输出什么？**

实测（`mkdir accepted.txt` 后运行）：

```text
オープン=受理 失敗 状態=37
```

退出码 `1`，`rejected.txt` 没有被创建（程序在第一个 `IF WS-受理-STATUS NOT = "00"` 里就 `MOVE 1 TO RETURN-CODE`、`STOP RUN` 了），也没有任何记录被写出。状态码 `37` 是 GnuCOBOL 状态码表里的"权限被拒绝"类错误；本机实测"目标是目录""目标是只读文件（0444）""目录不可写"三种情况都得到 `37`。这段行为只证明"打开失败被检出并返回 1"，不代表生产环境里所有写盘故障都能这样被及时检出（见 README 的"证据来源与验证范围"）。
