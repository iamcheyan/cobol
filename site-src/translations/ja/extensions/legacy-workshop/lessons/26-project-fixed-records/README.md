# 総合プロジェクト2：固定幅レコード、REDEFINES、テーブル

## 学習目標

固定幅入力、レコードのスライス、REDEFINES、OCCURS、検証、レポート出力を使って、ホストのバッチ処理におけるデータレイアウトを練習します。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラム内で対応する宣言箇所や実行箇所を見つけられるようになります。構文を暗記するだけではなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L26.COB`](./L26.COB) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文と実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/26-project-fixed-records/L26.COB
cobc -x -Wall -o build/l26 extensions/legacy-workshop/lessons/26-project-fixed-records/L26.COB
./build/l26
```

期待される観察結果：付属の FIXEDREC.COB と TX-REC.CPY に、固定長の取引レコードが示されています。

コンパイラが形式や列位置に関するエラーを報告した場合は、まず第7、8、12、72列を確認してください。次に、ピリオド、変数の PIC、スコープを終了する文を確認します。`-Wall` は追加の警告を表示します。警告も内容を理解してから対処するか決めてください。

## 各部分を理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` は、プログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすくするための段落名にすぎず、自動的に繰り返し実行されるわけではありません。
4. 各文はソースの順序に従って実行されます。制御フロー文で経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更演習

make run-fixed を実行します。フィールド幅を変更してファイルの列位置を確認し、入力を16進表示または列ごとの可視化と照らし合わせてください。

変更のたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つにして、変更前後の出力を記録します。

## cobol.nvim で学ぶ

プラグインのルーラーで7/8/12/72列を確認します。REDEFINES/OCCURS にはレコード計算機を使い、ABI の制約も確認してください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかは、GNUCOBOL で実際にコンパイルした結果を基準に判断してください。
