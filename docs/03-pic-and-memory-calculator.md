# 第 3 课：数据层级与 PIC 内存计算器 (Data & PIC Size Calculator)

在银行业与大型机系统的日常维护中，**定长文件接口（Fixed-Length File）**与**定长报文协议（如 ISO 8583 银行卡交易报文）**是最核心的数据交换载体。

这类系统要求每个数据字段的字节数、偏移量必须分毫不差。如果某个结构体总和算错 1 个字节，整张文件成千上万行数据就会全面错位报废。传统开发中，程序员只能拿计算器对着 `PIC` 子句一位位做口算，繁琐且极易出错。

本课教你掌握 COBOL 数据类型的底层内存分配规则，并使用插件的一键换算与排布报表功能。

---

## 1. 核心理论：COBOL 数据类型与内存换算秘籍

COBOL 使用 `PIC`（Picture，图像子句）描述数据的存储格式。

### 1.1 基本类型与字符型

| 声明形式 | 含义与展开 | 实际占用物理内存 |
|---|---|---|
| `PIC X(20)` | 20 位定长任意字符（字母/数字/符号） | **20 字节** |
| `PIC A(10)` | 10 位字母字符 | **10 字节** |
| `PIC 9(05)` | 5 位未压缩字符型数字（如 `"12345"`） | **5 字节**（每个字符 1 字节） |
| `PIC 9(05)V99` | 7 位数值（5 位整数 + 2 位小数），`V` 是虚拟隐式小数点 | **7 字节**（`V` 不占任何物理存储空间！） |
| `PIC S9(05)` | 带有代数正负号的 5 位数字 | 默认 **5 字节**（符号被编码进最高位或最低位的半字节中，不占额外字节；除非显式声明 `SIGN IS SEPARATE`） |
| `PIC S9(4) COMP-1` / `COMP-2` | 单精度/双精度浮点 | 常见 ABI 下分别为 **4 / 8 字节** |

---

### 1.2 大型机看家法宝：`COMP-3`（压缩十进制 Packed Decimal）

`COMP-3`（在 ANSI 标准中叫 `PACKED-DECIMAL`）是 IBM 大型机和金融账务系统的绝对核心。

#### 为什么不用普通 Float 浮点数？
在银行记账中，`0.1 + 0.2` 绝不能等于 `0.30000000000000004`。浮点数存在二进制舍入误差，而 `COMP-3` 采用 **BCD（Binary Coded Decimal）** 编码，具备 100% 精确的十进制表示，且计算速度极高。

#### 物理存储原理
* 普通字符数字一个字符占 1 字节（8 位，即 1 个 Byte）；
* 一个 Byte 可以拆成两个 4 位的半字节（**Nibble**，`0x0` ~ `0xF`）；
* 每一个数字 `0` ~ `9` 只需要 4 个位就能表示（比如 `5` 就是二进制 `0101`）；
* 一个 Byte 可以紧凑存放 **2 个十进制数字**！
* 最后一个半字节用来存放符号（`C` 代表正数 `+`，`D` 代表负数 `-`，`F` 代表无符号）。

#### 换算公式
$$\text{总字节数} = \lceil \frac{\text{有效数字位数} + 1}{2} \rceil$$

* 例如 `PIC S9(7) COMP-3`：7 位有效数字，加 1 个符号位共 8 个半字节，占 **4 字节**（原先字符形式需要 7 字节，节省了近一半空间！）。
* 例如 `PIC S9(7)V99 COMP-3`：7 + 2 = 9 位数字，加 1 个符号位共 10 个半字节，占 **5 字节**。

---

### 1.3 `COMP` / `BINARY`（纯二进制整型）

`COMP`（或 `BINARY`）以原生 CPU 机器字补码形式存储：
* **1 ~ 4 位数字**（如 `PIC S9(4) COMP`）：占 **2 字节**（半字 Half-word，范围 -32,768 ~ +32,767）
* **5 ~ 9 位数字**（如 `PIC S9(9) COMP`）：占 **4 字节**（全字 Full-word，范围约 -20 亿 ~ +20 亿）
* **10 ~ 18 位数字**（如 `PIC S9(18) COMP`）：占 **8 字节**（双字 Double-word，64 位大整数）

## 2. 插件配备的计算器利器

1. **行尾单项实时提示**：光标停在变量行，行尾以灰白斜体实时提示单项字节与用法（如 `/* 20 B */`，`/* 5 B COMP-3 */`）。
2. **`01` 根记录递归统计**：光标停在 `01` 行，自动向下汇总所有子字段的字节和，并在行尾提示：`/* Total: 398 Bytes (6 fields) */`。
3. **内存排布 ASCII 报表（`<leader>cr` / `:CobolCalcRecord`）**：居中弹出格式化大表，列出每个字段从 `+0` 起始的精确内存偏移量与类型。

## 3. 实操任务清单 (Step-by-Step)

打开测试文件开始演练：

```bash
cd /home/tetsuya/development/cobol
nvim INPUTCSV.COB
```

### 任务 3.1：观察单项 PIC 字节实时换算
1. 移动光标至第 57 行：
   ```cobol
              05  IN-EMPLOYEE-ID         PIC X(20).
   ```
   **观察行尾**：自动显示 `/* 20 B */`；
2. 移动光标至 `WS-TOTAL-SALARY`：
   ```cobol
          05  WS-TOTAL-SALARY        PIC S9(9) COMP-3 VALUE ZERO.
   ```
   **观察行尾**：自动显示 `/* 5 B COMP-3 */`！
   - *思考*：7 位整数加 2 位小数共 9 位数字，加 1 个符号半字节共 10 个半字节，正好占用 5 个物理字节！
3. 移动光标至 `WS-RECORD-COUNT`：
   ```cobol
          05  WS-RECORD-COUNT        PIC 9(5) COMP VALUE ZERO.
   ```
   **观察行尾**：显示 `/* 2 B COMP */`。

### 任务 3.2：观察 `01` 顶级结构体总字节递归汇总
1. 移动光标至第 26 行：
   ```cobol
          01  INPUT-RECORD           PIC X(256).
   ```
   **观察行尾**：自动显示 `/* Total: 256 Bytes (1 fields) */`；
2. 移动光标至第 56 行：
   ```cobol
          01  WS-INPUT-FIELDS.
   ```
   **观察行尾**：自动提示 `/* Total: 398 Bytes (6 fields) */`！
   - 插件自动穿透遍历了内部的所有嵌套成员（`IN-EMPLOYEE-ID`, `IN-FULL-NAME`, `IN-AGE`, `IN-SALARY`, `IN-DEPARTMENT`, `IN-JOIN-DATE`），把每一个叶子字段的字节相加，得出该结构体在内存中占用 398 个字节。

### 任务 3.3：呼出居中内存排布报表（`<leader>cr`）
定长接口联调时，外部系统经常问：“你的 `IN-SALARY` 字段从第几个字节开始？占几个字节？”
1. 保持光标停留在 `01 WS-INPUT-FIELDS` 上；
2. 按下快捷键 **`<leader>cr`**（或在命令行输入 `:CobolCalcRecord`）；
3. **观察屏幕效果**：屏幕居中弹出一个格式优雅的 ASCII 表格：
   ```text
   ┌────────────────────────────────────────────────────────────────────────┐
   │ COBOL Record Memory Layout: 01 WS-INPUT-FIELDS                         │
   ├──────────────────────────────┬─────┬─────────┬──────────┬──────────────┤
   │ Field Name                   │ Lvl │  Offset │     Size │ Usage / Pic  │
   ├──────────────────────────────┼─────┼─────────┼──────────┼──────────────┤
   │ IN-EMPLOYEE-ID               │ 05  │      +0 │     20 B │ PIC X(20)    │
   │ IN-FULL-NAME                 │ 10  │     +20 │     80 B │ PIC X(80)    │
   │ NAME-LENGTH                  │ 10  │    +100 │      2 B │ PIC 99       │
   │ IN-AGE                       │ 05  │    +102 │     10 B │ PIC X(10)    │
   │ IN-SALARY                    │ 05  │    +112 │     30 B │ PIC X(30)    │
   │ CSV-LINE                     │ 05  │    +142 │    256 B │ PIC X(256)   │
   ├──────────────────────────────┴─────┴─────────┴──────────┴──────────────┤
   │ Total Elementary Fields: 6                   Total Size: 398 Bytes     │
   └────────────────────────────────────────────────────────────────────────┘
   ```
   *(注：具体偏移量数值根据代码实际定义列出)*
4. 表格中清晰列出了每个字段的物理起始偏移（Offset）、单项大小（Size）与定义；
5. 按下 **`q`** 或 **`<Esc>`** 随手关闭弹窗，继续编写代码。

## 4. 本课速查总结

| 快捷键 / 命令 | 作用说明 |
|---|---|
| 行尾虚拟文本 | 自动实时展示当前行字段物理字节数（如 `/* 20 B */`，`/* 5 B COMP-3 */`） |
| `01` 行行尾提示 | 自动递归向下累加并显示整个结构体的总字节数（如 `/* Total: 398 Bytes (6 fields) */`） |
| `<leader>cr` | 居中弹出当前 `01` 记录的物理内存排布与偏移量 ASCII 报表（Cobol Record Layout） |
| `:CobolCalcRecord` | 用户命令，等价于 `<leader>cr` |
| `:CobolFormatCase` | 将当前行、Visual 选区或整个文件中的 COBOL 保留字规范为大写 |
| `za` / `zc` / `zo` | 折叠、关闭或打开 Division、Section、Paragraph 和数据记录结构 |
| `q` 或 `<Esc>` | 随手关闭排布报表浮窗 |
