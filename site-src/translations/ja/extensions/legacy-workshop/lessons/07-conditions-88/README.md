# 条件判断、条件名与布ール値の意味

## 学習目標

関係条件、複合 AND/OR/NOT、88レベル条件名、SET ... TO TRUE、条件名が独立した記憶領域を占めないこと。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L07.COB`](./L07.COB) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートから次を実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/07-conditions-88/L07.COB
cobc -x -Wall -o build/l07 extensions/legacy-workshop/lessons/07-conditions-88/L07.COB
./build/l07
```

期待される観察：88レベル条件名を使って状態遷移を表現する。

コンパイラが形式や列位置に関するエラーを報告した場合は、まず7、8、12、72列目を確認してください。次に、ピリオド、変数の PIC、スコープ終端文を確認します。`-Wall` は追加の警告を表示します。警告も内容を理解したうえで、対処するかどうか判断してください。

## 各部の理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名であり、自動的に繰り返し実行されるわけではありません。
4. 各文はソースの順番に実行されます。制御フロー文によって処理経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更演習

WS-FAILED 条件名を追加してください。`IF WS-STATUS = "Y"` と `IF WS-READY` の読みやすさも比べてみましょう。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つに絞り、変更前後の出力を記録します。

## cobol.nvim を使った学習

条件名から `gd` でホストフィールドに戻ります。アウトラインと折りたたみを使って、条件フィールドの階層を確認してください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使います。プログラムがコンパイルできるかどうかは、GNUCOBOL による実際のコンパイル結果で判断してください。
