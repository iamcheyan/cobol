# 環境の準備と最初のプログラム

## 学習目標

GNUCOBOL をインストールし、cobc と cobcrun を見分け、コンパイラのバージョンを確認し、ソースファイル、実行可能ファイル、ランタイムの関係を理解します。

この課を終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L00.COB`](./L00.COB) を開きます。この課のソースファイルは固定形式を使用します。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースコードを1行ずつ読み、その後実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/00-environment/L00.COB
cobc -x -Wall -o build/l00 extensions/legacy-workshop/lessons/00-environment/L00.COB
./build/l00
```

期待される結果：挨拶が2行表示されます。

コンパイラが形式や列位置のエラーを報告した場合は、まず第 7、8、12、72 列を確認します。次に、ピリオド、変数の PIC、スコープ終端の文を確認しましょう。`-Wall` は追加の警告を表示します。警告も内容を理解してから、対処するかどうかを判断してください。

## 各部分を理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言します。`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。この課にフィールド宣言がある場合は、レベル番号と PIC を確認しましょう。
3. `PROCEDURE DIVISION` は実行の開始位置です。`0000-MAIN` は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文によって経路が変わるか、`STOP RUN` でプロセスが終了するまで、ソースコードの順に実行されます。

## 変更練習

2行目を自分の名前に変更します。次に、わざと DISPLAY のつづりを間違え、コンパイル時のエラーと実行時の出力をそれぞれ観察しましょう。

変更するたびに、構文チェック、コンパイル、実行をもう一度行います。一度に変更する概念は1つだけにし、変更前後の出力を記録しましょう。

## cobol.nvim で学ぶ

Neovim でこの課のソースファイルを開き、filetype と固定形式のルーラーを確認してから、:CobolLint で検証します。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使います。プログラムがコンパイルできるかどうかの判断基準となるのは、GNUCOBOL による実際のコンパイル結果です。
