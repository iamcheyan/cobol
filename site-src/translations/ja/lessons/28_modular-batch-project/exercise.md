# 第 28 課の練習：モジュールインターフェースと再現可能なビルド

本節では、第 23〜28 課で扱った内容だけを使います。Copybook、`CALL ... USING BY REFERENCE`、`LINKAGE SECTION`、段落、`EVALUATE`/`IF`、`STRING`、バッチビルドスクリプトです。

## 変更練習（参考解答は `answer.md`）

2 つとも元のソースから始めます。変更後は `./build.sh run` を再実行してください。スクリプトが 2 つのサブプログラムを再コンパイルし、メインプログラムを再リンクして初めて変更が反映されます。

```sh
./build.sh check      # 组合语法检查
./build.sh run        # 重新编译、链接并在 build/ 里运行
echo $?               # 退出码
./build.sh clean      # 清理 build/
```

1. `1300-POST-OVERDRAFT` の `2000.00` を `1000.00` に変更します。出金が拒否から成功に変わること、最終残高と `記帳`/`拒否` 件数が変わること、`build/batch.log` の 3 件目の取引イベントの状態を確認します。
2. 元のソースに戻してから、`1400-POST-UNKNOWN-TYPE` の種別を `"X"` から `"D"` に変更します。計上モジュールが `POSTED` を返し、口座報告に入金が反映され、ログの取引番号が引き続き `004` であることを確認します。

**正しさの判定基準：** 変更ごとに標準出力、`build/batch.log`、件数の不変条件（`記帳 + 拒否 = 5`）をすべて確認します。テストフィクスチャだけ変更したり、再リンクせず再実行したりしても完了とは見なしません。2 つの課題とも制御の流れを説明してください。`CALL` はどの段落で呼ばれるか、`GOBACK` はどこへ制御を戻すか、どちら側が件数を増やすか。

参考解答は `answer.md` にあります。

## 応用練習（解答なし）

サンプル取引をファイル入力に変更し、「読み込み / EOF / 不正レコードの分類」を独立したモジュールへ移します。口座、取引、状態の Copybook を唯一のインターフェース定義として使い、Copybook を変更した後に影響を受けるモジュールをすべて再コンパイルしてリンクする方法を説明してください。

ソース、`build.sh` のコマンド、実際の標準出力と `batch.log` を提出し、件数を所有するモジュールと読み取り専用のモジュールを説明します。業務拒否をコンパイル失敗のように見せず、Copybook にすでに定義されているレコードレイアウトを重複定義しないでください。本題には解答がありません。
