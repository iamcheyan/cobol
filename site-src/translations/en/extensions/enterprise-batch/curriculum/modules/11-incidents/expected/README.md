# Module 11 Expected Results (Independent Calculation)

`expected/` is generated by `instructor/modules/11-incidents/tools/gen_course.py`. The generator **reimplements** validation for the frozen contract (CUSTOMER 27B / ACCOUNT 47B / TRANSACTION 55B) and the 1:N overdraft/orphan rules; it **does not read any course program output**. Rules:

- **JOB002 validation**: length ≠ 55, a key/amount is nonnumeric, or the transaction number is all spaces → structural error (whole batch RC8); direction is not C/D, status is not N, business date does not match, or amount is 0 → business rejection (RC4, per record).
- **JOB005 matching**: account does not exist → ORPHAN; debit would make closing balance <0 → OVERDRAFT; otherwise `closing = opening + credit − debit`. Account and transaction streams must be ordered, or RC8.
- **Control totals**: `opening_total + credit_total − debit_total = closing_total`.

| File | Contents |
|---|---|
| `normal.control.txt` | Baseline control totals (received=4, closing_total=1475) |
| `normal.closing.txt` | Baseline closing Master (acc1 1300／acc2 150／acc3 25) |
| `incidents.txt` | For each event: `as_found_rc / desired_rc / publish_before / publish_after` |
| `customer-v1.txt` | CUSTOMER v1 status extract (`STATUS\|id\|A/D`) |
| `enterprise-class-v1.txt` | Enterprise customer classification v1 extract (`CLASS\|id\|A`) |
| `enterprise-class-v2.txt` | Enterprise customer classification v2 extract (`CLASS\|id\|A1`) |

An event in `incidents.txt` with `as_found_rc=0` and `publish_before=yes` represents a **defect in the current system**: the system published an incorrect result with RC0. The corresponding `desired_rc=8` and `publish_after=no` are the contract behavior **required after the fix**. Which events fall into this category is determined by the contract data itself and is not identified here (see the instructor package for root causes).

`check.py` uses these independent expectations as its assertion source; it never treats a program's own stdout as the correct answer.
