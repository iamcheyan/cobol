# モジュール化されたプロジェクト、コンパイル、実行環境

## 学習目標

ソースファイルとオブジェクトファイル、モジュール間の依存関係、COPY のパス、動的ライブラリの検索、環境変数、可搬性、ビルドディレクトリについて学びます。

このレッスンを終えたら、上記の用語を自分の言葉で説明し、小さなプログラムの中から関連する宣言や処理箇所を見つけられるようになっているはずです。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L19.COB`](./L19.COB) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読んでから、実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/19-modules-environment/L19.COB
cobc -x -Wall -o build/l19 extensions/legacy-workshop/lessons/19-modules-environment/L19.COB
./build/l19
```

期待される観察結果：プログラムは、プロジェクトがソースコード、Copybook、データ、ビルドスクリプトで構成されていることを知らせます。

コンパイラが書式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認してください。次に、ピリオド、変数の PIC、スコープを終了する文を確認します。`-Wall` は追加の警告を表示します。警告も内容を理解してから、対応するかどうかを判断してください。

## 各部分の理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` は、プログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言があれば、階層番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文で経路が変わるか、`STOP RUN` でプロセスが終了するまで、ソースコードの順に実行されます。

## 変更練習

サンプルをメインプログラム、サブプログラム、Copybook に分割します。それぞれのファイルをコンパイルコマンドにどのように含めるか記録してください。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つだけにし、変更前後の出力を記録します。

## cobol.nvim で学ぶ

Neovim をリポジトリのディレクトリから起動し、プラグインがプロジェクトのルートディレクトリと Copybook の検索パスを使えるようにします。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかは、GNUCOBOL による実際のコンパイル結果で判断してください。
