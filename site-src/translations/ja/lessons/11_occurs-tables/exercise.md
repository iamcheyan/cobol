# 第 11 課演習：OCCURS 固定容量テーブル

この課で使用するのは、第 11 課で学んだ内容だけです。`OCCURS` 固定容量テーブル、通常の数値添字、`PERFORM VARYING` による走査、`EVALUATE` 分岐、`DISPLAY` 出力を使います。

## 変更演習（参考解答は `answer.md`）

3 問はそれぞれ、本課の元の `lesson.cob` から独立して変更してください。別の問題の変更を重ねないでください。各問で README の「実行して確認」にあるコマンドを実行します。

```sh
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_11 lesson.cob
./build/lesson_11
```

1. **金額を変更する。** `1000-LOAD-TABLE` で `WS-TXN-AMOUNT(4)` の設定値を `20.00` から `35.00` に変更し、それ以外の文は変更しません。再コンパイルして実行し、どの出力行が変わるか、どの行が変わらないか、期末残高が新しい値になる理由を書いてください。
2. **項目を追加する。** `WS-TRANSACTION-ENTRY OCCURS 4 TIMES` を 5 項に拡張し、`WS-LAST-SAMPLE` の初期値を 5 に変更して、4 項目の後に5項目目を追加します。取引コードは `C`、金額は `10.00` です。容量、ロード済み項目数、走査上限をすべて 5 にしてください。実行後、出力全体を示し、期末残高を確認します。
3. **範囲外アクセスを観察する。** `WS-LAST-SAMPLE` の初期値だけを 4 から 5 に変更し、テーブル容量は 4 のままにします（変更する数字はこの1つだけです）。
   - まず `cobc -fsyntax-only lesson.cob` とコンパイルコマンドを使い、コンパイラーがエラーを報告するか確認します。
   - プログラムを実行し、5項目目に何が表示されるか、期末残高が記帳規則で計算した値と一致するか記録します。
   - 5項目目のバイトがどこから来たか、バッチ処理で「走査上限だけを増やす」ことが危険な理由を説明します。

## 学んだことを応用する（解答なし）

固定容量5項目の口座残高テーブルを定義してください。各項目は口座番号 `PIC X(10)` と残高 `PIC 9(7)V99` を持ちます。少なくとも3件をロードし、通常の数値添字を使って先頭から最後のロード済み項目まで走査します。口座番号と残高を項目ごとに表示し、最後に処理件数と残高合計を表示してください。

制約：本課の `OCCURS`、通常の数値添字、`PERFORM VARYING`、`EVALUATE`、`DISPLAY` および既習の基本文だけを使います。`INDEXED BY`、`SEARCH`、ファイル、データベースは使いません。ソース、実際の出力、終了コードを提出してください。容量、ロード済み項目数、走査上限の3つの数値を示し、ロード済み位置と未ロード位置の違いを説明してください。
