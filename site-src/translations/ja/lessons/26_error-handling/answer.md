## A00002 の金額フィールドを修正する

**基準状態：** 元の `transactions.txt` フィクスチャのコピー `build/transactions.txt`（5 行、62 バイト）。

**変更：** 2 行目だけを `A00002|00X50` から `A00002|00150` に変更します。行は 12 バイトのままで、残り 4 行はそのままです。

```sh
(cd build && ./lesson_26); echo "rc=$?"
```

**プロセスの終了コード：** `0`。

**標準出力（実測、7 行）：**

```text
受理口座=A00001
受理口座=A00002
拒否口座=A00003 REASON=ZERO_AMOUNT
受理口座=A00004
拒否口座=A00005 REASON=BAD_WIDTH
集計 入力=005 受理=003 拒否=002
システムエラー=N
```

基準状態では 2 行目が `拒否口座=A00002 REASON=BAD_AMOUNT` ですが、今回は `受理口座=A00002` に変わります。それ以外の行とレコード順は同じです。集計も `受理=002 拒否=003` から `受理=003 拒否=002` に変わります。`システムエラー` は `N` のままです。

**`build/accepted.txt`（3 行、1 行 13 バイト = 39 バイト）：**

```text
A00001|00125
A00002|00150
A00004|00999
```

`A00002|00150` は**2 行目**にあります。レコードは入力順に書き出されます。先頭の `A00001` の後、`A00004` の前に、フィクスチャ 2 行目の `A00002` が今回は受理されるためです。

**`build/rejected.txt`（2 行：19 + 17 = 36 バイト）：**

```text
A00003|ZERO_AMOUNT
A00005|BAD_WIDTH
```

基準状態にあった `A00002|BAD_AMOUNT` はなくなり、ゼロ金額と短いレコードの 2 件だけが残ります。

**理由と確認：**

- `00150` は 5 桁の数字で、ゼロではありません。幅（12 バイト）、区切り文字（7 列目が `|`）、金額の検査を順に通るため、`BAD_AMOUNT` では拒否されず、受理ファイルに書かれます。
- 拒否件数は 3 から 2 に減りますが、終了コードは 0 のままです。業務拒否が決めるのはレコードの行き先だけで、**バッチの終了コードは変えません**。今回のファイル操作はすべて状態 `00` なので、`WS-SYSTEM-ERROR` は `N`、`RETURN-CODE` は 0 のままです。
- 不変条件を確認します。`入力 005 = 受理 003 + 拒否 002`。`accepted.txt` は 3 行、`rejected.txt` は 2 行で、それぞれの件数とも一致します。各レコードの行き先は 1 つだけです。
