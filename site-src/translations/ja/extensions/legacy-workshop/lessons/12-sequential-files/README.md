# 順次ファイル、SELECT/FD、READ/WRITE

## 学習目標

ASSIGN、ORGANIZATION SEQUENTIAL、FDレコード、OPEN INPUT/OUTPUT/EXTEND、READ、WRITE、AT END、CLOSE。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラム内で対応する宣言や実行箇所を見つけられるようになります。構文を丸暗記するのではなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L12.COB`](./L12.COB)を開きます。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文と実行文はArea Bに記述します。まずソースを1行ずつ読み、それから実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/12-sequential-files/L12.COB
cobc -x -Wall -o build/l12 extensions/legacy-workshop/lessons/12-sequential-files/L12.COB
./build/l12
```

期待される観察結果：このレッスンでは、重要なファイル制御宣言がスクリーンショットの一部に隠れてしまわないよう、ファイルI/Oを含む完全な例を使用します。

コンパイラが形式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認してください。次にピリオド、変数のPIC、スコープを終了する文を確認します。`-Wall`は追加の警告を表示します。警告も内容を理解してから、対処するかどうかを判断してください。

## 順を追って理解する

1. `IDENTIFICATION DIVISION`はプログラム単位を宣言し、`PROGRAM-ID`はコンパイラが認識するプログラム名です。
2. `DATA DIVISION`はプログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言があれば、レベル番号とPICを確認してください。
3. `PROCEDURE DIVISION`は実行の入口です。`0000-MAIN`は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文によって経路が変わるか、`STOP RUN`でプロセスが終了するまで、ソースコードの順に実行されます。

## 変更練習

下にinput.txtを作成し、READMEにあるSELECT/FDの例を少しずつこのレッスンのプログラムに追加します。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つだけにし、変更前後の出力を記録します。

## cobol.nvimで学ぶ

プラグインを使ってFD/01レコードの階層を確認し、READを処理する段落間を移動します。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に`cobc --version`を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に役立ちます。プログラムをコンパイルできるかどうかの根拠となるのは、GNUCOBOLによる実際のコンパイル結果です。

## 実行可能な順次ファイル演習

このディレクトリには、完全な[`FILE-DEMO.COB`](./FILE-DEMO.COB)と[`input.txt`](./input.txt)もあります。プログラムは現在の作業ディレクトリから入力ファイルを探すため、このレッスンのディレクトリでコンパイルして実行してください。

```sh
mkdir -p build
cobc -x -Wall -o build/file-demo FILE-DEMO.COB
./build/file-demo
```

READは論理レコードを1件ずつ読み込みます。`AT END`はファイル末尾を処理し、`FILE STATUS`は成功または失敗の状態を示します。`input.txt`を削除してOPENのエラー経路を確認しましょう。次にレコード長、行末コード、空行を変更し、入力に関する前提を検証してください。
