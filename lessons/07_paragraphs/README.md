# 第 07 课：Paragraph 命名段落——把批次主流程拆成可命名阶段

一个夜间批次通常不是一长串平铺的语句，而要分成初始化、处理、汇总几个职责清晰的阶段，方便维护者定位问题。本课把平铺的过程改写成命名段落，用 `PERFORM 段落名` 组织主流程，并观察段落之间如何共享同一份工作存储数据，以及调换调用顺序为什么会改变结果。

## 为什么现在学

你已经能用循环和分支完成一笔处理，但所有语句还堆在 `PROCEDURE DIVISION` 里，读代码的人很难一眼看出“哪一段是初始化、哪一段是计算”。缺口是结构：真实批次要按阶段命名、按顺序调用，并且要能说清哪些阶段之间存在数据依赖。本课引入命名段落和 `PERFORM 段落名`，把主流程变成一张可读的调用清单。

## 本课完成后的能力与边界

学完本课后，你可以：

- 在 `PROCEDURE DIVISION` 中定义命名段落，并让段落名从 Area A 开始。
- 用 `PERFORM 段落名` 执行段落，并说明控制何时返回 `PERFORM` 之后的语句。
- 把批次主流程拆成初始化、处理、结束汇总三个阶段，并在主段落中排序调用。
- 解释段落为什么共享当前程序的 `WORKING-STORAGE`，以及调换调用顺序后最终余额为什么会变。
- 说明同一程序内的 `PERFORM` 与之后要学的 `CALL` 子程序不是一回事。

边界：本课只用固定在源码里的金额，不读文件、命令行参数或数据库，也不使用 `CALL` 调用独立子程序。跨程序接口与参数契约在第 23–25 课（Copybook、`CALL`、`USING`）展开，记录级错误处理在第 26 课展开。

## 运行环境

- GnuCOBOL 3.2.0，默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不依赖数据库或附加工具。
- 语法检查与编译在 `build/` 下生成可执行文件，可直接删除重来。

## 段落和 PERFORM

段落名是过程名，写在 `PROCEDURE DIVISION` 中；仓库的固定格式要求段落名从 Area A 开始。`PERFORM 1000-INITIALIZE` 执行该段落中的语句，到下一个段落或过程范围末端后，控制返回 `PERFORM` 之后的那条语句。段落共享当前程序的 `WORKING-STORAGE`，不会因此创建独立程序或新的数据副本。

本例把 `0000-MAIN` 放在第一个位置。程序从主段落开始，依序 PERFORM 初始化、计算和汇总；`STOP RUN.` 放在段落定义之前，结束普通顺序执行，避免主流程落进后面的段落定义。三个被调用段落各自只负责一项工作。

段落名是团队可读性约定，不是业务逻辑。GnuCOBOL 手册允许由字母、数字、连字符和下划线组成的过程名，例如 `0100-Read-Transaction`；名字不能以连字符或下划线开头或结尾。

## 完整示例

完整源码见 [`lesson.cob`](./lesson.cob)，按固定格式编写。

示例使用固定金额：期初 `1000.00`、存款 `125.50`、取款 `40.10`，处理段落算出期末余额 `1085.40`。

| 段落 | 职责 | 关键语句 |
|---|---|---|
| `0000-MAIN` | 按流程调用三个阶段；收到返回后报告批次完成 | `PERFORM ...`、`DISPLAY`、`STOP RUN` |
| `1000-INITIALIZE` | 清零期末余额字段 | `MOVE ZERO TO ...` |
| `2000-PROCESS` | 计算期末余额并显示 | `COMPUTE ...`、`DISPLAY` |
| `9000-FINALIZE` | 显示结束阶段与最终余额 | `DISPLAY` |

每个 `PERFORM` 使用的名字都对应一个段落定义。主流程先完成初始化，再计算，最后汇总；因此 `9000-FINALIZE` 能读到 `2000-PROCESS` 写入的共享余额字段。

## 执行顺序逐步解析

1. 程序到达第一个段落 `0000-MAIN`。
2. `PERFORM 1000-INITIALIZE` 输出 `段階=INITIALIZE`，并把期末余额置零；段落结束后返回主流程。
3. `PERFORM 2000-PROCESS` 输出 `段階=PROCESS`，计算 `1000.00 + 125.50 - 40.10 = 1085.40`，输出 `0001085.40`；随后返回主流程。
4. `PERFORM 9000-FINALIZE` 输出 `段階=FINALIZE` 和共享字段 `最終残高=0001085.40`，再返回主流程。
5. 主流程输出 `バッチ=COMPLETE` 并执行 `STOP RUN.`。没有执行流落入后面的段落定义。

句点结束 COBOL 句子和尚未结束的语句作用域。本例在每个被调用段落的最后一条语句放句点，主段落的句点放在 `STOP RUN` 之后。

## 运行与观察

本课不读取终端、文件或数据库，因此在本课目录或任意目录执行结果相同。下面按本课目录说明。

**输入：** 无。三个金额是程序内固定数据，全部来自 `WORKING-STORAGE` 的 `VALUE`。

**命令及作用：**

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob                  # 只做语法检查，不生成可执行文件
cobc -x -Wall -o build/lesson_07 lesson.cob    # 编译并生成可执行文件
./build/lesson_07                              # 运行程序，输出写到标准输出
echo $?                                        # 查看退出码
rm -rf build                                   # 清理生成的可执行文件
```

**预期结果：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出 | 6 行，见下方代码块；阶段顺序为 INITIALIZE → PROCESS → FINALIZE |
| 进程退出码 | `0` |

```text
段階=INITIALIZE
段階=PROCESS
期末残高=0001085.40
段階=FINALIZE
最終残高=0001085.40
バッチ=COMPLETE
```

**输出字段对照（日文输出 → 含义）：** `段階` = 当前阶段；`期末残高` = 处理段落算出的期末余额；`最終残高` = 汇总阶段读到的余额；`バッチ=COMPLETE` = 批次完成。余额字段是 `PIC 9(7)V99`，`1085.40` 按 7 位整数位补零显示为 `0001085.40`，隐含小数点在显示时省略。

**实际观察到的环境细节：** 在本工作区运行可执行文件时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境的链接库版本警告，不是本程序的业务输出；其触发组件尚未定位。程序输出在标准输出，退出码为 0。

## 在企业中的位置

批次程序常按初始化、输入、校验、业务处理、输出和结束清理划分过程。段落能让维护者快速定位职责，但所有段落仍共享程序数据；必须明确哪些段落读写哪些字段，并保持调用顺序与数据依赖一致，否则会出现本课第二题那种“处理结果被后执行的初始化清掉”的问题。

跨程序接口属于 `CALL` 的范围，不应把内部段落误当作独立子程序。真正需要参数契约和独立调用时，见第 24、25 课。
