# 表、OCCURS、添字と SEARCH

## 学習目標

固定長テーブル OCCURS、INDEXED BY、添字とインデックスの違い、SEARCH による逐次検索、SEARCH ALL のソート条件。

このレッスンの終了時には、上記の用語を自分の言葉で説明し、小さなプログラムの中で該当する宣言箇所や実行箇所を見つけられるようになることを目指します。構文を暗記するだけではなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L10.COB`](./L10.COB) を開いてください。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/10-tables-occurs-search/L10.COB
cobc -x -Wall -o build/l10 extensions/legacy-workshop/lessons/10-tables-occurs-search/L10.COB
./build/l10
```

期待される動作：3件の成績を入力し、1件ずつ走査します。

コンパイラが形式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認してください。次に、ピリオド、変数の PIC、スコープ終端文を確認します。`-Wall` は追加の警告を表示します。警告も内容を理解したうえで、対処するかどうかを判断してください。

## 各部の理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言がある場合は、階層番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースの順序に従って実行され、制御フロー文で経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更演習

4件目を追加してください。SEARCH ALL を試す前にソートし、二分探索が成立する条件を理解してください。

変更のたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つにし、変更前後の出力を記録してください。

## cobol.nvim で学ぶ

プラグインのレコード計算機で OCCURS の総長を確認できます。インデックス変数の位置で gd を使ってください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認してください：`:set filetype?`。次に `cobc --version` を確認します。プラグインは移動、レイアウトのヒント、診断に使います。プログラムがコンパイル可能かどうかは、GNUCOBOL で実際にコンパイルした結果に基づいて判断してください。
