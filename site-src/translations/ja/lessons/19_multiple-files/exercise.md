# 第 19 課の練習：入力ストリームと EOF の独立性

この節では、第 15〜19 課で学んだ内容だけを使います：順次ファイルの `SELECT`/`OPEN`/`READ`/`CLOSE`、`FILE STATUS`、`AT END`、`PERFORM UNTIL`、`IF`、`DISPLAY`。

## 改変練習（参考解答は `answer.md`）

どちらの変更も**一時ディレクトリ内のフィクスチャのコピーだけ**に行い、リポジトリ内の `accounts.txt` / `transactions.txt` は変更しないでください。まず一時ディレクトリを用意します：

```sh
scratch=$(mktemp -d)
cp lesson.cob accounts.txt transactions.txt "$scratch/"
cd "$scratch"
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o lesson_19 lesson.cob
```

1. コピーした `transactions.txt` の末尾 2 レコードを削除し、先頭 2 レコードだけを残します。`./lesson_19` を実行し、主ファイルの 3 レコードすべてが引き続き読まれ、取引件数が 2 になることを確認してください。
2. 4 件の取引はそのままにして、コピーした `accounts.txt` を空にします。`./lesson_19` を実行し、空の主ファイルは最初の `READ` で EOF に達し、その後も取引が 1 件ずつ読み取られることを確認してください。

実行ごとに、出力全体、終了コード、独立した 2 つの件数を記録してください。制約：「もう一方のファイルを読み続けさせる」ために EOF フラグをクリアしたり共有したりしないこと。2 つの入力の EOF、状態、件数はそれぞれ独立させてください。参考解答は `answer.md` を参照してください。

## 応用（解答なし）

口座主ファイルと取引ファイルに加えて、顧客主ファイル用の 3 つ目の入力ストリームを追加し、それぞれ 3、2、1 レコードのフィクスチャを用意します。3 ファイルそれぞれに専用の `FILE STATUS`、EOF フラグ、件数を設け、3 つすべてのストリームが終了するまでラウンドロビン方式で読み取ります。フィクスチャには空ファイルの場合も含め、いずれかの入力で OPEN に失敗した場合や READ エラーが発生した場合に、すでに開いたファイルをどのように閉じて非ゼロの終了コードを返すか説明してください。

ソース、コンパイルと実行のコマンド、各フィクスチャの実際の出力と終了コード、および 3 つのストリームの EOF が互いに影響しないことをどのように確認したかを提出します。ファイル間の照合や金額計算は追加しないでください。この練習には解答がありません。
