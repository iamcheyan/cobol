# 第 17 课：定长账户主档——按字节偏移读写 27 字节记录

银行账户主档常以定长记录文件交换：每条记录固定 27 字节，字段靠字节位置定位，文件里没有换行符分隔记录。本课逐条读入 [`accounts.dat`](./accounts.dat) 的账户记录，把字段按客户号、账户号、余额重新排列，写出同样 27 字节的 `balances.dat`，再用文件总字节数核对记录宽度、字段偏移与记录数三者是否自洽。

## 为什么现在学

第 15、16 课处理的是行顺序文件：每条记录以换行符结束，程序按行读取，行长由文件内容决定。真实主机接口更常见的是定长记录：没有换行符，字段偏移由接口规范固定，记录数只能从文件总字节数推断。缺口在于，读文本行时编译器替你处理了记录边界；读定长文件时，边界完全由你声明的 `RECORD CONTAINS` 和各字段 `PIC` 决定，任何一位宽度写错都会让后续字段整体错位，而且读坏数据时程序不一定报错。本课把“宽度 ⇄ 偏移 ⇄ 总字节数”的关系固定下来，第 19–22 课的多文件读取、按键匹配和文件综合批次都以它为前提。

## 本课完成后的能力与边界

学完本课后，你可以：

- 用 `ORGANIZATION IS SEQUENTIAL` 与 `RECORD CONTAINS 27 CHARACTERS` 声明无换行符的定长记录文件，并说明它与 `LINE SEQUENTIAL` 的区别。
- 按字节偏移解释 FD 记录布局（账户号 1–10、客户号 11–18、余额 19–27），并算出余额 `PIC 9(7)V99` 占 9 个数字字节。
- 用 `READ ... AT END` 逐条读入定长记录，区分“读到一条记录”与“到达文件末尾”。
- 用 `MOVE` 按字段名重排字段并 `WRITE` 出 27 字节输出记录，说明为什么输出字段顺序可以与输入不同。
- 用 `wc -c`、`od -c` 和 `3 × 27 = 81` 三方核对输入输出字节数，确认记录数、宽度与偏移一致。

边界：程序只检查输入/输出文件的打开、写出和关闭状态；它不校验输入文件总字节数是否为 27 的整数倍，因此长度不足或含换行字节的乱版式输入会被静默误读（见下文“边界与失败场景”）。业务校验与拒绝记录从第 18 课起，系统故障与返回码分类见第 26 课，排序、匹配与综合批次见第 21、22 课。

## 运行环境

- GnuCOBOL 3.2.0，默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不需要数据库、附加工具或第三方库。
- 输入夹具 [`accounts.dat`](./accounts.dat)：3 条 27 字节记录，共 81 字节，记录之间没有换行符。
- `ASSIGN TO "accounts.dat"` 使用相对文件名，运行目录必须能找到该文件；把夹具复制到临时目录运行，可以避免在本课目录留下输出文件。

## 定长记录与行顺序记录的区别

| 对比项 | 行顺序（`LINE SEQUENTIAL`，第 15、16 课） | 定长（`ORGANIZATION IS SEQUENTIAL`，本课） |
|---|---|---|
| 记录边界 | 由换行字节确定 | 由 `RECORD CONTAINS` 声明的宽度确定 |
| 记录长度 | 可以逐行不同 | 每条记录都相同 |
| 记录数 | 按行数统计 | 由文件总字节数 ÷ 记录宽度推断 |
| 文本编辑器 | 可以正常另存 | 会插入换行字节，破坏字段偏移 |

定长文件记录之间没有分隔符，`cat` 会把整个文件连成一行、`wc -l` 显示 0 行；判断布局只能按字节查看，例如 `od -An -c -w27 accounts.dat` 每行正好显示一条记录。若用文本编辑器打开并重新保存，编辑器会在记录之间写入换行字节，之后按 27 字节切分就会把换行读到字段里，字段整体错位。

反过来，把本课夹具交给行顺序方式读取也不会自动正确：用一个只把 `ORGANIZATION IS SEQUENTIAL` 改成 `LINE SEQUENTIAL` 的临时变体读取同一份 81 字节夹具时，27 字节记录区装不下“整行”，每条读满 27 字节的 `READ` 都返回状态 `06`，末尾还会多读出一条残留数据；把记录区加宽到 `PIC X(100)` 后，整个文件被读成**一条** 81 字节记录，三个账户再也分不开。所以定长接口不能靠更换文件组织方式来绕开，交换双方必须先对“无分隔符、按宽度切分”达成一致，本课也才有必要声明 `ORGANIZATION IS SEQUENTIAL` 并按 27 字节设计 FD。

## 输入契约与记录布局

输入记录布局如下（`V` 是隐含小数点，不占物理字节）：

| 字节位置 | 长度 | 字段声明 | 第 1 条记录 |
|---:|---:|---|---|
| 1–10 | 10 | `05 FD-ACCOUNT-NUMBER PIC X(10)` | `0001234567` |
| 11–18 | 8 | `05 FD-CUSTOMER-ID PIC X(8)` | `C0001042` |
| 19–27 | 9 | `05 FD-ACCOUNT-BALANCE PIC 9(7)V99` | `000100000` |

余额的 9 个数字字节表示 7 位整数与 2 位小数，所以 `000100000` 是 `1000.00`。三条记录的账户号、客户号、余额依次为：

| 记录 | 账户号 | 客户号 | 余额数字 | 余额 |
|---:|---|---|---|---:|
| 1 | `0001234567` | `C0001042` | `000100000` | 1000.00 |
| 2 | `0002468101` | `C0002042` | `000002000` | 20.00 |
| 3 | `0007654321` | `C0003042` | `000025075` | 250.75 |

输出文件 `balances.dat` 同样是 27 字节记录，但字段顺序不同：

| 字节位置 | 长度 | 字段声明 | 第 1 条输出 |
|---:|---:|---|---|
| 1–8 | 8 | `05 FD-OUT-CUSTOMER-ID PIC X(8)` | `C0001042` |
| 9–18 | 10 | `05 FD-OUT-ACCOUNT-NUMBER PIC X(10)` | `0001234567` |
| 19–27 | 9 | `05 FD-OUT-BALANCE PIC 9(7)V99` | `000100000` |

字节核算：输入 `3 × 27 = 81` 字节，输出 `3 × 27 = 81` 字节，两个宽度都由 `RECORD CONTAINS 27 CHARACTERS` 与字段 `PIC` 共同保证。

**输入契约（由上游保证，程序不校验）：**

- 文件总字节数必须是 27 的整数倍，最后一条记录不得残缺。
- 记录之间不得出现换行字节或其他分隔符。
- 余额字段必须是 9 个数字字节；本课不对余额做业务校验（没有负数、上下限或币种规则）。

**空文件与文件缺失：** 长度为 0 的 `accounts.dat` 可以正常打开，第一次 `READ` 立即到达 `AT END`，件数为 `00`、`balances.dat` 为 0 字节、退出码为 0。文件不存在时 `OPEN INPUT` 失败，程序报告状态码并以退出码 1 结束，此时还没有创建输出文件。

**计数字段宽度：** `WS-RECORD-COUNT` 是 `PIC 9(2)`，只能表示 `00`–`99`，本课夹具 3 条远低于上限。实测 100 条记录（2700 字节）时，`balances.dat` 仍是正确的 2700 字节，但 `クローズ完了 件数=` 显示为 `00`——只要件数可能达到三位数，计数就必须加宽。

## 源码阅读路径

完整源码见 [`lesson.cob`](./lesson.cob)。按数据流顺序读，四个段落分工如下：

| 段落 | 职责 | 关键语句 |
|---|---|---|
| `0000-MAIN` | 打开输入与输出文件、检查状态、循环处理、关闭并决定返回码 | `OPEN`、`PERFORM UNTIL`、`STOP RUN` |
| `1000-READ-AND-WRITE` | 读取下一条 27 字节记录；`AT END` 置结束标志 | `READ ... AT END` |
| `1100-WRITE-BALANCE-RECORD` | 按字段名重排三个字段，写出 27 字节记录并计数 | `MOVE`、`WRITE` |
| `9000-CLOSE-FILES` | 关闭两个文件并检查关闭状态 | `CLOSE` |

需要特别理解的三点：

1. `FD-ACCOUNT-RECORD` 是一块 27 字节的**共享记录区**。每次 `READ` 都用新记录覆盖这块区，所以必须在读到之后再 `MOVE` 到输出字段；`1100-WRITE-BALANCE-RECORD` 与 `READ` 在同一个循环迭代内完成，就是为了避免下一轮 `READ` 覆盖数据。
2. `FILE STATUS IS` 声明的两个字段由每次文件操作刷新。程序在 `OPEN`、`WRITE`、`CLOSE` 之后检查状态并显示状态码；`READ` 只使用 `AT END` 分句判断结束，不检查其他读取状态（见下节实测结果）。
3. `WS-END-OF-FILE` 表示读到 `AT END`，`WS-IO-ERROR` 表示写出或关闭失败。任一为 `"Y"` 循环都结束；只要 `WS-IO-ERROR` 为 `"Y"`，程序最终以 `RETURN-CODE = 1` 结束，避免把不完整结果当成功。`件数` 在 `WRITE` 状态为 `"00"` 时才加 1，所以它统计的是成功写出的记录数，不是读到的记录数。

### 固定格式核对（按字节）

定长记录课同样讲究源文件的列位置：第 7 列是指示符区，Area A 从第 8 列、Area B 从第 12 列开始，程序文本不越过第 72 列。用下面三条命令核对本课源码（`LC_ALL=C` 让 `awk` 按字节计数）：

```sh
LC_ALL=C awk 'length($0)>72 {print "over72", NR, length($0)}' lesson.cob
LC_ALL=C awk '/^      \*/ {next} {i=match($0,/[^ ]/); if (i>0 && (i<8 || (i>=9 && i<=11))) print "bad column", NR, i}' lesson.cob
LC_ALL=C awk '{if (length($0)>m) {m=length($0); n=NR}} END {print "max bytes", m, "line", n}' lesson.cob
```

实测结果：前两条都没有输出——没有越过第 72 列的行，也没有从第 1–7 列或第 9–11 列开始写字的行；第三条输出 `max bytes 72 line 96`（第 96、102 行放日语字面量的 `DISPLAY` 语句正好 72 字节，再改动就要缩短）。本课的代码行只从第 8 列（Division、`FD`、`01` 级字段、段落名）、第 11 列（`05` 级字段）、第 12 列（语句）开始，11 行注释在第 7 列写 `*`；这与仓库其他各课的缩进一致。

两点容易踩坑：`cobc` 3.2.0 在 UTF-8 源文件中按字节计算列位置，把中文写进字符串字面量时整行超过 72 字节就会被截断并报 `invalid literal`（注释内容不参与编译，本课同样控制在 72 字节内）；另外 `cobc -fsyntax-only` 不会报出“`05` 级写在第 11 列”这类情况——层级号从 Area A（第 8–11 列）开始是合法的，本仓库各课统一把 `05` 级放在第 11 列，所以列位置是否合规要看上面的检查命令，而不是指望编译器报错。

## 运行与观察

程序用相对文件名绑定输入输出，因此要先进入本课目录，或把 `accounts.dat` 与本课可执行文件放在同一目录。下面的写法把编译产物和运行输出都放在临时目录，不污染课程目录：

```sh
cd lessons/17_fixed-length-files
scratch_dir=$(mktemp -d)
trap 'rm -rf "$scratch_dir"' EXIT
cobc -fsyntax-only lesson.cob                          # 只做语法检查，不生成可执行文件
cobc -x -Wall -o "$scratch_dir/lesson_17" lesson.cob   # 编译并生成可执行文件
cp accounts.dat "$scratch_dir/"                        # 夹具复制到运行目录
(cd "$scratch_dir" && ./lesson_17)                     # 运行程序，业务输出写到标准输出
wc -c "$scratch_dir/balances.dat"                      # 核对输出文件字节数
od -An -c -w27 "$scratch_dir/balances.dat"             # 按 27 字节一行查看输出记录
```

各命令作用不同：`-fsyntax-only` 只证明语法路径可解析；`-x -Wall` 才真正生成可执行文件并报告编译警告；`cp` 把夹具放到运行目录（`ASSIGN` 用的是相对文件名）；`(cd ... && ./lesson_17)` 运行程序并产生 `balances.dat`；`wc -c` 与 `od` 用来核对输出字节数与记录布局；`trap`/`rm -rf` 负责清理临时目录。若要在本课目录直接编译，注意不要把可执行文件和 `balances.dat` 留在课程目录里，也不要删除或覆盖 `accounts.dat`。

**预期标准输出：**

```text
ファイルを開きました
出力 口座番号=0001234567 顧客番号=C0001042 残高=0001000.00
出力 口座番号=0002468101 顧客番号=C0002042 残高=0000020.00
出力 口座番号=0007654321 顧客番号=C0003042 残高=0000250.75
クローズ完了 件数=03
```

**日文输出的中文对照：** `ファイルを開きました` = 输入与输出文件都已打开；`出力 口座番号=… 顧客番号=… 残高=…` = 每条写出记录的账户号、客户号、余额；`クローズ完了 件数=03` = 关闭完成、共写出 3 条。余额显示为 `0001000.00`，是 `PIC 9(7)V99` 的显示格式：7 位整数补前导零后接小数点与 2 位小数。

**预期输出文件：** `balances.dat` 共 81 字节，即 `3 × 27`；按 27 字节分组查看为下面三行（文件内没有换行字节，分行为查看时的效果）：

```text
C00010420001234567000100000
C00020420002468101000002000
C00030420007654321000025075
```

**预期退出码与文件状态码：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x -Wall` 退出码 | `0`，无编译诊断 |
| 程序标准输出 | 上列 5 行 |
| 进程退出码 | `0` |
| `wc -c balances.dat` | `81` |
| `OPEN INPUT` 状态（`WS-ACCOUNT-STATUS`） | `00` |
| `OPEN OUTPUT` / `WRITE` / `CLOSE` 状态 | `00`（非 `00` 时显示 `STATUS=` 并以 1 结束） |
| `WS-END-OF-FILE` | 读完全部记录后为 `"Y"` |

### 边界与失败场景

下表是在本工作区用本课源码与真实处理过的输入实际观察到的结果（输入文件按需要拼接，程序本身未修改）：

| 输入文件字节数 | 观察到的行为 | 退出码 |
|---:|---|---:|
| 81（正常夹具，3 条） | 件数 `03`，`balances.dat` 81 字节 | 0 |
| 0（空文件） | 能打开，首次 `READ` 即 `AT END`，件数 `00`，`balances.dat` 0 字节 | 0 |
| 54（2 条完整记录） | 件数 `02`，输出 54 字节 | 0 |
| 28（1 条完整 + 尾随 1 字节） | 仍报件数 `02`：第 2 条以那 1 个字节开头，其余字节保留上一条记录的残留内容；输出 54 字节 | 0 |
| 82（3 条完整 + 尾随换行） | 报件数 `04`，第 4 条是错位记录；输出 108 字节 | 0 |
| 84（文本编辑器按行保存，每条后带换行） | 报件数 `04`，各字段整体错位（账户号里混入换行与相邻记录的字符）；输出 108 字节 | 0 |
| 文件不存在（或在别的目录运行） | `入力ファイルを開けません STATUS=35`，不创建输出文件 | 1 |
| 输出目录不可写 | `出力ファイルを開けません STATUS=37`，输入文件已关闭，不创建输出文件 | 1 |

可核对的不变量：在上列各例中，读到的记录数等于 `⌈文件字节数 ÷ 27⌉`，输出字节数等于 `记录数 × 27`。**但程序不会把乱版式输入当错误**：末条不完整时 GnuCOBOL 3.2.0 仍返回状态 `00`，未覆盖的字节保持上一条记录的残留内容；含换行的文件也不会被识别。因此“总字节数是 27 的整数倍”是必须由上游保证的前提，本课不校验它；要报告这类问题需要额外的长度核对与故障规则（第 26 课）。

### 证据来源与范围

- 已验证：上面给出的语法检查、编译（`-Wall` 无诊断）、正常运行、空文件、缺少输入文件、输出目录不可写，以及 27/54/28/82/84 字节输入的行为与字节数观察；`wc -c`、`wc -l`、`od -An -c -w27`、`cmp` 的核对结果与文中一致。

## 在企业中的位置

定长接口的价值与风险都在“约定”：记录宽度、字段偏移、字符编码、数字存储方式和记录数由交换双方共同约定，字段宽度一改，它后面的所有偏移都会移动，接收方若还用旧布局就会静默读错——本课实测的错位行为正说明这类错误不会自己暴露。真实系统因此需要版本化的布局规范、可复核的样例字节、记录数与总字节数的对账检查，以及记录级别的拒绝与审计；本课只验证“宽度 ⇄ 偏移 ⇄ 总字节数”在一个小文件上自洽，不代表已具备这些保证。

本课的记录布局会在第 23 课抽成 Copybook，被主档与后续批次共同复用；多文件读取、按键匹配与结果写出分别在第 19、20、22 课展开。
