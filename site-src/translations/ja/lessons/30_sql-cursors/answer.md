# 第30課 変更演習の参考解答

この解答が扱うのは [`exercise.md`](./exercise.md) の二つの変更演習だけです。応用演習の解答はありません。どちらも本課の元の [`lesson.cob`](./lesson.cob) を基準にします。基準の実行結果は [`expected-output.txt`](./expected-output.txt) を参照してください（8 行、終了コード `0`）。

二つの変更は本ワークスペースで実測しました。ソースを一時ディレクトリにコピーして問題のとおりに変更し、同じ GixSQL ツールチェーンで `./build.sh run` を実行しました（`BUILD_DIR` と `GIXSQL_ROOT` は一時パスを指定）。以下は実際に観察した出力です。

## 1. 結果の順序を逆にする

**変更箇所：** カーソル宣言内の並び順の句。

```sql
ORDER BY ACCOUNT_NO DESC
```

**コマンド：** `./build.sh run`

**実際の出力：**

```text
接続=成功
オープン=成功
行=A000000002 CUSTOMER=C0001002 BALANCE=00875.00
行=A000000001 CUSTOMER=C0001001 BALANCE=01250.75
取得=EOF SQLCODE=100
クローズ=成功
行数=002
切断=成功
```

**基準との差分と理由：** 3 行目と 4 行目だけが入れ替わり、`A000000002` が先、`A000000001` が後になります。`ORDER BY` が決めるのはデータベースから返される行の**順序**だけで、行数は変わらないため `行数=002` はそのままです。最後の行の後も `FETCH` ループは `SQLCODE 100` を受け取るので、`取得=EOF SQLCODE=100` と `クローズ=成功` も変わりません。残高 `00875.00` / `01250.75` は `schema.sql` の `875.00` / `1250.75` に対応します（`PIC 9(5).99` により整数部が 5 桁にゼロ埋めされます）。

## 2. 一つの口座に限定する

**変更箇所：** カーソル `SELECT` の `FROM` の後。第1問とは独立して行います。

```sql
WHERE ACCOUNT_NO = 'A000000002'
```

**コマンド：** `./build.sh run`

**実際の出力：**

```text
接続=成功
オープン=成功
行=A000000002 CUSTOMER=C0001002 BALANCE=00875.00
取得=EOF SQLCODE=100
クローズ=成功
行数=001
切断=成功
```

**基準との差分と理由：** `行=A000000002 CUSTOMER=C0001002 BALANCE=00875.00` の一行だけが残り、`行数` は `002` から `001` になります。`WHERE` によって結果セットが一行に絞られます。最初の `FETCH` は `SQLCODE 0` を返し（件数を +1 して表示）、**次の** `FETCH` では行が残っていないため `SQLCODE 100` が返ります。そこで `取得=EOF SQLCODE=100` を表示してループを終え、その後 `CLOSE` を実行して切断します。終了コードは `0` です。

注：ここで `SQLCODE 100` が表すのは「結果セットの終端」であり、エラーでも「口座が存在しない」でもありません。本課には「見つからない」分岐はありません。口座が存在しない場合は結果セットが空になります。その挙動は [`README.md`](./README.md) の「空、単一行、複数行、EOF のケース」を参照してください（本ツールチェーンでは、空表から最初に空白レコードが一行返ります）。
