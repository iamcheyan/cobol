## R10 · reset 与 runner 统一锁协议

- 原反例（已复现）：workspace 有合法 `output/`，创建目录 `workspace/output.lock` 后执行
  `scripts/reset.sh` → **RC 0，output 被删除，锁保留**（runner 实际用 `$out.lock`，reset 却检查
  `running.lock`/`.b04-run.lock`）。
- 修复：reset 用与 runner **相同**的原子 `mkdir "$root/output.lock"` 取得同一互斥锁，持锁贯穿删除，
  退出清理；任何已存在目录/文件/符号链接（含悬空软链）令 mkdir 失败 → **RC 12 且不修改任何内容**。
- 复测（原始 RC）：
  - 目录锁：`reset` RC **12**，`output/report.txt` 保留，锁保留。
  - 符号链接锁：`reset` RC **12**，output 保留，软链保留。
  - 无锁完整输出：`reset` RC **0**，删除 output，无残留锁。
- 永久回归：`scripts/check.py` 重建合法输出后分别注入目录锁与悬空软链锁，断言 RC12 且内容保留，
  无锁时 RC0 删除且学员文件保留。

## R11 · 压力程序断言 / scratch / 磁盘 / 空间耗尽

- 原反例（已复现）：导入 `pressure`，将 `run_runner` 替换为返回 12，执行 `expected_rc=4` 的
  scenario，**正常返回**（runner_rc=12、published=False，无异常）——CLI RC0 不能证明通过。
- 修复：
  - `scenario` 断言 `runner_rc==expected_rc`、`published==(rc∈{0,4})`、无泄漏 `output.lock`、
    发布时独立 verifier RC0；违约即 `AssertionError`。`main()` 捕获后写
    `evidence/B04-pressure-FAILURE.json` 并以非零退出。
  - scratch 契约显式化：scratch root 按空闲空间选择并记录（本次 `/var/tmp`，非 /tmp）；每个 runner/
    verifier 调用都用 `TMPDIR` 指向该 root 下 per-case 目录（oracle 临时文件记录在 `oracle_tmpdir`）；
    每 scenario 清理自身，`main()` 退出清理 root。
  - 新增 10ms 采样 scratch 文件系统 used/free 高水位（`scratch_fs`）。
  - 新增 `space_exhaustion`：oracle `python3` 以 8-block `RLIMIT_FSIZE` 写临时 expected，触发
    `OSError: [Errno 27] File too large`；断言整链 RC **12**、**不发布**、**不遗留锁**。
- 复测（`python3 scripts/pressure.py`，full，原始 RC **0**）：
  - `matched-million-high-diff`：runner RC 4、published、wall 567.2s、report 113,000,308 B、scratch
    高水位 3.86 GB、verifier `ru_maxrss` 20,944 KiB。
  - `matched-clean-100k`：runner RC 0、published、wall 54.1s。
  - `verifier-failure`：RC 12、不发布、无锁。
  - `oracle-temp-space-exhausted`：RC 12、不发布、无锁、无遗留 oracle 临时文件。
- 限制：真实“磁盘写满”无法在无 root 的主机上构造，故空间耗尽用显式 `RLIMIT_FSIZE` 边界代表；
  已在 evidence 中标注。
