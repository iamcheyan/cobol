# COPY、Copybook、REDEFINES

## 学習目標

COPY のテキスト展開モデル、COPY の検索パス、名前の衝突、REDEFINES による記憶領域の共有、条件付きコンパイルにおける REPLACING の用途。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L14.COB`](./L14.COB) と [`RECORD.CPY`](./RECORD.CPY) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後に実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -I extensions/legacy-workshop/lessons/14-copybooks-redefines -fsyntax-only extensions/legacy-workshop/lessons/14-copybooks-redefines/L14.COB
cobc -I extensions/legacy-workshop/lessons/14-copybooks-redefines -x -Wall -o build/l14 extensions/legacy-workshop/lessons/14-copybooks-redefines/L14.COB
./build/l14
```

期待される観察結果：同じ記憶領域を、元のテキストとしても構造化されたフィールドとしても解釈できます。COPY はコンパイル時にフィールド宣言を作業領域へ取り込み、`REDEFINES` は2つのレイアウトで同じ開始バイトを共有させます。

コンパイラが形式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認します。次にピリオド、変数の PIC、スコープ終端文を確認してください。`-Wall` は追加の警告を表示します。警告も内容を理解したうえで対処するか判断しましょう。

## 順を追って理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラに認識されるプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC に注目してください。
3. `PROCEDURE DIVISION` は実行の開始点です。`0000-MAIN` は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースの順序に従って実行され、制御フロー文で経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更して練習する

レコード定義をこのレッスンの RECORD.CPY に移し、COPY で取り込んでみましょう。フィールドの長さも変更してみてください。

変更するたびに、構文チェック、コンパイル、実行をやり直します。一度に変更する概念は1つにし、変更前後の出力を記録しましょう。

## cobol.nvim で学ぶ

COPY の行で gf を押すと Copybook を開き、K を押すとプレビューできます。<C-o> で戻ります。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、続いて `cobc --version` を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に使います。プログラムがコンパイル可能かどうかは、GNUCOBOL による実際のコンパイル結果で判断してください。
