# 第 19 课：同时读取主档与交易文件——两个独立输入流的 EOF 生命周期

真实批次很少只读一个文件：账户主档和当日交易必须一起被推进，而两者行数往往不同，先读完的那一份不能把另一份也带停。本课同时打开主档和交易两个顺序文件，各自维护文件状态、EOF 标志和记录计数，在主档先到文件尾之后继续把四条交易读完，为第 20 课的按键顺序匹配准备输入推进方式。

## 为什么现在学

第 15 课你已经能打开一个顺序文件、逐行读取并用 `AT END` 识别 EOF。缺口是“不止一个输入”：如果两份数据共用一个 EOF 标志或一个读取段落，先读完的文件会让另一份提前停止，或者两个文件的记录被交错错配。本课把每个输入的读取、状态和结束条件分开，并明确：正常 EOF（状态 `10`）不是错误，其他非零状态才是。

## 本课完成后的能力与边界

学完本课后，你可以：

- 在一个程序中声明并 `OPEN INPUT` 两个顺序文件，各自绑定 `FILE STATUS`。
- 为每个输入分别维护 EOF 标志和成功读取计数，并说明为什么不能共用。
- 用一个循环交错推进两个流：某个文件到 EOF 后，另一个文件继续读完。
- 区分正常 EOF（`10`）、OPEN 失败、READ 错误和 CLOSE 错误对应的处理与返回码。
- 核对输出：主档三条、交易四条，且这四条交易都出现在主档 EOF 之后。

边界：程序只读取并回显整行，**不解析字段、不按账户号匹配、不做金额计算、不生成输出文件**；顺序匹配是第 20 课的内容。文件格式约定（字段分隔、宽度）由夹具保证，本课不校验。缺失文件、空文件等边界在本课会当作失败或零记录处理，但没有重试或恢复。

## 运行环境

- GnuCOBOL 3.2.0，默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不依赖数据库或附加工具。
- 本课必须先有输入夹具，且 `SELECT` 里写的是相对文件名，因此**从本课目录执行**。
- 语法检查与编译在 `build/` 下生成可执行文件；程序不写任何数据文件。

## 输入文件

| 夹具 | 记录数 | 一行示例 | 说明 |
|---|---:|---|---|
| [`accounts.txt`](./accounts.txt) | 3 | `MASTER\|0001234567\|C0001042\|0001000.00` | 账户主档，行顺序文本 |
| [`transactions.txt`](./transactions.txt) | 4 | `TXN-000001\|D\|0001234567\|125.50` | 当日交易，行顺序文本 |

两者都是行顺序（LINE SEQUENTIAL）文本文件，每个物理行是一条记录，行内用 `|` 分隔字段；本课不看字段含义，只把整行显示出来。`FD` 记录区为 `PIC X(100)`，本课夹具最长一行 34 字节，远小于该上限，因此不会发生记录被截断或拼行。

## 读取流程

1. 分别打开主档和交易文件，检查各自的 `FILE STATUS`。第二个文件打开失败时，关闭已打开的第一个文件并返回错误。
2. 进入循环后，若某个文件尚未到 EOF，就对它执行一次 `READ`；每个输入各有一个读取段落，互不共享状态。
3. 成功读取时（状态 `00`）只增加**该文件**的计数并显示该行。
4. 到达 EOF 时只设置**该文件**的 EOF 标志。状态 `10` 是正常文件尾，不计入记录数，也不算错误。
5. 任一 `READ` 返回其他状态时，报告文件与状态，停止读取并关闭两个文件。
6. 只有两个 EOF 标志都为 `Y`（或发生 I/O 错误）时，读取循环才结束。

`AT END` 只覆盖文件状态 `10`，捕不到其他非零状态；因此各段落都在 `READ` 之后显式检查状态字段，避免把 I/O 错误当成 EOF 悄悄收尾。

## 文件状态、失败与限制

| 情形 | 观察到的文件状态 | 程序行为 / 返回码 |
|---|---|---|
| 正常读到文件尾 | `10` | 设置该文件 EOF，不计记录数，返回码保持 `0` |
| 输入文件缺失 | `35`（OPEN） | 输出 `... 文件打开失败 STATUS=35`，返回码 `1` |
| 读取中其他非零状态 | 其他状态码 | 输出 `读取...失败 STATUS=xx`，停止读取、关闭文件，返回码 `1` |
| 关闭异常 | 非 `00` | 输出 `关闭时...异常`，返回码 `1` |

- 两个输入都是必需文件：`SELECT` 未声明 `OPTIONAL`，缺文件即失败。
- 发生 READ 错误时立即停止，并尝试关闭两个文件；本课不提供重试或断点续读。
- 本课不校验业务日期、记录格式或跨文件一致性，也不声称完成了文件匹配。

## 运行与观察

**输入：** 本课目录下的 `accounts.txt` 与 `transactions.txt`；程序按相对路径打开，所以要先 `cd` 到本课目录。

**命令及作用：**

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob                  # 只做语法检查，不生成可执行文件
cobc -x -Wall -o build/lesson_19 lesson.cob    # 编译并生成可执行文件
./build/lesson_19                              # 运行，读取当前目录下的两个夹具
echo $?                                        # 查看退出码
rm -rf build                                   # 清理生成的可执行文件
```

**预期结果：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出 | 9 行，见下方代码块 |
| 进程退出码 | `0` |
| 生成的业务文件 | 无（本课只读） |

```text
账户与交易文件已打开
账户主档：MASTER|0001234567|C0001042|0001000.00
交易：TXN-000001|D|0001234567|125.50
账户主档：MASTER|0002468101|C0002042|0000020.00
交易：TXN-000002|T|0001234567|0007654321|40.00
账户主档：MASTER|0007654321|C0003042|0000250.75
交易：TXN-000003|D|0002468101|75.00
交易：TXN-000004|T|0007654321|0009999999|20.00
关闭完成 账户记录数=003 交易记录数=004
```

**可独立核算：** 夹具 `accounts.txt` 有 3 行、`transactions.txt` 有 4 行，所以汇总必须是 `账户记录数=003`、`交易记录数=004`，合计 7 条被回显的记录。第 5 行之后主档记录不再出现（主档已 EOF），但交易仍继续打印到第 4 条——这正是两个 EOF 标志彼此独立的效果。

**实际观察到的环境细节：** 在本工作区运行可执行文件时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境的链接库版本警告，不是本程序的业务输出；其触发组件尚未定位。

## 修改练习

两项都在**临时目录里的夹具副本**上做，不要改动仓库内的 `accounts.txt` / `transactions.txt`：

1. 删除副本 `transactions.txt` 的最后两条记录，只留前两条。确认主档仍读完三条，而交易计为两条。
2. 清空副本 `accounts.txt`，保留四条交易。确认空主档在首次 `READ` 就到达 EOF，后续交易仍被逐条读取。

## 举一反三练习

增加一份客户状态文件，与主档和交易文件一起读取。为三个输入各自维护 EOF 和计数；准备三条、两条、一条记录的夹具，确认任意一个流先结束时其他流仍继续推进。设计一个能区分文件名和状态码的读取错误输出格式。不添加账户匹配、排序或数据库访问。题目见 [`exercise.md`](./exercise.md)，本题不提供答案。

## 在企业中的位置

日批处理常把主档、控制文件和交易文件当作一个输入集合，每个文件都有自己的必需/可选策略、文件状态处理和独立记录计数。生产对账还要校验业务日期、记录格式和跨文件一致性。

本课只验证“并行推进文件位置”和“每个输入独立的 EOF 生命周期”，属于顺序匹配（第 20 课）之前的一步。它不读取键、不比较记录、不写结果文件，也没有错误重试；拒绝与结果写出从第 16、26 课开始。
