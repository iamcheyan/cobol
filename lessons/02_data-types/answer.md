# 第 02 课修改练习参考答案

本答案只覆盖 `exercise.md` 中的三项初值修改及其边界自检，不提供举一反三练习答案。

## 三项修改

从本课原始 `lesson.cob` 出发，只改三条数据声明的 `VALUE` 子句：

```cobol
       01 WS-BRANCH-CODE PIC 9(4) VALUE 3107.
       01 WS-CURRENCY-CODE PIC X(3) VALUE "EUR".
       01 WS-CUSTOMER-NUMBER PIC X(10) VALUE "0000000042".
```

字段名、`PIC`、字段顺序和 `PROCEDURE DIVISION` 都不改动。重新编译并运行：

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_02 lesson.cob
./build/lesson_02
```

`cobc -fsyntax-only` 与 `cobc -x` 都返回 `0` 且无诊断，程序退出码为 `0`（运行时 stderr 只有 libxml 环境警告）。

## 完整预期差异

与原始程序的标准输出相比，恰好三行不同：

| 原始输出 | 修改后输出 | 原因 |
|---|---|---|
| `支店コード=2048` | `支店コード=3107` | `PIC 9(4)` 的初值改为 `3107`，仍是四位数字，输出宽度不变 |
| `通貨コード=USD` | `通貨コード=EUR` | `PIC X(3)` 的三个字符换成 `EUR`，宽度不变 |
| `顧客番号=0002046819` | `顧客番号=0000000042` | `PIC X(10)` 仍逐字符保存十个字符，前导零原样保留 |

其余 26 行逐字符不变，因为没有改动任何其他字段的 `PIC` 或初值。输出行标签是日文：客户号那一行是 `顧客番号=`，不要写成字段名 `WS-CUSTOMER-NUMBER`。

## 客户号为什么继续用 PIC X(10)

客户号是标识符，不是参与加减的数量：

- 前导零是键值本身的一部分。本课实测：同一个十位数字串用 `PIC 9(10)` 或 `PIC X(10)` 声明，`DISPLAY` 的外观相同（都打印 `0002046819`）；差别不在这一次显示，而在语义——`9` 把字段声明为数值，程序后续按数值语义处理它（参与运算、按数值对齐、按数值比较），而客户号不该参与算术，也不该因为某次数值处理而丢掉前导零或改变位数。
- 用 `X` 还能容纳非纯数字的取值（例如带分隔符或校验位的编号格式），不过本课不引入这类取值。
- 结论：宽度用 `X(10)` 保持，改动只发生在 `VALUE` 上。

## 边界自检

把 `WS-BRANCH-CODE` 的初值临时改成 `12345` 后，本机实测：

- `cobc -fsyntax-only lesson.cob` 与 `cobc -x -Wall -o build/lesson_02 lesson.cob` 都输出 `warning: value size exceeds data size [-Wothers]` 并指向该声明行，两条命令的返回码仍是 `0`。
- 运行输出该行变为 `支店コード=2345`：初值 `12345` 超出 `PIC 9(4)` 的容量，最高位 `1` 被丢弃，只留下低四位 `2345`。
- 程序不会在运行期报错，退出码仍是 `0`。

所以 `PIC 9(n)` 的宽度是硬约束：超宽只是编译期警告，被截断的值照样进入程序。写完初值要核对宽度；这个警告在本机 GnuCOBOL 3.2.0 上不加 `-Wall` 也会出现。自检完成后请把初值恢复为 `3107`。
