# ファイル状態、入力検証、例外処理

## 学習目標

FILE STATUSの2文字コード、OPEN/READ/WRITEのエラー分岐、AT END/INVALID KEY、入力データの検証とエラーカウント。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言や処理箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L13.COB`](./L13.COB)を開いてください。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文と実行文はArea Bに記述します。まずソースを1行ずつ読んでから、実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行してください。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/13-file-status-errors/L13.COB
cobc -x -Wall -o build/l13 extensions/legacy-workshop/lessons/13-file-status-errors/L13.COB
./build/l13
```

期待される観察内容：ファイル状態コードに応じた成功・失敗の分岐。

コンパイラが形式や列位置のエラーを報告した場合は、まず第7、8、12、72列目を確認してください。次に、ピリオド、変数のPIC、スコープ終端文を確認します。`-Wall`は追加の警告を出力します。警告も内容を理解してから、対処するかどうかを判断してください。

## 各段落の理解

1. `IDENTIFICATION DIVISION`はプログラム単位を宣言し、`PROGRAM-ID`はコンパイラが認識するプログラム名です。
2. `DATA DIVISION`はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号とPICを確認してください。
3. `PROCEDURE DIVISION`は実行の入口です。`0000-MAIN`は読みやすくするための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースの順序に従って実行され、制御フロー文によって経路が変わるか、`STOP RUN`でプロセスが終了します。

## 変更練習

存在しない入力ファイルを使ってエラー経路を発生させてください。プログラムがゼロ以外のコードを返し、役に立つメッセージを表示するようにします。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つに絞り、変更前後の出力を記録してください。

## cobol.nvimで学ぶ

フィールド名を意図的に1つ削除し、:CobolLintと:CobolQuickfixを使って、エラー一覧からソースコードに戻る練習をしてください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認してください：`:set filetype?`。次に、`cobc --version`を確認します。プラグインは移動、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかは、GNUCOBOLで実際にコンパイルした結果を基準に判断してください。
