# 名前付け、コメント、リテラル、ピリオド

## 学習目標

COBOLの単語、ハイフンを使った命名、予約語、文字列の引用符、数値リテラル、行内コメント／行全体のコメント、ピリオドの作用範囲。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言箇所や実行箇所を見つけられるようになります。文法を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L03.COB`](./L03.COB) を開きます。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文／実行文はArea Bに記述します。まずソースコードを1行ずつ読み、その後実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/03-names-comments-literals/L03.COB
cobc -x -Wall -o build/l03 extensions/legacy-workshop/lessons/03-names-comments-literals/L03.COB
./build/l03
```

期待される結果：文字列と数値リテラルが表示されます。

コンパイラが形式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認します。次に、ピリオド、変数のPIC、スコープ終端文を確認しましょう。`-Wall` は追加の警告を表示します。警告も内容を理解してから対処するか判断してください。

## 順を追って理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言があれば、レベル番号とPICを確認しましょう。
3. `PROCEDURE DIVISION` は実行の開始点です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されるわけではありません。
4. 各文はソースコードの順に実行されます。制御フロー文で処理経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更演習

テキストを二重引用符を含む内容に変更し、引用符を二重にする方法を試します。コメントを追加し、最後のピリオドを削除して診断メッセージを確認しましょう。

変更のたびに、構文チェック、コンパイル、実行をもう一度行います。一度に変更する概念は1つにし、変更前後の出力を記録しましょう。

## cobol.nvimで学ぶ

`:CobolFormatCase` を試します。フォーマットによってキーワードだけが整えられ、変数名、文字列、コメントは変わらないことを確認しましょう。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認しましょう。プラグインは移動、レイアウトのヒント、診断に利用します。プログラムがコンパイルできるかどうかは、GNUCOBOLで実際にコンパイルした結果を基準に判断してください。
