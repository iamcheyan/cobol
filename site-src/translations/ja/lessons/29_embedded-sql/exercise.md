# 第 29 課の演習：ホスト変数と SQL の状態

本演習では、第29課で扱った内容だけを使います。GixSQLによるプリコンパイル、`EXEC SQL ... END-EXEC`、ホスト変数、`SQLCODE` の分岐、`CONNECT` / `CONNECT RESET` です。

## 変更演習（回答例は `answer.md`）

まず `./build.sh run` を実行して、基準出力を保存します。`lesson.cob` を変更するたびに同じコマンドを再実行してください。スクリプトがDBを作り直し、前回の結果が今回に影響しないようにします。

```sh
./build.sh run
echo $?
```

1. 1回目の検索口座を `A000000001` から `A000000002` に変更します。顧客番号と残高を確認し、`SELECT ... INTO` がDB列をどうCOBOLフィールドに入れるか説明してください。
2. 元のソースから始め、2回目の検索口座を `A99999999X` から `A000000002` に変更します。それぞれの検索がどの `SQLCODE` 分岐を通るか、標準出力がどう異なるかを比較してください。

制約：`schema.sql` と `build.sh` は変更しないこと。毎回クリーンなDBから実行し、終了コードを記録すること。回答例は `answer.md` を参照してください。

## 発展演習（解答なし）

`ACCOUNT_SNAPSHOT` に開設日と口座状態を追加し、ホスト変数を使って `ACTIVE` な口座を検索します。「口座が存在しない」と「SQL実行に失敗した」を標準出力、ログ、終了コードでどのように表すか定義してください。データベースのパスと認証情報をデプロイ環境から渡すべき理由も説明してください。

`schema.sql`、`lesson.cob`、実行コマンド、および3つのケース（見つかった / 見つからない / SQL失敗）の実際の出力と終了コードを提出してください。解答例はありません。
