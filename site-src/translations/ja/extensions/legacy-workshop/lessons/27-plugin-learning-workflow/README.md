# cobol.nvimを使って学びながら練習する

## 学習目標

プラグインはCOBOL言語そのものではありません。ルーラー、アウトライン、ジャンプ、Copybookのプレビュー、PICの計算、診断、折りたたみ、フォーマットを学習に取り入れましょう。

このレッスンを終えたら、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言箇所や実行箇所を見つけられるようになっているはずです。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L27.COB`](./L27.COB) を開いてください。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文や実行文はArea Bに記述されています。まずソースコードを1行ずつ読んでから、実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/27-plugin-learning-workflow/L27.COB
cobc -x -Wall -o build/l27 extensions/legacy-workshop/lessons/27-plugin-learning-workflow/L27.COB
./build/l27
```

期待されるポイント：プラグインは学習を支援するものですが、GnuCOBOLコンパイラーや、信頼できる方法での意味検証の代わりにはなりません。

コンパイラーが形式や列位置のエラーを報告した場合は、まず第7、8、12、72列を確認してください。次に、ピリオド、変数のPIC、スコープ終端文を確認します。`-Wall` は追加の警告を出力します。警告も内容を理解したうえで、対処するかどうかを判断してください。

## 各部分を理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラーが認識するプログラム名です。
2. `DATA DIVISION` は、プログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、階層番号とPICを確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすくするための段落名にすぎず、自動的に繰り返し実行されるわけではありません。
4. 各文はソースコードの順に実行されます。制御フロー文によって経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更練習

最初の10レッスンから知識を1つ選び、コードを書いて、コンパイル、実行、意図的なエラーの作成、プラグインを使った箇所の特定、修正、記録を行ってください。

変更のたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つだけにして、変更前後の出力を記録します。

## cobol.nvimを使った学習

READMEのプラグイン課題カードを完了し、:CobolGuideToggle、:CobolCalcRecord、:CobolLint、:CobolQuickfix を使ってください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、次に `cobc --version` を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかは、GNUCOBOLでの実際のコンパイル結果が判断基準です。
