# 第 13 課演習：SEARCH と SEARCH ALL

この課では、第 11～13 課で学んだ内容だけを使います。`OCCURS` テーブル、`INDEXED BY` インデックス、`SEARCH` / `SEARCH ALL`、`SET`、`MOVE`、`DISPLAY` を使用します。

## 変更演習（参考解答は `answer.md`）

1. `1000-LOAD-ACCOUNTS` で口座 `0002468101` の残高を `520.00` から `600.00` に変更します。2種類の検索を実行し、返される残高を確認してください。
2. 口座テーブルを4項目から5項目に拡張し、口座 `0009999999`、残高 `75.00` を末尾に追加します。2つ目の検索対象を `0005550000` から `0009999999` に変更し、2種類の検索を実行してください。

各演習は元の `lesson.cob` から別々に行い、変更を重ねないでください。変更ごとに次を実行します。

```sh
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_13 lesson.cob
./build/lesson_13
```

テーブルを拡張する際、`OCCURS` の上限だけ変更して対応するデータのロードを忘れないでください。そうすると追加した口座番号は空白のままとなり、検索で見つかりません。参考解答は上記の変更演習だけを扱います。

## 学んだことを応用する（解答なし）

5項目の商品在庫テーブルを作成します。`SEARCH` で存在する商品コードと存在しない商品コードを検索し、さらにキー順を宣言して `SEARCH ALL` で検索します。コードは重複させず、実行時の並び順を `ASCENDING KEY` または `DESCENDING KEY` と一致させてください。

ソース全体と、両方の検索方式の実際の出力を提出します。順序の約束を維持しているコード箇所、キー宣言を更新せずにテーブルデータの順番だけを変えた場合の危険性、本課の探針がその危険性を自動検出できない理由を説明してください。メモリ内データだけを使い、ファイルやデータベースは追加しません。解答はありません。
