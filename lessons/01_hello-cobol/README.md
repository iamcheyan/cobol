# 第 01 课：Hello COBOL——编译并运行最小固定格式程序

银行夜间批处理要能被调度器启动：调度器只认可执行文件路径，程序负责把结果写到它能观察的地方。本课写出最小的固定格式 COBOL 程序，把它编译成 Linux 可执行文件并运行，打通“源文件 → 编译 → 可执行 → 输出”这条后续每课都要复用的路径。

## 为什么现在学

你已经会编辑文件、在终端里运行命令，但还没有让本机执行 COBOL 程序的经验。缺口有三处：COBOL 源文件长什么样、编译器怎样把它变成可执行文件、程序输出从哪里看。本课用一个只输出一行文本的程序把这条流程固定下来；之后每课都在同样的编译/运行方式上增加数据、运算、条件、文件和数据库处理。

## 本课完成后的能力与边界

学完本课后，你可以：

- 用 `cobc -fsyntax-only` 检查一个 `.cob` 源文件能否通过语法解析。
- 用 `cobc -x -o <名称>` 把源文件编译成可执行文件，并根据命令返回码确认编译是否成功。
- 运行可执行文件，区分标准输出和标准错误，并用进程退出码判断是否正常结束。
- 在最小程序中认出程序标识、执行入口、输出语句和正常结束语句。
- 说明程序既没有输入、也没有用户定义数据项时，为什么不需要 `DATA DIVISION`。

边界：本课不定义数据项、不读文件、命令行参数或数据库，不做任何运算，除语法错误外也尚未处理运行期故障。数据字段从[第 02 课](../02_data-types/README.md)开始，文件读取从第 15 课开始。

## 运行环境

- GnuCOBOL 3.2.0，使用默认方言（不加 `-std=cobol85`），源文件为固定格式。
- Linux 终端；本课不依赖数据库、附加工具或第三方库。
- 运行不会产生业务数据文件，只在 `build/` 下生成可执行文件。

## 知识讲解

### 一个 COBOL 程序解决什么问题

COBOL 程序常用于按明确记录和规则处理业务数据。第一课先只输出一条问候语，目的是建立从源文件到可执行文件的完整路径；后面的课再逐步引入字段、运算、条件、文件和数据库。真实批处理也需要这个最小闭环：编译器能找到程序入口，运行时能执行它，操作人员能观察输出。

### 本课用到的结构

- `IDENTIFICATION DIVISION` 标识源文件里的程序单元。
- `PROGRAM-ID` 为程序单元声明名称。本例叫 `HELLO01`。
- `PROCEDURE DIVISION` 开始可执行过程。
- `DISPLAY` 把字面量文本写到标准输出；这里没有读文件或数据库。
- `STOP RUN` 结束当前 COBOL run unit。本例到此正常退出。

本例没有 `DATA DIVISION`，因为没有定义或保存数据项。随着课程加入字段，我们会在需要时再添加数据声明。

### 与 Java / Python 的对应关系

可以把 `PROGRAM-ID` 粗略类比为 Java 类名或 Python 模块名，把 `DISPLAY` 的用途类比为 `System.out.println(...)` 或 `print(...)`。这只是用途上的类比：COBOL 的 Division 是源程序结构，不能直接等同于 Java 类或 Python 函数。

### 固定格式和常见误区

本课程的源文件使用固定格式。代码从第 8 列起；Division 名称位于 Area A，执行语句位于 Area B；有效程序文本不能越过第 72 列。不要把自由格式代码的左对齐习惯直接套进来。

常见误区：

- `cobc` 成功编译只说明生成了可执行文件；程序输出要在运行可执行文件后才会出现。
- 源文件名和 `PROGRAM-ID` 是不同概念。`-o` 指定可执行文件名。
- 字符串里的逗号和感叹号是普通输出字符，不是 COBOL 语句分隔符。
- 没有输入数据的程序无需 `ACCEPT`、字段声明或文件声明；这些会在后续课学习。

### 关于输出文本的语言

仓库约定：源文件注释与 README 讲解使用中文，程序运行输出的业务文本沿用日文。本课输出的 `こんにちは、COBOL！` 意为“你好，COBOL！”。判断程序行为时以实际输出和 README 的中文说明为准。

## 完整示例源码

完整源码见 [`lesson.cob`](./lesson.cob)，按固定格式编写。

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. HELLO01.
       PROCEDURE DIVISION.
           DISPLAY "こんにちは、COBOL！".
           STOP RUN.
```

## 逐行解析

| 源码行 | 作用 | 运行时变化 |
|---|---|---|
| `IDENTIFICATION DIVISION.` | 开始程序身份声明区 | 编译阶段据此解析后续程序声明；不产生业务输出 |
| `PROGRAM-ID. HELLO01.` | 给程序单元命名 | 编译器将此程序标识纳入生成的可执行程序 |
| `PROCEDURE DIVISION.` | 声明执行部分开始 | 运行时从这里进入程序过程 |
| `DISPLAY "こんにちは、COBOL！".` | 将字面量写到标准输出 | 终端收到一行 `こんにちは、COBOL！`；本例未定义业务字段 |
| `STOP RUN.` | 正常结束 COBOL run unit | 程序返回操作系统；没有后续 COBOL 语句执行 |

这里数据变化非常有限：程序没有用户定义的数据项，也没有改变余额或记录；编译器/运行时仍会使用实现自身的运行时状态。

## 运行与观察

本课不读取输入文件、命令行参数或数据库记录，因此在本课目录或任意目录执行结果都相同。下面按本课目录说明。

**输入：** 无。输出全部来自 `lesson.cob` 中的字面量，不是外部数据。

**命令及作用：**

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob                    # 只做语法检查，不生成可执行文件
cobc -x -Wall -o build/lesson_01 lesson.cob      # 编译并生成可执行文件
./build/lesson_01                                # 运行程序，输出写到标准输出
echo $?                                          # 查看上一条命令的退出码
rm -rf build                                     # 清理生成的可执行文件
```

**预期结果：**

| 观察项 | 预期值 |
|---|---|
| `cobc -fsyntax-only` 退出码 | `0` |
| `cobc -x` 退出码 | `0`，无编译诊断 |
| 标准输出（stdout） | 一行 `こんにちは、COBOL！` |
| 进程退出码（`echo $?`） | `0` |
| 生成文件 | 仅 `build/lesson_01` |

`-fsyntax-only` 只验证语法路径；它不生成也不运行程序，因此不能替代编译和运行观察。`-x` 要求 GnuCOBOL 生成可执行程序，`-o` 指定输出路径。

**实际观察到的环境细节：** 在本工作区运行 `./build/lesson_01` 时，标准错误会输出 `Warning: program compiled against libxml 212 using older 209`。这是运行环境链接库版本差异产生的警告，不是本程序的业务输出；其触发组件尚未定位。程序的正常输出写在标准输出，退出码为 0。

## 举一反三练习

为一家保险公司的夜间批次写另一个最小问候程序：用两行输出说明批次名称和“等待输入文件”的状态。只使用本课学过的程序结构、固定字符串输出和结束语句，不要加入尚未学习的字段、条件、循环或文件操作；自己记录编译命令、实际输出和退出码。题目见 [`exercise.md`](./exercise.md)，本题不提供答案。

## 在企业中的位置

在银行、保险、证券和制造业的批处理系统里，最小程序入口通常会逐渐承担初始化、处理、汇总和结束职责。上线作业的 shell 或调度器负责启动可执行文件、收集标准输出/错误输出并解释进程退出码，因此“编译成功”“运行成功”“退出码为 0”是上线前必须能区分的事实。

本课只验证源代码能编译并输出。它尚未读取业务数据、核对金额，也不代表已具备生产批次的错误处理能力；字段定义见第 02 课，文件读取与文件结束处理见第 15 课，错误分类与返回码见第 26 课。
