# モジュール 09 のフィクスチャ

すべてのファイルは ASCII、固定幅で、各行の末尾は LF です。LF は論理幅に含めません。営業日は `20261010` に固定されています。レイアウトは凍結された契約です：CUSTOMER v1 = 27 バイト、ACCOUNT v1 = 47 バイト、TRANSACTION v1 = 55 バイト。ディレクトリ構成：`normal/`（主ケース。3 つの `.dat` ファイルがディレクトリ直下にあります）、`boundary/<case>/`、`invalid/<case>/`。フィクスチャは `../scripts/generate-fixtures.py` によって決定的に生成されます。`SHA256SUMS` にはこのファイルとすべての `.dat` ファイルが含まれます。

| ディレクトリ | 対象 | 期待 RC | 公開 |
|---|---|---|---|
| `normal` | すべて受入：8 桁の顧客検証に合格し、取引ごとの金額計算が正しい | 0 | はい |
| `empty-customers` | 顧客ファイルは空で、口座/取引は通常どおり | 0 | はい |
| `no-transactions` | 取引ファイルは空でも、口座の期末残高を出力 | 0 | はい |
| `max-amount` | 1 回の取引金額と残高が 13 桁の上限に達しても有効 | 0 | はい |
| `all-empty` | 3 ファイルすべてが空 | 0 | はい |
| `customer-bad-status` | 顧客状態 `Z` に対して `CUSTVAL` が業務上の拒否を返す | 4 | はい |
| `customer-bad-id` | 顧客 ID に数字以外が含まれ、`CUSTVAL` が業務上の拒否を返す | 4 | はい |
| `customer-no-name` | 顧客名がすべて空白で、`CUSTVAL` が業務上の拒否を返す | 4 | はい |
| `zero-amount` | 取引金額が 0 で、`AMTCALC` が業務上の拒否を返す | 4 | はい |
| `overdraft` | 出金が利用可能残高を超え、`AMTCALC` が業務上の拒否を返す | 4 | はい |
| `overflow` | 入金によって残高が 13 桁の上限を超え、`AMTCALC` が業務上の拒否を返す | 4 | はい |
| `unknown-direction` | 取引方向が `C` でも `D` でもなく、`AMTCALC` が業務上の拒否を返す | 4 | はい |
| `no-account` | 取引口座が口座ファイルに存在せず、呼び出し側が業務上の拒否と判定 | 4 | はい |
| `frozen-account` | 口座状態が `F` で、呼び出し側が業務ポリシーに従って取引ごとに拒否 | 4 | はい |
| `bad-layout-version` | 口座レイアウトのバージョン `002` によるファイル契約エラー | 8 | いいえ |
| `short-account` | 口座レコードが 46 バイトで、入力長の契約エラー | 8 | いいえ |
| `bad-account-date` | 口座の営業日がジョブの営業日と一致しない契約エラー | 8 | いいえ |
| `unsorted-transactions` | 取引が口座/連番の昇順でなく、契約エラー | 8 | いいえ |

RC4 のフィクスチャでも、検証済みレポートと派生ファイルは公開されます（JOB の呼び出し側は RC4 でも処理を続行することを明示的に許可する必要があります）。
RC8 のフィクスチャではバッチ全体が失敗し、出力ディレクトリは生成されません。
