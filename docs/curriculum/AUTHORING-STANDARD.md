# 课程制作与验收标准

状态：后续制作课程必须遵循的交付规范。目录名称为目标结构，实施进度见课程入口，未完成单元不得标为已验收。

## 1. 单个实战单元的交付结构

```text
curriculum/modules/07-matching/labs/03-one-to-many/
  README.md                 学员任务及验收，避免直接给答案
  DESIGN.md                 输入输出、状态图、业务规则及约束
  starter/                  能构建的起始代码，TODO 清楚说明
  copybooks/                版本化接口
  fixtures/normal/          正常输入
  fixtures/boundary/        EOF、长度、金额、空文件等边界
  fixtures/invalid/         有明确根因的异常输入
  expected/                 独立核算的输出、RC、统计与规则说明
  scripts/                  build/run/check/reset，支持任意启动目录
  evidence/README.md        学员需要提交的证据，不预填通过结果
instructor/modules/07/...   参考实现、根因、提示阶梯、评分说明
```

统一银行模型和共通程序只维护一份 canonical source；实验通过版本化配置、补丁或阶段快照使用它，不大量复制同名程序形成不同实现。微实验允许独立源码，但须解释其与银行系统的关系。

## 2. README 必须回答的问题

1. 业务为什么需要这一处理？学员接到什么需求？
2. 输入文件/DB 从哪来、格式是什么、哪些前提已经保证？
3. 从干净 checkout 如何构建、运行、复位？执行会覆盖哪些派生文件？
4. 预期输出、RC、笔数和金额是多少，如何独立核算？
5. 需要修改哪里、哪些接口不能破坏？
6. 故意破坏哪些条件，应该如何调查和恢复？
7. 哪些插件操作有助于定位，终端替代方式是什么？
8. 完成需要交什么证据，何种结果算失败？

不得以只有 DISPLAY 说明文本的程序作为文件处理、DB、排序、突合或综合项目的主要实现。代码必须实际处理所附数据。

## 3. 夹具矩阵

| 类别 | 最低覆盖 | 结果要求 |
|---|---|---|
| 输入边界 | 缺失、0 字节、最后一条、无匹配、两边 EOF、短/长记录 | 明确 RC/拒绝/允许空文件政策 |
| 字段 | 空必填、非法数字、未知状态、金额上下界、符号/缩放 | 明确字段级原因，无静默截断 |
| 键 | 重复 Master、重复交易、逆序、同键不同次序、孤立键 | 明确基数及分类策略 |
| DB | 无结果、NULL、唯一约束、连接失败、事务回滚 | 原始 DB 状态及映射 RC |
| 环境 | 输出无权限、临时空间不足、并发锁、错误日期 | 无正式输出发布，不覆盖源数据 |
| 恢复 | 提交前/后、发布前/后崩溃、同日重复启动 | 无重复应用，状态与证据一致 |
| 静默错误 | RC0 但金额错误、少一行、多一行、旧 DB 快照 | 控制总数或差异验收必须发现 |

文件夹具记录字符集、换行、字节长度和校验和。坏字节/非法 Packed Decimal 必须以真实字节提交或可重复生成，不能只在 README 写“这里是坏数据”。随机数据生成器只能生成实验材料，不得代替学员核心 COBOL 算法。

## 4. 预期结果与验证证据

expected 先由业务规则、人工微型算例或独立参考模型确定，再运行学生/参考程序验证。不能将实现自身输出直接认定为正确答案。每个 expected 附规则说明和核算过程。

检查至少包含：编译、源码格式、脚本状态、退出码、文件字节/逻辑内容、拒绝分类、笔数守恒、金额守恒、正式发布状态。比较允许规范化时必须逐项说明，例如换行平台差异；不得对整个输出 trim 后掩盖定宽记录错误。

证据格式：版本/提交、编译器和 DB 工具版本、营业日、run_id、命令、原始 RC、输入校验和、输出校验和、核对表、调查结论及限制。日志或输出与断言不匹配即失败。

## 5. 参考答案和事故发放

学员包只提供任务、可用资料和逐层提示；讲师包保存参考实现、根因、触发条件、最小修复、误导线索和评分点。公开仓库无法保密答案，需提供不含 instructor 的可重复学员打包方式，并告知自学者答案位置。

事故包至少包含 Scheduler Flow/状态、JOB Log、Shell、源码、Copybook、原始输入、参数/Manifest、DB 种子或 SQL Log。至少 6 类事故：非法数字、DB 唯一约束、空输入、Master 逆序、系统资源失败、RC0 但业务错误。各类都有实际可复现入口；主机 ABEND 名称和 GNUCOBOL 实际行为分别说明。

事故调查交付顺序：现象与影响范围→时间线→假设与证据→最小复现→根因→修复/回滚→恢复与重跑→防再发。不得通过篡改原输入或放宽断言“修复”事故。

## 6. Legacy Maintenance 变更包

需求：客户区分由 1 位扩展为 2 位。编码前交付：

- 影響調査書：字段定义、所有使用位置、依赖图、未知项。
- 修正対象一覧：Copybook、程序、文件、DB、Shell、JOB、设计书、下游接口及负责人角色。
- 修正方針：布局 v1/v2、兼容策略、迁移/回滚步骤、数据切换与并行验证。
- Test Case：正常、边界、异常、跨版本、全流程及恢复场景。
- Evidence 计划：每个测试的期望与证据位置。

经过调查评审再修改；完成后交修改前后布局、生成文件、DB 结果、上下游测试和回滚证据。最终陌生系统规模目标为约 8,000 行有意义 COBOL、20 Copybook、15 Shell、30 JOB 节点、12 逻辑表；不能重复填充代码凑规模。逐阶段增大，规模只是阅读复杂度目标，不替代功能质量。

## 7. 模块 07 标杆验收

L1 覆盖双 EOF 状态与三类输出；L2 覆盖连续同键累计、同键交易次序、重复交易和溢出；L3 交多流基数表、状态转换表和快照日期校验；L4 交至少 150 字段目录与独立差异清单。

检查不得出现核心流程全量读数组、SQL Join 或 Python 匹配。允许系统 SORT 用作独立 JOB，但学员仍要实现并验证 COBOL 顺序突合与有序性检查。内存证据、计数与金额守恒缺一项均不放行。

## 8. 毕业评分与硬门禁

| 维度 | 分值 |
|---|---:|
| 数据结构与字节解释 | 15 |
| 文件/排序/突合正确性 | 25 |
| DB、JOB、恢复与幂等 | 20 |
| 影响调查及安全修改 | 20 |
| 事故调查与证据 | 20 |

总分至少 80/100，并通过所有硬门禁：无重复扣款、金额/笔数核对正确、失败不发布、上下游版本兼容有证据、事故根因可复现、先调查后修改。硬门禁失败不能通过其他项得分抵消。结业现场演练包含未知事故，不仅重复已经展示过的答案。

## 9. 阶段发布检查表

- [ ] 阶段目标、先修、工时和业务成果明确。
- [ ] 起始代码及参考实现从干净环境可构建。
- [ ] 所有读取的文件和 DB 种子都随课程提供。
- [ ] expected 具有独立核算依据，RC 和控制总数已覆盖。
- [ ] 学员任务能在不看答案的情况下完成。
- [ ] 源码遵守选定固定格式，例外自由格式实验单独标记。
- [ ] 平台/工具版本、ABI、DB 预编译与错误码限制已说明。
- [ ] 插件任务和纯终端替代路径均可执行。
- [ ] 运行/复位不会破坏原始夹具或其他实验产物。
- [ ] 课程/讲师/证据版本对应清楚，无虚构“已通过”。
