# 第 02 课练习：数据类型与 PIC

本节只使用第 01、02 课讲过的内容：固定格式源文件、`PIC`/`VALUE` 字段声明、`DISPLAY` 输出、`STOP RUN`。不使用 `MOVE`、算术、条件、循环、组项或文件操作。

## 修改练习（参考答案见 `answer.md`）

### 基线

从本课原始 `lesson.cob` 开始（程序名 `DATA02`，字段全部平铺在 `WORKING-STORAGE SECTION`），不要先做举一反三练习。

### 改动位置与约束

只改以下三个字段的 `VALUE` 子句，`PIC`、字段名、字段顺序和 `PROCEDURE DIVISION` 全部保持不变：

1. `WS-BRANCH-CODE`：初值 `2048` 改为 `3107`（保持 `PIC 9(4)`）。
2. `WS-CURRENCY-CODE`：初值 `"USD"` 改为 `"EUR"`（保持 `PIC X(3)`）。
3. `WS-CUSTOMER-NUMBER`：初值 `"0002046819"` 改为 `"0000000042"`（保持 `PIC X(10)`）。

第三条要求你解释：客户号为什么继续用文本类型，而不是改成 `PIC 9(10)`。

### 重新编译与运行

```sh
mkdir -p build
cobc -fsyntax-only lesson.cob
cobc -x -Wall -o build/lesson_02 lesson.cob
./build/lesson_02
```

### 完整预期差异

与原始程序的标准输出相比，应恰好三行不同，其余 26 行逐字符不变：

| 原始输出行 | 修改后输出行 | 原因 |
|---|---|---|
| `支店コード=2048` | `支店コード=3107` | `9(4)` 的初值由 2048 改为 3107，四位数字不变 |
| `通貨コード=USD` | `通貨コード=EUR` | `X(3)` 的三个字符换成 `EUR` |
| `顧客番号=0002046819` | `顧客番号=0000000042` | `X(10)` 逐字符保存，前导八个零原样保留 |

`cobc -fsyntax-only` 与 `cobc -x` 都应返回 0 且无诊断，程序退出码仍为 0。如果出现 `value size exceeds data size` 之类的警告，说明改动越出了声明的宽度，请检查是否误改了 `PIC`。

### 边界自检（同属本练习）

把 `WS-BRANCH-CODE` 的初值临时改为 `12345`，编译（可对比加与不加 `-Wall`）并运行，记录编译器输出和程序打印的分行号；然后恢复为 `3107`。说明这个结果与 `PIC 9(4)` 的宽度约定有什么关系，以及这个警告在不加 `-Wall` 时是否也会出现。
