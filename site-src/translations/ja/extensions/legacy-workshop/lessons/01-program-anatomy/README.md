# プログラムの骨格と四つの Division

## 学習目標

IDENTIFICATION、ENVIRONMENT、DATA、PROCEDURE の各 Division の役割、プログラム名、ピリオド、段落、STOP RUN について学びます。

このレッスンを終えたら、上記の用語を自分の言葉で説明し、小さなプログラム内で対応する宣言や実行箇所を見つけられるようになることを目指します。構文を暗記するだけではなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L01.COB`](./L01.COB) を開きます。このレッスンのソースファイルは固定形式を使用しています。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読んでから、実行してみましょう。

## コンパイルと実行

リポジトリのルートディレクトリから、次のコマンドを実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/01-program-anatomy/L01.COB
cobc -x -Wall -o build/l01 extensions/legacy-workshop/lessons/01-program-anatomy/L01.COB
./build/l01
```

期待される動作：まず四つの Division の役割が表示され、その後、名前付き段落が呼び出されます。

コンパイラが書式や列位置のエラーを報告した場合は、まず第7、8、12、72列目を確認します。次に、ピリオド、変数の PIC、スコープを終了する文を確認してください。`-Wall` は追加の警告を表示します。警告も内容を理解してから対処するかどうかを判断しましょう。

## 逐段理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言します。`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC に注目してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名であり、自動的に繰り返し実行されることはありません。
4. 各文はソースコードの順序どおりに実行されます。制御フロー文によって経路が変わるか、`STOP RUN` によってプロセスが終了するまで続きます。

## 変更の練習

2000-FAREWELL 段落を追加し、メインの処理から PERFORM してみましょう。段落の順序と実行順序は同じとは限らないことを観察してください。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は一つにし、変更前後の出力を記録しましょう。

## cobol.nvim で学ぶ

アウトラインで Division と Paragraph を確認します。PERFORM の名前にカーソルを置いて gd で定義へ移動し、段落の定義位置で <C-o> を押すと戻れます。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使用します。プログラムをコンパイルできるかどうかは、GNUCOBOL による実際のコンパイル結果で判断します。
