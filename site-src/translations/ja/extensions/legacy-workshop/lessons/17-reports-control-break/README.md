# レポート、累算器、コントロールブレーク

## 学習目標

ヘッダー／明細／合計、累算器、グループ化とソート、コントロールブレーク（control break）、編集用 PIC、金額の書式。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラム内で対応する宣言や実行箇所を見つけられるようになります。構文を暗記するだけではなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L17.COB`](./L17.COB) を開いてください。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述されています。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/17-reports-control-break/L17.COB
cobc -x -Wall -o build/l17 extensions/legacy-workshop/lessons/17-reports-control-break/L17.COB
./build/l17
```

期待される結果：1つの部門の累計金額と、書式設定された合計が出力されます。

コンパイラが書式や列位置のエラーを報告した場合は、まず7、8、12、72列目を確認してください。次に、ピリオド、変数の PIC、スコープを終了する文を確認します。`-Wall` は追加の警告を表示します。警告も内容を理解してから対処するか判断してください。

## 順を追って理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言があれば、レベル番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の開始点です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースコードの順に実行されます。制御フロー文によって経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更演習

2つ目の部門を追加し、部門が変わったときに小計を出力してから累算器をリセットしてください。

変更するたびに、構文チェック、コンパイル、実行を再度行ってください。一度に変更する概念は1つに絞り、変更前後の出力を記録してください。

## cobol.nvim で学ぶ

Aerial のアウトラインで 1000／2000／9000 の段落を確認し、コントロールブレークの処理順を観察してください。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使用します。プログラムをコンパイルできるかどうかの判断基準は、GNUCOBOL による実際のコンパイル結果です。
