# cobcのコンパイルオプション、方言、実行ファイル

## 学習目標

-x、-c、-o、-I、-fsyntax-only、-Wall、-Wextra、-std などのオプション、固定形式／自由形式、GnuCOBOLのデフォルト拡張。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から対応する宣言や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L21.COB`](./L21.COB)を開きます。このレッスンのソースファイルは固定形式を使用しています。Divisionと段落はArea Aから始まり、宣言文や実行文はArea Bに記述されています。まずソースを1行ずつ読み、その後で実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/21-compiler-options/L21.COB
cobc -x -Wall -o build/l21 extensions/legacy-workshop/lessons/21-compiler-options/L21.COB
./build/l21
```

確認するポイント：プログラムが、コンパイルと静的チェックの主な用途を列挙します。

コンパイラが形式や列位置に関するエラーを報告した場合は、まず第7、8、12、72列を確認します。次に、ピリオド、変数のPIC、スコープ終端の文を確認しましょう。`-Wall`は追加の警告を表示します。警告の内容も理解したうえで、対処するかどうかを判断してください。

## 順を追って理解する

1. `IDENTIFICATION DIVISION`はプログラム単位を宣言し、`PROGRAM-ID`はコンパイラに認識されるプログラム名です。
2. `DATA DIVISION`は、プログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言がある場合は、階層番号とPICを確認しましょう。
3. `PROCEDURE DIVISION`は実行の入口です。`0000-MAIN`は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文で処理経路が変わるか、`STOP RUN`でプロセスが終了するまで、ソースの順序どおりに実行されます。

## 変更演習

-fsyntax-only、-Wall、-xをそれぞれ実行し、-freeも試して、使用している環境で実際に利用できるオプションを記録しましょう。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は一つにし、変更前後の出力を記録しましょう。

## cobol.nvimを使った学習

プラグインのリアルタイム診断は、構文チェックのためにcobcを呼び出します。最終的な検証は、ターミナルからのビルドで行います。

プラグインが応答しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。続いて、`cobc --version`を確認してください。プラグインは移動、レイアウトのヒント、診断に役立ちますが、プログラムをコンパイルできるかどうかの判断基準は、GNUCOBOLによる実際のコンパイル結果です。
