# Bash連携：パイプ、ログ、ジョブスケジューリング

## 学習目標

リダイレクト、パイプ、tee、ログ、パイプラインでの失敗伝播、ロックファイル、cron と systemd timer の役割分担、および繰り返し実行可能な設計を学びます。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から対応する宣言や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察してください。

## サンプルコード

[`L24.COB`](./L24.COB) を開いてください。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文と実行文は Area B に配置されています。まずソースを1行ずつ読み、その後で実行してください。

## コンパイルと実行

リポジトリのルートディレクトリから次を実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/24-bash-pipelines-scheduling/L24.COB
cobc -x -Wall -o build/l24 extensions/legacy-workshop/lessons/24-bash-pipelines-scheduling/L24.COB
./build/l24
```

期待される観察結果：プログラムの終了ステータスを使って、シェルのログとバッチ処理の結果を制御します。

コンパイラが書式や列位置のエラーを報告したら、まず第 7、8、12、72 列目を確認してください。次に、ピリオド、変数の PIC、スコープを終了する文を確認します。`-Wall` は追加の警告を表示します。警告の内容を理解してから、対処するかどうかを判断してください。

## 各部分を理解する

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の開始点です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文は、制御フロー文によって経路が変わるか、`STOP RUN` でプロセスが終了するまで、ソースの順番に実行されます。

## 変更演習

出力をログにリダイレクトし、パイプラインで pipefail を使ってください。続けて2回実行し、入力を壊さないことを確認してください。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つだけにして、変更前後の出力を記録してください。

## cobol.nvim で学ぶ

プラグインでプログラムの終了経路を確認してください。構文のチェックには CobolLint を使い、ShellCheck がインストールされていればスクリプトのチェックに使ってください。

プラグインが応答しない場合は、まず現在のファイルタイプを確認します。`:set filetype?` を実行し、その後 `cobc --version` を確認してください。プラグインはナビゲーション、レイアウトのヒント、診断に役立ちます。プログラムをコンパイルできるかどうかは、GNUCOBOL による実際のコンパイル結果で判断してください。

## 実行可能なパイプラインの例

[`run-pipeline.sh`](./run-pipeline.sh) を実行します。

```sh
extensions/legacy-workshop/lessons/24-bash-pipelines-scheduling/run-pipeline.sh
LOG_FILE=/tmp/course-batch.log extensions/legacy-workshop/lessons/24-bash-pipelines-scheduling/run-pipeline.sh
```

このスクリプトでは、`tee` を使ってターミナルとログの両方に出力し、`set -o pipefail` によってパイプライン内の COBOL プログラムの失敗ステータスを保持します。`L24.COB` を非ゼロの終了コードを返すように変更して再実行し、失敗時の分岐を確認してください。
