# 第 10 課演習：REDEFINES

この演習では第 10 課と先行課で学んだ `05` / `10` レベル項目（第 [09](../09_group-items/README.md) 課）、`REDEFINES`、`MOVE`、`DISPLAY`、段落呼び出しの `PERFORM`（第 [07](../07_paragraphs/README.md) 課）、`STOP RUN` のみを使います。

## 変更演習（解答例は `answer.md`）

### 基準

変更されていない元の [`lesson.cob`](./lesson.cob) から始めます。編集前に複製しておくと基準を再実行できます（例：`cp lesson.cob /tmp/lesson_10_ex.cob`）。

### 変更箇所と制約

`2000-LOAD-TRANSFER` 内の次の文だけを変更します。

```cobol
           MOVE 250.75 TO WS-TRANSFER-AMOUNT
```

`250.75` を `99.99` に置き換えます。

`PIC`、項目順、`REDEFINES` の位置や対象、2つのビューの長さは変更しません。`DISPLAY` 文言、`1000-LOAD-DEPOSIT`、取引コード・口座番号・参照番号の `MOVE` 値も変更しません。この数値リテラルだけを変え、`COMPUTE`、`IF`、`EVALUATE`、データ項目を追加しないでください。

### コマンド

```sh
mkdir -p build                                   # 先に出力ディレクトリを作成
cobc -fsyntax-only lesson.cob                    # 構文検査
cobc -x -Wall -o build/lesson_10 lesson.cob      # コンパイル
./build/lesson_10                                # 実行し12行の出力を確認
echo $?                                          # 終了コード
```

### 期待される差分

標準出力は引き続き12行で、変わるのは2行だけです。

| 行 | 元の値 | 変更後 |
|---|---|---|
| 8 | `振込金額=00250.75` | `振込金額=00099.99` |
| 12 | `参照番号=3210025075` | `参照番号=3210009999` |

11行目 `金額=00076.54` を含む残り10行はバイト単位で変わりません。構文検査、コンパイル、実行の終了コードはすべて `0` です。

変更後の完全な出力：

```text
取引種別=D
入金口座=0001234567
入金額=00125.50
入金参照番号=TXN-000001
取引種別=T
振込元口座=0001234567
振込先口座=0007654321
振込金額=00099.99
同じバイト列の入金ビュー:
口座=0001234567
金額=00076.54
参照番号=3210009999
```

README のレイアウト表で独立確認できます。`9(5)V99` は7桁を格納し、`99.99` はペイロードの21〜27バイトに `0009999` として入ります。参照番号はペイロードの18〜27バイトを読むため、振込先口座の末尾3桁 `321` と `0009999` を連結した `3210009999` になります。入金額が読むのは11〜17バイト（振込先口座の先頭7桁 `0007654`）だけなので変化しません。

### 問い

1. `金額=00076.54` が変わらないのはなぜですか。どのバイト位置で決まりますか。
2. `参照番号=3210009999` の `321` と `0009999` は、それぞれどの範囲から来ますか。
3. 取引コードに応じて入金ビューと振込ビューを選ぶ文はソースのどこにありますか。存在しない場合、今回の書込みが振込ビューを使うことは何によって決まりますか。プログラムが実際に検証する条件は何ですか。

実出力とソース上の根拠を記録してください。解答例は [`answer.md`](./answer.md) を参照してください。

## 学んだことを応用する（解答なし）

現金引出しと口座間振込の2つのビューが、同じペイロードを共有する設計を考えます。

各ビューの項目と `PIC` を決め、各基本項目とビュー全体のバイト数を計算し、両ビューが同じ長さであることを確認します（再定義側が長いとコンパイルに失敗し、短い場合はコンパイルできても一部のバイトが覆われません）。`W` / `T` などの取引コードで区別し、読取側がどのビューを使うか分かる仕組みを説明します。未定義コードの場合の動作と、それが正しい処理とは言えない理由も説明してください。一方のビューで値を書き込み、もう一方で読み取って表示し、その結果を元の取引の有効な解釈と見なせない理由を述べます。

この課と先行課で学んだ階層項目、`REDEFINES`、`MOVE`、`DISPLAY`、段落と `PERFORM`、`STOP RUN` のみを使います。どちらのビューを表示するか選ぶために第 [04](../04_if-conditions/README.md) / [05](../05_evaluate/README.md) 課の条件文を追加しても構いませんが、必須ではありません。ファイル、表（`OCCURS` は第 [11](../11_occurs-tables/README.md) 課）、データベース、サブプログラムは導入しません。ソース、バイト計算、コマンド、実出力、終了コード、型コードとレイアウトを一致させる責任の説明を提出してください。解答はありません。
