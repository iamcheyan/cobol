# 企业 Legacy Batch COBOL 课程制作规格

状态：设计已获准实施，当前按阶段制作；进度与验收见 [课程入口](../curriculum/README.md)，尚未完成全课程。
版本：1.0，2026-10-09。

## 1. 目标与定位

本课程面向需要接手既存 COBOL Batch 的开发者，以 GNUCOBOL 为主要实验环境，围绕同一个模拟银行夜间批处理系统逐步展开。毕业能力是：读懂陌生程序的数据结构和 JOB Flow，追踪输入输出，完成影响调查，在明确上下游契约后修改程序，设计有证据的测试，并调查一次批处理事故。

课程不能以章节数量、代码可编译或插件截图替代业务验收。全部银行数据为合成数据；“企业实战”指训练方法和工程约束，不表示模拟系统已具备真实银行生产资质。

## 2. 受众与前提

学习者能使用终端、编辑文本和理解基本变量/条件/循环；无需大型机或数据库生产经验。课程从基础建立数据观，但前 01～05 模块要尽快连接真实业务记录。中文为教学主语言；保留常见英文及日文维护交付物术语并解释含义。

基础环境：GNUCOBOL、Bash、Make、Git、Hex Dump 工具。Linux 为首要验证环境；macOS/WSL 支持必须经过对应平台运行验证后标注。Neovim 和 cobol.nvim 可选，纯终端路径必须完成同样业务目标。

## 3. 可衡量目标

- 12 模块、76 小时建议学习量；模块 07/10/11 合计 30 小时。
- 从模块 02 起，主要练习都使用统一客户/账户/交易模型；独立微实验只用于解释字节或语义。
- 每个实战单元具有正常、边界、异常夹具，以及独立定义的预期文件、RC 和控制总数。
- 突合实现采用顺序读和有界状态；核心算法不得用 DB Join、Python 或全量数组替代。
- 结业必须交付影响调查、修改方案、测试证据、运行手册和事故复盘。

## 4. 学员任务与验收

### US-01 数据表示实验

作为维护开发者，我能判断 PIC/USAGE 的逻辑范围与实际存储，并通过 Hex Dump 验证。

验收：解释隐含小数、符号、截断、字节序与 ABI；提交 DISPLAY/COMP/COMP-3 的源码、原始字节、解释表；不得把二进制或 Packed Decimal 当文本解析。

### US-02 安全读取业务文件

作为批处理开发者，我能识别文件缺失、空文件、非法数字、未知状态、重复键和长度异常。

验收：每种异常有独立夹具及处理策略；正常与拒绝笔数守恒；失败不得发布正式输出。

### US-03 顺序突合与差异报告

作为既存系统维护者，我能处理 1:1、1:N、多文件/N:N 业务关系，以及 150+ 字段比较。

验收：明确重复键基数及比较规则；覆盖两边 EOF；排序错误先失败；输出 MATCH、MASTER ONLY、TRANSACTION ONLY；差异报告可定位字段与偏移；内存不随文件总行数增长。

### US-04 数据库批处理

作为开发者，我能以游标提取业务日数据，处理 NULL、无数据、唯一约束错误及事务失败。

验收：Host/Indicator Variable、SQLCODE/SQLSTATE、事务边界及重跑行为有实验和证据；必须使用验证通过的真实 DB 实验环境。

### US-05 JOB 运维

作为值班开发者，我能按依赖执行 JOB，并在失败后判断能否恢复。

验收：RC 传播、锁、业务日、日志、输入快照、输出发布和提交后失败均有演练；重复启动不重复扣款。

### US-06 维护与事故调查

作为维护者，我先做影响调查，再扩展客户区分字段，并定位一次隐藏根因事故。

验收：覆盖 Copybook、程序、文件、DB、JOB、外部接口及下游；保留修改前后证据；不得先改 PIC 再补调查。

## 5. 强制要求

- FR-01：完整课次、先修关系、建议工时、业务任务及验收必须在制作前列清。
- FR-02：每课包含起始代码、合成输入、输入契约、预期结果、运行步骤、修改任务与故障任务。
- FR-03：参考实现、讲师根因和答案与学员资料分离；事故发放包不得直接暴露根因。
- FR-04：数据格式必须版本化；记录长度按字节定义，文件换行、字符集、金额单位、排序规则明确。
- FR-05：金额计算使用明确的小数/整数单位和溢出策略；不得依赖浮点近似。
- FR-06：大记录必须有 150+ 有业务意义字段、字段目录和可追踪布局，不得用 FILLER 凑数。
- FR-07：RC 0/4/8/12 是课程作业约定；各 JOB 明确 Warning 是否允许继续。
- FR-08：DB、文件与下游发布之间不得假定原子提交；提供恢复清单与幂等键。
- FR-09：每课给出终端路径和适用的插件调查任务；插件估算不得作为字节布局最终依据。
- FR-10：所有关键夹具必须可离线取得；随机生成数据有固定 seed 和清单。
- FR-11：正常/异常结果由业务契约独立确定，不能仅将程序当前输出保存成 expected。
- FR-12：每次阶段发布提供源码、数据、设计、测试和证据版本的对应关系。

## 6. 范围边界

核心包含 GNUCOBOL、文件批处理、数据表示、排序突合、DB、模块化、Bash 作业编排、事故与维护。JCL/JP1 等以阅读和映射为主；没有实际环境不得声明已执行大型机 JCL。特定 DB 的错误码、主机 ABEND、EBCDIC 和 GNUCOBOL 运行时错误必须分别标注，不混用。

真实支付清算、生产凭据、真实客户数据、完整调度器产品实现、所有历史厂商方言不属于课程实现范围。SQL、复杂字符集与平台移植的限制需要明确展示。

## 7. 制作顺序及门禁

| 阶段 | 交付 | 放行条件 |
|---|---|---|
| P0 设计 | 本文及三份配套规格 | 用户认可目标、结构和验收 |
| P1 技术验证 | GNUCOBOL 字节实验、顺序突合原型、DB 工具链可复现验证 | 记录版本、命令、失败模式和结论 |
| P2 标杆模块 | 模块 07 完整学员包、讲师包、夹具和证据 | 四级突合任务逐项验收 |
| P3 基础链 | 模块 01～06、09 | 每个模块为统一银行模型提供实际能力 |
| P4 工程链 | 模块 08、10 | DB 集成、RC、重跑、提交后恢复验证通过 |
| P5 事故与结业 | 模块 11～12 | 学员可凭发放材料独立调查和维护 |
| P6 发布 | 课程入口切换、旧内容索引 | 全流程从干净环境运行，资料可追踪 |

旧 30 课及其未提交补丁保留为历史素材，不视作新课程完成项。制作前逐项评估可复用内容，不整体搬运占位例子。用户已授权开始新课程实现；不删除或重置旧工作区修改。

## 8. 发布验收

学习者从干净 checkout 能建立实验环境、运行指定业务日、对照预期结果、复现故障并恢复。每个模块的验收记录列出版本、命令、退出码、输出摘要和限制。毕业通过条件详见制作标准，核心门禁不可用平均分抵消。

## 9. 实施前待验证事项

1. DB：建议 PostgreSQL；Embedded SQL 预编译器候选必须先验证与选定 GNUCOBOL 版本兼容、NULL/游标/事务/错误传递和安装复现性。未通过前模块 08 不标完成。文件快照用于先修练习，不能冒充 DB 实操。
2. GNUCOBOL 版本和编译选项：以技术验证后锁定清单为准；当前本机 3.2.0 只作为基线参考。
3. Linux/macOS/WSL 支持矩阵、二进制布局差异、索引文件后端和 Hex 工具差异在 P1 建档。
4. 数据规模及性能预算先给出验收档位，P1 测量后锁定硬件和时间阈值，不编造性能承诺。
