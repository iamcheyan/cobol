# Save and Restore Sessions: auto-session

You close Neovim and open it again the next day. **The 12 files you had open, the window layout, and cursor positions are all gone.**

auto-session saves sessions by “project directory”: one layout per directory, restored automatically the next time you enter that directory.

---

## 1. What Problem It Solves

| Need | Without sessions | With auto-session |
|---|---|---|
| Restore the files you had open | Reopen them manually | `cd` into the directory to restore automatically |
| Keep the window layout | Recreate the splits | Layout is saved |
| Switch between projects | Reopen each one | Separate session for each directory |
| Recover last week's workspace | Rely on memory | Session list |

## 2. Your Configuration

In `lua/plugins/auto-session.lua`, the key `opts` entries are:

| Option | Value | Meaning |
|---|---|---|
| `auto_save` | `true` | Save automatically on exit |
| `auto_restore` | `true` | Restore automatically when entering a directory |
| `auto_restore_last_session` | `false` | Do not unconditionally restore the last session on startup |
| `args_allow_files_auto_save` | `true` | Save even when started with file arguments |
| `git_auto_restore_on_branch_change` | `false` | Do not switch sessions automatically when changing branches |

### Extra Handling for Sidebars

This configuration is more involved than the default because it addresses **Neo-tree / Aerial sidebars in sessions**. The comment at the start of the configuration explains why:

```lua
-- auto-session closes non-file windows in auto_save_session() *before*
-- pre_save_cmds. Snapshot first, keep neo-tree/aerial through that close
-- pass, then fold them ourselves so mksession cannot write ghost splits.
```

The problem: `mksession` can write “ghost splits”—blank windows that appear when the session is restored. The configuration's solution is to **snapshot the sidebar state first, let auto-session complete its normal close sequence, then rebuild the sidebars itself**.

```lua
-- Restore is per-tab and per-file-window: a right-hand outline next to a
-- vsplit is not the same as "aerial is open".
```

Restoration is also **per tab and per window**: an outline on the right next to a vertical split is not the same thing as “Aerial is open.”

## 3. Keybindings

| Key | Command | Action |
|---|---|---|
| `<leader>wr` | `:AutoSession search` | Search for / select a session |
| `<leader>ws` | `:AutoSession save` | Save the current session manually |
| `<leader>wa` | `:AutoSession toggle` | Toggle automatic saving |
| `<leader>wd` | `:AutoSession delete` | Delete the current session |

**These keys are under the `<leader>w` (windows) group**, because a session is essentially a saved window layout.

## 4. How It Works

### Automatic Save and Restore

1. Work in `~/development/cobol` with a bunch of files open
2. Exit with `:q` → the session for that directory is **saved automatically**
3. Next time, run `cd ~/development/cobol && nvim` → the session is **restored automatically**

Each directory has its own session, independent of the others. Switch between `cobol` and `cobol.nvim`, and each keeps its own layout.

### Where Sessions Are Stored

```sh
ls ~/.local/share/nvim/sessions/
```

The directory path is encoded in the filename. **Do not edit these files manually**—they are generated by `mksession`, and an incorrect edit can prevent restoration.

### What Happens if Restoration Fails

The configuration includes `restore_missing_session_paths` to handle cases where a file recorded in a session has been moved or deleted. It tries to resolve the path again using the cwd recorded in the session.

## 5. Typical Scenarios

### Scenario 1: Continue Working the Next Day

```
晚上：改到一半，:q 退出
早上：cd ~/development/cobol && nvim
      → 昨天开的文件、分屏、光标位置全回来了
```

### Scenario 2: Work on Multiple Projects in Parallel

```
~/development/cobol/        → 会话 A（课程编辑布局）
~/development/cobol.nvim/   → 会话 B（插件开发布局）
~/nvim/                     → 会话 C（配置编辑布局）
```

Switch directories to switch layouts; there is no need to reopen everything manually.

### Scenario 3: Recover a Layout from Last Week

```text
<leader>wr     搜索会话
```

Search by name or path with fuzzy matching, then select a session to restore it.

### Scenario 4: Do Not Restore Automatically

Sometimes you want to start clean:

```text
<leader>wa     关掉自动保存
:qa            退出
```

The session will not be restored the next time you enter.

## 7. Common Pitfalls

### Blank Splits Appear After Restoration

The configuration specifically handles the “ghost split” problem, but it may still occur if you manually edit session files or use other plugins. To fix it:

```text
<leader>wd     删除该目录的会话
重新搭建布局
<leader>ws     重新保存
```

### Neo-tree / Aerial Are Missing After Restoration

The configuration attempts to restore sidebars, but **restoration is per tab and per window**. A very unusual layout when saved (for example, two vertical splits, each with its own outline) may not be fully restored.

Reopen them with `<leader>fe` / `<leader>cs`.

### The Session References a Deleted File

The configuration handles this with `restore_missing_session_paths`, but restoration will still fail if the entire directory has been moved. Delete the session and recreate it.

### Start with a Clean Session Temporarily

```sh
nvim --clean      # 完全不用配置
```

Or:

```text
<leader>wa       关掉自动保存
:qa!
```

### Sessions and Git Branches

`git_auto_restore_on_branch_change = false`, so changing branches will **not** switch sessions. This is intentional—layouts are usually the same for the same files on different branches.

## 8. How It Relates to Other Plugins

| Plugin | Handles |
|---|---|
| auto-session | Files, window layout, cursor positions |
| dashboard | Start page (shown when there is no session to restore) |
| neo-tree / aerial | Sidebars, saved by auto-session's extension logic |

A configuration comment explains that on startup, if Auto Session finds a project session, it restores that session first; Dashboard appears only when there is no session to restore.

## 10. Scope

- The keybindings in this tutorial come from `lua/plugins/auto-session.lua`: `<leader>wr`, `<leader>ws`, `<leader>wa`, and `<leader>wd` (all under the `<leader>w` group).
- This configuration is **significantly more involved than the plugin default**: it implements its own snapshot and restoration for sidebars (Neo-tree / Aerial), because native `mksession` can write ghost splits.
- `<leader>wd` (delete session) cannot be undone.
- `rm -rf ~/.local/share/nvim/sessions/` clears all sessions, but loses every saved layout.
