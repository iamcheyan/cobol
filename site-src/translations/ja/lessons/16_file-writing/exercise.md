# 第 16 課演習：分類結果の書き込み—振り分け、上書き、再実行

この課では、第16課と先行課で学んだ内容だけを使います。`SELECT` / `FD` / `FILE STATUS` / `OPEN OUTPUT` / `WRITE ... FROM` / `CLOSE`（本課）、`OCCURS` テーブル（[第11課](../11_occurs-tables/README.md)）、`EVALUATE`（[第05課](../05_evaluate/README.md)）、段落と `PERFORM`（[第07課](../07_paragraphs/README.md)）、`DISPLAY`、`MOVE`、`STOP RUN` を使用します。

> **実行場所：** プログラムは `accepted.txt` / `rejected.txt` を**実行時のカレントディレクトリー**に書き込みます。課のディレクトリーにある同名ファイルは `.gitignore` の対象ではありません。すべての演習で課の `build/` を作業ディレクトリーにしてください。実行ファイルと出力ファイル2つはそこに作成され、`build/` はリポジトリーで無視されます。最後に `rm -rf build` を実行してまとめて削除します。

## 変更演習（参考解答は `answer.md`）

### 1. 4件目を受理結果にする

#### 基準

作業ツリーで変更されていない本課の元の [`lesson.cob`](./lesson.cob) から始めます。基準を再実行できるよう、例えば `cp lesson.cob /tmp/lesson_16_ex1.cob` でコピーしてから編集してください。

#### 変更箇所と制約

`1000-LOAD-RESULTS` の次の2文だけを変更します。

```cobol
           MOVE "R" TO WS-RESULT-DESTINATION(4)
           MOVE "TXN-000004|0009999999|T|000020.00|R"
               TO WS-RESULT-TEXT(4)
```

振り分け先マーカーを `"A"` に変更し、レコードテキストの最後の文字も `A` に変更します。

制約：

- 他の3レコードの振り分け先マーカーとテキストは変更しません。
- `PIC`、`FD` レコード幅、`OCCURS 4 TIMES` の上限、ループ上限 `UNTIL WS-RESULT-NUMBER > 4` は変更しません。
- `DISPLAY` の文字列は変更せず、新しい出力ファイル、入力ファイル、ログ、データベースも追加しません。

#### コマンド

```sh
mkdir -p build                                          # 作業ディレクトリー
cp lesson.cob build/                                    # build/ 内のコピーを編集し、課のソースは変更しない
cobc -fsyntax-only build/lesson.cob                     # 構文検査
cobc -x -Wall -o build/lesson_16 build/lesson.cob       # コンパイル
(cd build && ./lesson_16)                               # build/ 内で実行し、出力もそこに作成
echo $?                                                 # 終了コード
wc -lc build/accepted.txt build/rejected.txt            # 行数とバイト数
cat build/accepted.txt build/rejected.txt               # 2ファイルの内容
```

#### 想定される差分

標準出力は引き続き9行で、**変わるのは2行だけ**です。

| 行 | 元の値 | 変更後 |
|---|---|---|
| 6 | `書込=拒否 取引=000004` | `書込=受理 取引=000004` |
| 9 | `SUMMARY 受理=02 拒否=02` | `SUMMARY 受理=03 拒否=01` |

残り7行（先頭5行と `クローズ=` の2行）はバイト単位で変わりません。変更後の出力全体：

```text
オープン=受理 成功
オープン=拒否 成功
書込=受理 取引=000001
書込=受理 取引=000002
書込=拒否 取引=000003
書込=受理 取引=000004
クローズ=受理 成功
クローズ=拒否 成功
SUMMARY 受理=03 拒否=01
```

2つのファイル：

`accepted.txt`（3行、108バイト）

```text
TXN-000001|0001234567|D|000125.50|A
TXN-000002|0007654321|T|000040.00|A
TXN-000004|0009999999|T|000020.00|A
```

`rejected.txt`（1行、36バイト）

```text
TXN-000003|0002468101|X|000000.00|R
```

構文検査、コンパイル、プログラムの終了コードはいずれも `0` です。独立検算：各行は35文字で末尾は空白ではないため、1行36バイトです。したがって `3 × 36 = 108`、`1 × 36 = 36` です。2ファイルで合計4行となり、テーブルの4項目と一致します。`03 + 01 = 04` です。

#### 回答する質問

1. 振り分け先マーカーと一緒にレコードテキストも変更しなければならないのはなぜですか。振り分け先だけ変更した場合、`accepted.txt` にはどのような行が入りますか。プログラムはエラーを報告しますか。
2. 変更後の `accepted.txt` にある3行の順番は何で決まりますか。ファイルシステム、`EVALUATE`、それとも別の要因ですか。
3. 4件目の振り分け先マーカーを `A` でも `R` でもない `X` にした場合、どうなりますか。標準出力、両ファイルの内容とバイト数、`SUMMARY`、終了コードを示してください。

各問について実際の出力と該当するソースコードを記録してください。参考解答は [`answer.md`](./answer.md) を参照してください。

### 2. 上書き動作と再実行を確認する

#### 基準

変更していない元の [`lesson.cob`](./lesson.cob) を使います。実行前に `build/` 内の2つの出力ファイルへ旧データを入れます。

```sh
mkdir -p build
cp lesson.cob build/
cobc -fsyntax-only build/lesson.cob
cobc -x -Wall -o build/lesson_16 build/lesson.cob
printf 'OLD\n' > build/accepted.txt
printf 'OLD\n' > build/rejected.txt
wc -c build/accepted.txt build/rejected.txt     # 実行前のバイト数
(cd build && ./lesson_16)                       # 実行
echo $?
wc -lc build/accepted.txt build/rejected.txt    # 実行後の行数とバイト数
cat build/accepted.txt build/rejected.txt        # 内容
```

#### 制約

課のディレクトリー内のファイルは削除も編集もしません。そこでプログラムを実行しないでください。ソース変更は不要です。

#### 想定される差分

| 確認項目 | 実行前 | 実行後 |
|---|---|---|
| `accepted.txt` | 4バイト、内容 `OLD` | 72バイト、サンプルの受理レコード2件だけ |
| `rejected.txt` | 4バイト、内容 `OLD` | 72バイト、サンプルの拒否レコード2件だけ |
| 標準出力 | — | 通常経路と同じ9行 |
| 終了コード | — | `0` |

#### 回答する質問

1. `OLD` が消えるのはなぜですか。どのプログラム文が原因ですか。
2. 2回実行した結果が「累積して」144バイトになると予想した場合、実際のサイズはいくつですか。その理由も説明してください。
3. 実行前に `mkdir accepted.txt` で `accepted.txt` を**ディレクトリー**にした場合、プログラムは何を表示しますか。終了コードはいくつですか。ファイルは作成されますか。

各問について実際の出力、終了コード、バイト数を記録してください。参考解答は [`answer.md`](./answer.md) を参照してください。

## 学んだことを応用する（解答なし）

人手による確認が必要な結果のため、3つ目の経路を追加します。結果テーブルに3つ目の振り分け先マーカー（例：`H`）を追加し、新しい出力ファイル（例：`review.txt`）を宣言します。`EVALUATE` に `WHEN` 分岐を追加し、書き込み件数と `SUMMARY` にも項目を加えます。

要件：

- 新しいファイル名とレコード幅を決めます。相対パスがどのディレクトリーに作られるか、どのフィールドまたは `PIC` がレコード幅を決めるか、2つの根拠を明記してください。
- どのサンプルレコードに `H` を付けるか決め、各レコードテキスト末尾のマーカーと振り分け先マーカーを一致させます。
- 検査方法を説明してください。3ファイルそれぞれの行数とバイト数、3つの件数の合計がテーブル項目数と一致するか、各ファイル内の全行で末尾マーカーがファイル名に対応するかを確認します。
- 少なくとも1つの境界ケースを含めます。レコードテキスト末尾のマーカーを振り分け先マーカーと意図的に不一致にし、プログラムが矛盾を検出するかを報告してください。その結果の責任が誰にあるかも説明します。
- コンパイルコマンド、実際の出力、ファイルのバイト数、終了コード、検算過程を記録してください。

制約：本課と先行課で学んだ構文だけを使います。`SELECT` / `ASSIGN` / `ORGANIZATION` / `FILE STATUS`、`FD`、`OPEN OUTPUT` / `WRITE ... FROM` / `CLOSE`、`EVALUATE`、`OCCURS` テーブル、段落と `PERFORM`、`MOVE`、`DISPLAY` を使用してください。入力ファイル、追加モード、一時ファイルへのリネーム、データベース、サブプログラムは導入しません。

ソース、2または3個の出力ファイルの全内容とバイト数、コマンド、実際の出力と終了コード、マーカーと振り分け先が一致しない場合の責任者についての説明を提出してください。解答はありません。
