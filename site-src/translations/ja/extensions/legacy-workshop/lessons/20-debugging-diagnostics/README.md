# デバッグ、コンパイル診断と問題の特定

## 学習目標

コンパイラの警告／エラー、行番号・列番号、最小再現例、DISPLAYによる追跡、戻り値、GnuCOBOLのデバッグオプション、プラグインのquickfixについて学びます。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言箇所や実行箇所を見つけられるようになります。構文を暗記するだけではなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L20.COB`](./L20.COB)を開きます。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文／実行文はArea Bに置かれます。まずソースを1行ずつ読み、その後に実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/20-debugging-diagnostics/L20.COB
cobc -x -Wall -o build/l20 extensions/legacy-workshop/lessons/20-debugging-diagnostics/L20.COB
./build/l20
```

期待される観察結果：プログラムがたどった経路が、明確な追跡情報として表示されます。

コンパイラが形式や列位置のエラーを報告した場合は、まず7、8、12、72列目を確認します。次に、ピリオド、変数のPIC、スコープ終端の文を確認しましょう。`-Wall`を指定すると追加の警告が表示されます。警告も内容を理解してから、対処するかどうかを判断してください。

## 各部分の理解

1. `IDENTIFICATION DIVISION`はプログラム単位を宣言し、`PROGRAM-ID`はコンパイラが認識するプログラム名です。
2. `DATA DIVISION`は、プログラムの実行時に使用するデータを記述します。このレッスンにフィールド宣言があれば、レベル番号とPICを確認しましょう。
3. `PROCEDURE DIVISION`は実行の開始点です。`0000-MAIN`は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースコードの順に実行されます。制御フロー文によって経路が変わるか、`STOP RUN`でプロセスが終了するまで続きます。

## 変更演習

未宣言フィールドとEND-IFの欠落という2種類のエラーを発生させます。まず最初に表示される根本原因を読み、修正してから再実行しましょう。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つにし、変更前後の出力を記録しましょう。

## cobol.nvimで学ぶ

`<leader>cl`／`:CobolLint`、`<leader>cq`／`:CobolQuickfix`を使い、ターミナルのcobc出力と照らし合わせます。

プラグインが応答しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に`cobc --version`を確認しましょう。プラグインは移動、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかの判断基準は、GNUCOBOLによる実際のコンパイル結果です。
