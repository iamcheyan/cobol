# 分支：IF、ELSE、EVALUATE

## 学習目標

IF のネストとスコープ終端子 END-IF、EVALUATE/WHEN/WHEN OTHER、範囲指定と複数条件による選択。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から対応する宣言箇所や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L08.COB`](./L08.COB) を開きます。このレッスンのソースファイルは固定形式です。Division と段落は Area A から始まり、宣言文や実行文は Area B に記述します。まずソースを1行ずつ読み、その後で実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから次を実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/08-branching-evaluate/L08.COB
cobc -x -Wall -o build/l08 extensions/legacy-workshop/lessons/08-branching-evaluate/L08.COB
./build/l08
```

期待される動作：EVALUATE TRUE を使って成績をランク分けします。

コンパイラが書式や列位置のエラーを報告した場合は、まず第 7、8、12、72 列を確認してください。次に、ピリオド、変数の PIC、スコープ終端文を確認します。`-Wall` は追加の警告を表示します。警告の内容も理解したうえで、対処するかどうかを判断してください。

## 各部分の理解

1. `IDENTIFICATION DIVISION` はプログラム単位を宣言し、`PROGRAM-ID` はコンパイラが認識するプログラム名です。
2. `DATA DIVISION` はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号と PIC を確認してください。
3. `PROCEDURE DIVISION` は実行の入口です。`0000-MAIN` は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースの順序どおりに実行され、制御フロー文で経路が変わるか、`STOP RUN` でプロセスが終了するまで続きます。

## 変更練習

A+ のランクを追加します。EVALUATE を IF/ELSE に書き換えて、読みやすさを比べましょう。

変更するたびに、構文チェック、コンパイル、実行をやり直してください。一度に変更する概念は1つだけにして、変更前後の出力を記録しましょう。

## cobol.nvim を使った学習

折りたたみ機能で EVALUATE の分岐を折りたたみます。END-IF を書き忘れるエラーを意図的に作り、quickfix にどう表示されるか確認しましょう。

プラグインが応答しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に `cobc --version` を確認してください。プラグインは移動、レイアウトのヒント、診断に使います。プログラムをコンパイルできるかどうかは、GNUCOBOL で実際にコンパイルした結果が判断基準です。
