# 固定形式、自由形式与列規則

## 学習目標

固定形式のシーケンス領域、指示領域、Area A/B、識別領域、GNUCOBOLの自由形式指令とコンパイルオプション。

このレッスンを終えると、上記の用語を自分の言葉で説明し、小さなプログラムの中から該当する宣言箇所や実行箇所を見つけられるようになります。構文を暗記するだけでなく、まず入力、出力、状態の変化を観察しましょう。

## サンプルコード

[`L02.COB`](./L02.COB)を開きます。このレッスンのソースファイルは固定形式です。Divisionと段落はArea Aから始まり、宣言文や実行文はArea Bに記述します。まずソースを1行ずつ読み、その後で実行しましょう。

## コンパイルと実行

リポジトリのルートディレクトリから実行します。

```sh
mkdir -p build
cobc -fsyntax-only extensions/legacy-workshop/lessons/02-source-format/L02.COB
cobc -x -Wall -o build/l02 extensions/legacy-workshop/lessons/02-source-format/L02.COB
./build/l02
```

期待される出力：固定形式における列の規則が表示されます。

コンパイラが形式や列位置に関するエラーを報告した場合は、まず第7、8、12、72列を確認します。次に、ピリオド、変数のPIC、スコープ終端文を確認しましょう。`-Wall`は追加の警告を表示します。警告も内容を理解してから対処するか判断してください。

## 各部分の理解

1. `IDENTIFICATION DIVISION`はプログラム単位を宣言し、`PROGRAM-ID`はコンパイラが認識するプログラム名です。
2. `DATA DIVISION`はプログラムの実行時に使うデータを記述します。このレッスンにフィールド宣言がある場合は、レベル番号とPICを確認しましょう。
3. `PROCEDURE DIVISION`は実行の入口です。`0000-MAIN`は読みやすさのための段落名にすぎず、自動的に繰り返し実行されることはありません。
4. 各文はソースの順序に従って実行され、制御フロー文で経路が変わるか、`STOP RUN`でプロセスが終了するまで続きます。

## 変更練習

DISPLAY文を第8列まで字下げして、違いを比べましょう。`-free`を付けてコンパイルした後、固定形式に戻します。

変更のたびに、構文チェック、コンパイル、実行をやり直しましょう。一度に変更するのは1つの概念だけにして、変更前後の出力を記録してください。

## cobol.nvimで学ぶ

ルーラーを表示し、`g7`、`g8`、`g12`、`g73`で列へ移動します。コードを意図的に第72列より右まで伸ばしてから、`:CobolLint`を実行しましょう。

プラグインが反応しない場合は、まず現在のファイルタイプを確認します：`:set filetype?`。次に、`cobc --version`を確認しましょう。プラグインは移動、レイアウトのヒント、診断に使います。プログラムがコンパイル可能かどうかは、GNUCOBOLの実際のコンパイル結果で判断してください。

## 理解度チェック

- 入力やフィールド値が変わると、出力はどのように変化しますか？
- このレッスンのテーマに関連する小さなエラーを意図的に起こし、コンパイラのメッセージを説明できますか？
- このサンプルを実際のバッチ処理プロジェクトで使う場合、どのような入力や失敗経路を検証する必要がありますか？
